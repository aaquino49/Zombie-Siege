# T-004: World view: render map with TileMapLayer and props

Milestone: M1 | Type: code | Owner: gemini | Scenario: `map_overview`

## Goal

Launching the game shows the generated 48×48 map: Kenney ground tiles, trees/rocks/scrap props, and the Command Center at the center. This task also sets up the game-wide plumbing (`Game` and `Events` autoloads, `GameState`) that every later M1 task plugs into.

## Files to create / change

1. `game/scripts/sim/game_state.gd`: `class_name GameState extends RefCounted`. Owns the run's sim objects.
   - `var data: GameData`, `var map: WorldMap`, `var map_seed: int`.
   - `func _init(game_data: GameData, p_seed: int)`: stores data, creates and generates the `WorldMap`.
   - `func tick(delta: float) -> void`: empty for now (T-006/T-009 add to it).
   - No Node dependencies. Later tasks add `resources`, `clock`, etc. here.
2. `game/scripts/autoload/events.gd` (autoload `Events`, extends Node): global signals only. Start with `signal game_started(state: GameState)`.
3. `game/scripts/autoload/game.gd` (autoload `Game`, extends Node):
   - `var state: GameState`
   - `const DEFAULT_SEED := 1337`
   - `func new_game(map_seed: int = DEFAULT_SEED) -> void`: `GameData.load_default()`, builds a `GameState`, emits `Events.game_started(state)`.
   - `func _process(delta: float) -> void`: `if state: state.tick(delta)`.
   - Register both in `project.godot` `[autoload]` **after** the existing `DevTools` line. Don't touch `dev_tools.gd`.
4. `game/scenes/world/world.tscn` + `game/scripts/world/world_view.gd` (`extends Node2D`). Children:
   - `Ground`: `TileMapLayer`. Build its `TileSet` in code (`tile_size = Vector2i(64, 64)`), one `TileSetAtlasSource` per ground texture (grass variants, dirt, road). Paint every tile from `map` terrain. Pick grass variants deterministically from the tile coords (e.g. hash of x,y), not with random calls.
   - `Props`: `Node2D` with one `Sprite2D` per tree/rock/scrap tile, positioned with `Grid.tile_to_world`. Keep a `Dictionary` tile → Sprite2D. Vary the sprite variant deterministically per tile, like the grass.
   - `Buildings`: `Node2D`. The Command Center `Sprite2D` (`res://assets/buildings/command_center.png`) centered on its 2×2 footprint (centre = top-left tile's corner + 64,64 px).
   - `Camera2D`: positioned on the Command Center centre, zoom 1. (T-005 adds controls; leave it a plain node named `Camera2D`.)
   - `func bind(state: GameState) -> void`: draws everything from `state.map` and connects `state.map.changed` to a handler that removes the sprite of any prop tile whose occupant became NONE (harvesting in M2).
   - Building texture fallback: if a building texture doesn't exist (`ResourceLoader.exists(path)` is false), draw a coloured `ColorRect`/`Polygon2D` of the footprint size instead. Never call `load()` on a missing path; it prints `ERROR:` and fails the smoke run.
5. `game/scenes/main.tscn` / `game/scripts/main.gd`: Main instances `world.tscn` as child `World`. `main.gd._ready()`: `Game.new_game()` then `$World.bind(Game.state)`.
6. `game/dev/scenarios/map_overview.gd`: sets the World camera zoom to `Vector2(0.4, 0.4)` and centres it on the map centre, so most of the map shows in the 1280×720 screenshot. Leave `default.gd` as-is (default shows zoom 1 on the Command Center).
7. `game/tests/test_game_state.gd`: GameState with a fixed seed has a generated map, CC origin matches `map.command_center_origin()`, same seed gives same map; `tick(0.1)` doesn't error.

## Acceptance criteria

- Launching (`default` scenario screenshot) shows Kenney grass/dirt/road ground, props, and the Command Center sprite in the centre; no placeholder scaffold label.
- `map_overview` screenshot shows most of the map: trees denser near the edges, scrap and rocks scattered, clear area around the CC.
- Prop sprites sit exactly on their tiles (centre of the 64 px cell); the CC covers exactly its 2×2 footprint.
- `Game` and `Events` autoloads exist; `Game.state` is a `GameState` after launch.
- `test_game_state.gd` passes; all tests and the 300-frame smoke run pass with no `ERROR:` lines.

## Pitfalls

- Godot 4 APIs only: `TileMapLayer` (not the deprecated `TileMap`), `set_cell(coords, source_id, atlas_coords)`. Each single-image atlas source has atlas coords `Vector2i(0, 0)`.
- Sprite2D is centred by default; position it at the tile centre, not the corner.
- Props may not be exactly 64 px. Don't stretch them; scale down only if larger than the tile (for 1×1 props).
- Don't put any game rules in the view. The view only reads `WorldMap`.
- Autoload names must not clash with a `class_name` (don't create `class_name Game` or `class_name Events`).
- Keep each file under ~400 lines.
