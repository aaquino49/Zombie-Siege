# T-012: Construction: blueprints + Builder job

Milestone: M2 | Type: code | Owner: gemini | Scenario: `construction`
Depends on: T-011 (survivors, pathfinder). Runs after T-055.
T-013 (gathering) and T-015 (selection/roster UI) build on the job framework this task creates, so stick to the names below exactly.

## Goal

Placing a building now creates a **blueprint**. It is paid for, occupies its tiles and is drawn translucent with a progress bar. Survivors with the **Builder** job walk up to blueprints and build them over `build_time` work-seconds (from `buildings.json`). When the progress is full, the building becomes complete and opaque. By day, Builders also repair damaged buildings for wood. You can cancel a blueprint for a 100% refund if no work has been done on it yet, or 50% after work has started. The first survivor starts as a Builder, so the real game builds whatever you place.

## Files

### Data
1. `game/data/balance.json`: add optional keys and read them with `data.balance(key, default)`. Don't add them to `_validate_balance`.
   - `"start_jobs": ["builder", "idle", "idle", "idle"]`. Index i is the starting job of survivor i. Missing or extra entries mean idle.
   - `"job_retry_interval": 1.0`: seconds an idle-but-employed survivor waits before searching for work again.
   - `"repair_time_fraction": 0.5`: repairing from 0 to full HP takes `build_time * 0.5` work-seconds.
   - Existing keys used: `refund_before_build` (1.0), `refund_after_build` (0.5), `repair_cost_fraction` (0.25).

### Sim (`scripts/sim/`, RefCounted, no Nodes)
2. `grid.gd`: add `static func in_ring(t: Vector2i, origin: Vector2i, size: Vector2i) -> bool`. It's true when `t` is in the 1-tile 8-neighbourhood ring around the rect and not inside it. Make `Pathfinder.find_path_adjacent` use it instead of its inline check.
3. `survivor.gd`:
   - `enum Activity { IDLE, WALKING, BUILDING, REPAIRING, HARVESTING, RETURNING, FARMING, CRAFTING }`. Define the full enum now. Later tasks use the extra values.
   - `var activity: int = Activity.IDLE`, `var work_uid: int = 0` (uid of the building being worked on, 0 = none), `var work_acc: float = 0.0` (fractional HP during repair), `var job_timer: float = 0.0`.
   - `static func job_from_name(n: String) -> int` ("idle", "gatherer", "farmer", "builder", "crafter", "guard"; unknown → IDLE), `static func job_label(j: int) -> String` ("Idle", "Builder", ...), `static func activity_label(a: int) -> String` ("Idle", "Walking", "Building", "Repairing", "Harvesting", "Returning", "Farming", "Crafting").
4. `building.gd`: `var build_time: float = 0.0`, `var progress: float = 0.0`, `func progress_ratio() -> float` (1.0 if build_time <= 0), `func is_damaged() -> bool` (`complete and hp < max_hp`).
5. `building_store.gd`:
   - `add()` sets `build_time` from data. If `complete` is true, `progress = build_time`.
   - `signal building_completed(b: Building)`. `func finish(uid: int) -> void` sets `complete = true`, `progress = build_time`, `hp = max_hp`, and emits once. It's a no-op for an unknown or already-complete uid.
   - `func blueprints() -> Array[Building]` and `func damaged() -> Array[Building]`, both sorted by uid.
6. `construction.gd`: `class_name Construction extends RefCounted`, static helpers:
   - `static func refund_fraction(data: GameData, b: Building) -> float`: `refund_before_build` if `progress <= 0.0`, else `refund_after_build`.
   - `static func repair_cost(data: GameData, b: Building) -> int`: `ceili(cost.wood * repair_cost_fraction * (max_hp - hp) / float(max_hp))`, and 0 if not damaged. Example: a farm (20 wood, 100 HP) at 50 HP costs `ceil(20 * 0.25 * 0.5)` = 3 wood.
7. `builder_job.gd`: `class_name BuilderJob extends RefCounted`, `static func tick(state: GameState, s: Survivor, sim_dt: float) -> void`. The state machine:
   - **Validate:** if `work_uid != 0` and the building is gone, or it is complete while the survivor is walking to build or building, or it is no longer damaged while the survivor is repairing: clear the work (`work_uid = 0`, `path.clear()`, `activity = IDLE`).
   - **Find work** (only when `work_uid == 0`): count down `job_timer` and return while it's > 0. Candidates are the blueprints first. If there are none and `state.clock.phase == GameClock.Phase.DAY`, use the damaged buildings whose `repair_cost` is affordable. Sort candidates by squared distance from `s.tile()` to the building's centre tile, then by uid. Try at most 5:
     - If `Grid.in_ring(s.tile(), b.origin, b.size)`, start working at once.
     - Otherwise use `find_path_adjacent`. If it's non-empty: `s.path = p`, `s.target = p.back()`, `s.work_uid = b.uid`, `activity = WALKING`.
     - If nothing works out: `job_timer = job_retry_interval`, stay IDLE.
   - **Arrive:** when WALKING and `not s.is_moving()`: if it's in the ring, switch to BUILDING (blueprint) or REPAIRING (damaged). When repair starts, pay `repair_cost` with `state.resources.take("wood", n)` once. If it can't afford it, drop the target. If it isn't in the ring (path blocked), clear the work.
   - **BUILDING:** `b.progress += sim_dt`. Several builders on one blueprint stack their progress. When `progress >= build_time`, call `state.buildings.finish(b.uid)`, clear the work and set `job_timer = 0` so the builder looks for the next job on the next tick.
   - **REPAIRING:** `s.work_acc += sim_dt * max_hp / (build_time * repair_time_fraction)`, then move whole points into `b.hp` (clamp at `max_hp`). When the building is full, clear the work.
8. `jobs.gd`: `class_name Jobs extends RefCounted`, `static func tick(state: GameState, sim_dt: float) -> void`. Return if `sim_dt <= 0`. For each survivor, `match s.job`: `Survivor.Job.BUILDER` → `BuilderJob.tick(...)`. Other jobs do nothing yet (T-013 and T-014 add theirs here).
9. `game_state.gd`:
   - `try_place`: `buildings.add(type_id, origin, build_time <= 0)`, so a blueprint unless `build_time` is 0.
   - Apply `start_jobs` in `_init` after spawning the survivors.
   - `func set_job(uid: int, job: int) -> bool`: returns false for an unknown uid. Otherwise it sets `job`, clears `path`, `work_uid`, `work_acc` and `job_timer`, and sets `activity = IDLE`. It doesn't move the survivor.
   - `func cancel_building(uid: int) -> bool`: returns false for an unknown uid, the command center or a complete building. Otherwise it calls `resources.refund(cost, Construction.refund_fraction(data, b))` then `buildings.remove(uid)`.
   - `tick`: `clock.advance(sim_dt)` → `Jobs.tick(self, sim_dt)` → `survivors.tick(sim_dt, pathfinder, map)`.

## Acceptance criteria

- `try_place("wooden_wall", t)` makes a building with `complete == false` and `progress == 0`. Wood drops by 5 and the tile is occupied. The CC is still complete.
- New game (seed 1337): survivor 0 is BUILDER, the others are IDLE.
- With a builder teleported onto a ring tile of a wall blueprint: not complete after 4.8 s of `tick(0.1)`, complete by 5.1 s, `building_completed` emitted exactly once, `hp == max_hp`. With two adjacent builders, it's complete by 2.6 s.
- A builder 6+ tiles away walks to the blueprint (never steps on an impassable tile), builds it, then walks to and builds a second blueprint without any new order.
- Cancel an untouched blueprint: wood is back to its pre-placement amount and the tile is free. Cancel after 1 s of building: refund is `floori(cost * 0.5)`. Cancel a complete building or the CC: returns false and nothing changes.
- Repair: a complete farm set to 50/100 HP with one builder: `repair_cost == 3`, wood drops by exactly 3 once, and HP reaches 100. At night, a builder with only damaged buildings doesn't start a repair. With 0 wood, repair doesn't start and nothing goes negative.
- A builder with no work and IDLE survivors don't move (pos unchanged after 5 s of ticks). Nothing happens while paused.
- `set_job` returns false for an unknown uid. It changes the job and clears the path and work.
- View: a blueprint node's sprite has `modulate.a < 1` and a `ProgressFill` whose width tracks progress. After `finish`, the node is replaced by an opaque one, and the child count equals the building count.
- `construction` screenshot: a translucent shelter blueprint with a partly filled progress bar, a builder standing next to it, and at least one completed (opaque) wall that was built during the scenario.
- `buildings_placed`, `survivors`, `default`, `hud` screenshots unchanged.
- All tests pass with no `SCRIPT ERROR` line. Smoke passes. Static typing everywhere. New files under ~250 lines, `game_state.gd` under ~200.

## Pitfalls

- Placement rules don't change. A blueprint occupies its tiles via `map.occupy` (in `BuildingStore.add`) exactly as before.
- Survivors can't stand inside a blueprint footprint. They work from the ring. `find_path_adjacent` returns `[]` when the survivor is already in the ring. That is "arrived", not "unreachable", so check `Grid.in_ring` first.
- `s.target` must be a passable tile (the last path tile), because `SurvivorStore.tick` re-paths to it when a wall is placed in the way.
- `hp` is an int. Accumulate fractional repair in `work_acc`.
- Never use `Engine.time_scale` or `SceneTree.paused`. All work time comes from `sim_dt`.
- Don't add buttons or UI here. Cancel and job assignment UI come in T-015.
- Godot commands: only the ones in `project/ARCHITECTURE.md`. Always pass `--path game`, and never `-s` on a non-SceneTree script.
