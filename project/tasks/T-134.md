# T-134: Chore: bound the audio drain in Game.request_quit with a safety timeout (absorbs T-137)

Milestone: M6 | Type: code | Owner: gemini | Scenario: `default`

## Goal

T-119 routed every quit path (DevTools `--quit-frames`, main-menu Quit, window close) through
`Game.request_quit()` in `game/scripts/autoload/game.gd`. It pauses the tree and loops
`while _has_pending_audio(pending): await create_timer(0.01, ...)` until every weakref'd `AudioStreamPlayback` is
freed. The loop has no upper bound: a stalled audio driver (device unplugged) or any future code holding a playback
would make the game impossible to close (`auto_accept_quit` is false now). T-137 (filed by the second review of the
same fix) is merged into this task.

## Do

1. Factor the wait condition into a small pure helper, e.g.
   `static func should_keep_waiting(alive: int, started_ms: int, now_ms: int, deadline_ms: int) -> bool`
   plus `const QUIT_AUDIO_DEADLINE_MS := 2000`.
2. In `request_quit()`, record `Time.get_ticks_msec()` at start; loop while playbacks are alive **and** the deadline
   hasn't passed. If the deadline passes, `push_warning` once with the number of playbacks still alive, then
   `get_tree().quit(exit_code)` anyway.
3. Normal path unchanged: no fixed delay, no FPS cap, quit as soon as the playbacks are freed.

## Acceptance criteria

- `request_quit()` quits after at most ~2 s even if a pending WeakRef never clears, logging exactly one warning.
- Unit tests: `_has_pending_audio` stays true while a `RefCounted` is held; `should_keep_waiting` is true before the
  deadline with live playbacks, false after the deadline, false when nothing is alive.
- `project/tools/smoke_loop.py` (20 uncapped + 5 capped, as in T-119) stays clean: no "leaked" or "still in use at
  exit" lines. Save its summary in `project/runs/T-134/a#/`.
- All tests pass; import, smoke and screenshot clean.

## Pitfalls

- The tree is paused during the wait: the timer must keep `process_always = true` (it already does).
  `Time.get_ticks_msec()` is wall-clock, which is what we want.
- Don't call `get_tree().quit()` twice.
- Don't touch menu scripts (T-111 is changing main_menu.gd / pause_menu.gd).
