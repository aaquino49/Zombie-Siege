# T-197: M10 weather balance pass (data only)

Milestone: M10 | Type: design | Owner: claude | Scenario: `default`

GDD §20.1. After T-193, rain and fog change the economy and night defence.
Tune `game/data/weather.json` with the balance bot so weather is noticeable
but never decides a run on its own.

## Do

1. Run bot v3.1 (`game/scripts/sim/balance_bot.gd`, same harness as
   T-169/T-189) on seeds 1337/1-9, Normal and Hard, sensible + scavenger,
   with the current `weather.json`. Compare with the T-189 table in
   `project/decisions.md` (Normal sensible 7/3/0, Hard 5/0/5, `none` loses
   on night 4, seed-1337 run 44:41).
2. Targets: Normal sensible >= 7 won and 0 lost; Hard sensible 4-6 won with
   CC damage on most seeds; `none` still loses early. Report fog nights per
   seed; a seed that only loses because of fog needs a look. Rain should
   add a visible but small food surplus (report extra food per run).
3. Levers, in order: fog `chance`, `first_night`, `range_delta_tiles` (-1 or
   -0.5), rain `chance`, `farm_mult`. Data only. If a target needs code,
   file a follow-up in `new_tasks` instead.
4. Update test pins that move only because of data (record old -> new).
   Write the before/after table and reasoning in `project/decisions.md`,
   add a GDD §15 change-log line with the final numbers, and update §20.1
   if the numbers change.

## Acceptance criteria

- Before/after bot tables (Normal + Hard, sensible + scavenger, 10 seeds) in
  `project/decisions.md`, including fog nights per seed.
- Targets met, or the gap explained with the variants tried.
- All tests pass; import/smoke clean.

## Pitfalls

- The bot doesn't react to the forecast, so its fog losses are an upper
  bound on what a player would see. Don't over-tune for it.
- Weather rolls don't use `GameState.rng`, so seeds stay comparable with
  T-189; only the weather effects differ.
