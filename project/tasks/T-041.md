# T-041: Reinforced Wall upgrade from a Wooden Wall

Milestone: M3 | Type: code | Owner: gemini | Scenario: `wall_upgrade`
Depends on: T-012 (construction), T-046 (build bar). Uses `Placement`, `BuildingStore`, `GameState.cancel_building`, `InfoPanel`, `SelectionController`, `BuilderJob`.

## Goal

GDD §7: "Reinforced Wall | 1×1 | 5 wood, 5 scrap | 400 HP | Upgrade from Wooden Wall | day 6". Today `reinforced_wall` has `"upgrade_from": "wooden_wall"` in `buildings.json`. `Placement` rejects it (NOT_PLACEABLE), and the build bar hides it (a 2026-10-09 decision). After this task, from day 6, the player selects a complete Wooden Wall, presses **Upgrade** in the info panel, pays 5 wood + 5 scrap, and a Builder turns it into a Reinforced Wall.

## Rules

- `GameState.try_upgrade(uid: int) -> int` returns a `Placement.Result`-style code. Add `Result.NOT_UPGRADABLE` at the **end** of the enum.
  - The building must exist, be complete, and have a type that some building's `upgrade_from` names (look it up from data; don't hard-code the wall ids). Otherwise `NOT_UPGRADABLE`.
  - The target type's `unlock_day` must be ≤ `clock.day`, otherwise `LOCKED`. The player must be able to afford its cost, otherwise `UNAFFORDABLE`.
  - On OK: spend the cost, `buildings.remove(old.uid)`, then `buildings.add(target_type, old.origin, build_time <= 0)`. That gives a reinforced-wall **blueprint** on the same tile, with full hp per the existing blueprint rule. Record `var upgraded_from: String = old.type_id` on the new `Building`. The tile never becomes passable for zombies or survivors: both calls happen in the same tick, so check that nothing between them reads the map.
  - Return OK. `Events`/selection: the info panel selects the new building if the old one was selected.
- **Cancel an upgrade blueprint:** `cancel_building` on a blueprint with `upgraded_from != ""` refunds the reinforced wall's cost with the normal refund rules (100% before work, 50% after), then puts back a **complete** building of the `upgraded_from` type at full hp. Without this, cancelling would delete the original wall.
- Builders build it like any blueprint (`build_time` 10). No BuilderJob changes should be needed. Check it.
- Placing `reinforced_wall` directly through `Placement.check` / the build bar stays NOT_PLACEABLE.

## Files

1. `game/scripts/sim/placement.gd`: `Result.NOT_UPGRADABLE` (end of enum) and a static `upgrade_target(data: GameData, type_id: String) -> String` ("" if none).
2. `game/scripts/sim/game_state.gd`: `try_upgrade`, and the upgrade-aware `cancel_building`.
3. `game/scripts/sim/building.gd`: `var upgraded_from: String = ""`.
4. `game/scripts/ui/info_panel.gd` (and its scene): an **Upgrade** button, shown only for a complete building with an upgrade target. Label it "Upgrade to Reinforced Wall (5 wood · 5 scrap)", using `BuildBar.cost_text` for the cost. Disable it with the reason as the tooltip ("Unlocks on day 6" / "Not enough resources"). Hook up `pressed` like the existing cancel button, and refresh on resource change and at dawn.
5. `game/dev/scenarios/wall_upgrade.gd` (new, typed vars): default state, `clock.day = 6`, 4 complete wooden walls in a line 4 tiles south of the CC, plus enough scrap (`resources.add("scrap", 20)`). Upgrade the 2nd wall with `try_upgrade` and tick until the builder is working on it (progress > 0, cap 600 ticks). Select the 3rd wall so the info panel shows the Upgrade button. Pause. Screenshot: one wall mid-upgrade with a progress bar, the info panel with an enabled Upgrade button.

## Tests (`game/tests/test_wall_upgrade.gd`, new)

- Day 6, affordable: `try_upgrade(wall.uid) == OK`. 5 wood + 5 scrap are spent. The tile holds a `reinforced_wall` blueprint with `upgraded_from == "wooden_wall"`. `map.is_passable(tile)` is false throughout.
- A builder completes it: a complete reinforced wall with max_hp 400 and hp 400.
- Day 5: `LOCKED`. Not enough scrap: `UNAFFORDABLE` and nothing is spent. A blueprint wooden wall, a gate or a shelter: `NOT_UPGRADABLE`.
- Cancel before work: 5 wood + 5 scrap refunded, and a complete wooden wall at full hp is back on the tile. Cancel after some progress: 50% refund (use the existing rounding), wall restored.
- `Placement.check(state, "reinforced_wall", t)` is still NOT_PLACEABLE, and the build bar still has no reinforced wall button.
- InfoPanel (off-tree, per `game/tests/README.md`): the Upgrade button is visible for a complete wooden wall, disabled before day 6, enabled on day 6 when affordable, and hidden for a farm. Pressing it calls `try_upgrade`.

## Pitfalls

- If T-018 has landed by the time you run, `map.changed` from remove + add marks the zombie flow field dirty twice in one tick. That's fine (the rebuild is lazy).
- Survivors standing next to the wall are unaffected (the tile was already solid).
- Don't hard-code "wooden_wall"/"reinforced_wall" in sim code. Use the data `upgrade_from` link.
- Static typing everywhere. Files under ~400 lines. Use only the Godot commands in `project/ARCHITECTURE.md`, always with `--path game`.
