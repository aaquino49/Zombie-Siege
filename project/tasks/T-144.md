# T-144: Save/Continue 1: SaveGame snapshot at dawn (sim only, JSON round trip)

Milestone: M7 | Type: code | Owner: gemini | Scenario: `default`

## Goal

A full run is 40–45 minutes, and closing the game loses it. M7 adds **Continue** (GDD §17.1): the colony is saved
automatically every dawn and the main menu can resume it. This task builds only the pure-sim half: a `SaveGame` class
that turns a `GameState` at the start of a day into a JSON-safe `Dictionary` and back. No UI, no file writing from the
game yet (T-146 does that).

## Why dawn

At dawn (`GameState._on_dawn`) every zombie is removed, `waves.clear_pending()` runs, and the night log is summarised.
So a dawn snapshot has no zombies, projectiles, wave timers or night state to save. On load the game starts at the
**beginning of that day** (`clock.day = N`, phase DAY, `elapsed = 0`). Survivors' in-flight paths, timers and carried
loads are not saved: they restart their job from their tile. That's an accepted, documented loss of a few seconds.

## Do

1. New `game/scripts/sim/save_game.gd`, `class_name SaveGame extends RefCounted`, static functions only:
   - `const VERSION := 1`
   - `static func capture(state: GameState, extra: Dictionary = {}) -> Dictionary`: returns `{}` and `push_warning`s if
     `state.game_over`, `state.won`, or `state.zombies.count() > 0`. Otherwise a dictionary of plain types only
     (int, float, String, bool, Array, Dictionary; Vector2i as `[x, y]`):
     `version`, `map_seed`, `day`, `resources` (all four kinds), `buildings` (each: `uid`, `type_id`, `origin`, `hp`,
     `complete`, `progress`, `upgraded_from`) and the store's next uid, `survivors` (each: `uid`, `name`, `variant`,
     `hp`, `max_hp`, `job` as its name via the existing `Survivor` job-name helpers, `gather_kind`, `hungry_days`,
     `tile`) and the store's next uid, `nodes` (every remaining resource node: tile, occupant, amount),
     stats (`zombies_killed`, `survivors_lost`, `buildings_lost`, `buildings_built`, `survivors_left`, `time_played`),
     `rng_state` (`state.rng.state`), and `extra` copied as-is (T-146 puts tutorial-hint flags there).
   - `static func restore(data: GameData, save: Dictionary) -> GameState`: returns `null` (with `push_warning`) for a
     missing/wrong `version` or malformed data. Otherwise: `GameState.new(data, map_seed)` (regenerates the identical
     seeded map), then replace its generated content with the save: remove the default survivors and buildings,
     re-add the saved buildings (same uids, hp, completion, progress; the Command Center too) and survivors (same
     uids), set node amounts and clear depleted nodes, set resources, clock day/phase/elapsed, stats and
     `rng.state`, then rebuild the flow field and pathfinder costs exactly as a normal placement would.
   - `static func to_json(save: Dictionary) -> String` and `static func from_json(text: String) -> Dictionary`
     (`{}` on parse failure).
2. Add the small accessors you need instead of reaching into private fields: e.g. `BuildingStore.next_uid()` /
   `set_next_uid()`, `SurvivorStore.set_next_uid()`, `BuildingStore.restore(b: Building)` that occupies the map and
   emits nothing, `WorldMap.export_nodes()` / `import_nodes()`. Keep each file under ~400 lines.
3. A survivor whose saved tile is not passable (e.g. it was inside a Shelter at dawn) is placed on the nearest
   passable tile next to it, so nobody starts inside a building. Restored survivors are not `sheltered`.
4. Tests in `game/tests/test_save_game.gd`:
   - Round trip: run a seeded game to dawn of day 4 or later with some built buildings, a blueprint in progress, a
     damaged building, a depleted node and a lost survivor (drive it with `BalanceBot` helpers or scripted
     `try_place`/`set_job` calls plus `tick`). `capture` → `to_json` → `from_json` → `restore` → `capture` again must
     equal the first capture (ignoring nothing but `time_played` float formatting if needed).
   - The restored state plays on: tick it through the rest of the day and the next night to the next dawn with no
     errors, zombies spawn, and day becomes N+1.
   - Survivor on a shelter tile is moved to a passable tile; uids continue (next placed building gets a new uid).
   - `capture` refuses during night (zombies alive) and after game over; `restore` refuses version 0/99 and garbage.

## Acceptance criteria

- `SaveGame.capture/restore/to_json/from_json` exist, are sim-only (no Node, no file I/O) and statically typed.
- Round-trip test passes: restored capture equals the original capture.
- A restored game plays through a full night to the next dawn in the test.
- No change to game balance, `GameState` behaviour for new games, or any existing test expectations.
- All tests, import, smoke and screenshot clean.

## Pitfalls

- `GameState._init` wires signals and weak refs; don't create a second construction path that skips them. Build the
  normal state, then overwrite.
- Buildings occupy map tiles and block pathing: remove default ones via the store's existing removal path so the map
  occupancy is vacated, and re-add through a path that occupies it.
- JSON turns ints into floats: cast on read (`int(v)`), and compare captures after a JSON round trip in the test.
- Don't touch `game_state.gd` tick logic, the bot, or any data JSON (T-136 is editing balance data right now).
