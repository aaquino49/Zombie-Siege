# T-120: Polish: gate sprite for gates in a north-south wall line

Milestone: M6 | Type: code | Owner: gemini | Scenario: `gate_vertical` (new) | skip_qa

## Goal

T-104 always draws `gate_closed.png`, which is an east-west piece. A gate placed in a vertical (north-south) wall line
looks wrong and leaves a visual gap (accepted limitation at T-104 review). Draw a vertical gate there.
**View and art only. Sim and placement don't change.**

## Context

- `game/scripts/world/building_sprites.gd`: `_is_wall_connectable`, `wall_suffix`, `wall_texture`, `make`,
  `apply_pixel_sprite`. Walls autotile when their `buildings.json` entry has `"autotile": true`. The gate doesn't, so it
  takes `texture_for()`.
- `game/scripts/world/world_view.gd`: `_update_wall_neighbours(b)` re-textures neighbouring **autotile** buildings
  when a building is added or removed. Gates are skipped today.
- Art: `game/assets/pixel/buildings/` has `gate_closed.png`, `gate_open.png` and the 16 fence pieces
  (`fence_v.png` is the N-S run, plus `fence_end_n/s`, `fence_post`, corners and tees). ART_GUIDE §2: no runtime rotation; §7: gap-fill by recombining
  pack pieces with a PIL script.

## Do

1. **Art:** make `game/assets/pixel/buildings/gate_closed_v.png` (16×16, or the same height convention as the fence
   N-S piece so it joins without a gap). Use a PIL script (`asset_library/ittaimanero/gapfill/gate_vertical.py`) from
   the vertical fence posts plus the gate's planks/hinge colours. It must be palette-exact (`palette.json`) with binary
   alpha. Add an `ASSET_INDEX.md` row.
2. **Code:** add `static func gate_texture(data, state_or_map, b) -> Texture2D` in BuildingSprites. Return
   `gate_closed_v` when N and S are connectable and E and W are not; return `gate_closed` in every other case. Use it in
   `make()` for `type_id == "gate"` when `state_or_map` is given.
3. Extend `_update_wall_neighbours` so a neighbouring gate is re-textured too (through `gate_texture`), not only
   autotile walls.
4. **Scenario `gate_vertical`:** a short N-S wooden wall run with a gate in the middle, next to an E-W run with a gate,
   both on screen at 1280×720.
5. **Tests** (extend `test_building_sprites*.gd` or add `test_gate_sprite.gd`): N+S only gives the vertical texture;
   E+W, none, N+E, and all four give `gate_closed`; placing then removing a wall north and south of an existing gate
   switches its texture both ways (through world_view with a bound GameState); the sprite rotation is 0 and the scale
   is 4.

## Acceptance criteria

- A gate with wall neighbours N and S only uses the vertical gate texture. Every other case keeps `gate_closed`.
- Placing or removing a wall next to a gate re-textures the gate (test).
- The sprite is never rotated: 4× Nearest, bottom-anchored via `apply_pixel_sprite`.
- `gate_vertical` capture shows the vertical gate joined to the wall run without gaps. The E-W gate is unchanged.
- All tests pass; import, smoke and screenshot clean.
