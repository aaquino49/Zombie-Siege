# T-070: ART: grass-edged dirt path tiles for natural roads

Milestone: M3 | Type: asset | Owner: codex | Scenario: `default` (no game change; T-071 uses these tiles)
Depends on: none. Next: T-071 (natural roads in map gen and world view). Owner request R-1.

## Goal

The owner says the two straight, full-height grey asphalt stripes look like UI dividers, not roads (R-1). We're
replacing them with **winding 2-tile-wide dirt tracks** that have soft grass edges, like the brown path in
`asset_library/kenney/kenney_tower-defense-top-down/Sample.png`. This task produces the tiles. T-071 does the
generation and drawing.

## What to deliver

13 tiles, 64×64 PNG, in `game/assets/tiles/path/`, taken from
`asset_library/kenney/kenney_tower-defense-top-down/PNG/Default size/towerDefense_tile###.png` (the grass↔dirt set
with wavy edges: for example 1, 2, 3, 4, 23, 25, 26, 27, 47, 70, 72, 73, 92–96; check them yourself). Rotating or
flipping a Kenney tile to get a missing orientation is fine: the art is flat, straight top-down and unlit.

Every tile describes a **dirt (path) tile** by which sides touch grass:

| File | Grass on | Looks like |
|---|---|---|
| `path_center.png` | nothing | plain dirt (should match `game/assets/tiles/dirt.png` or be that tile) |
| `path_edge_n.png`, `_e`, `_s`, `_w` | that one side | dirt with a wavy grass border along that side |
| `path_outer_ne.png`, `_nw`, `_se`, `_sw` | the two named sides (convex corner) | dirt with a rounded grass corner |
| `path_inner_ne.png`, `_nw`, `_se`, `_sw` | only the named diagonal neighbour (concave corner) | dirt with a small grass notch in that corner |

Rules:
- The grass part must be the same green as `game/assets/tiles/grass_1..3.png` and meet them with no visible seam.
  The dirt part must match `path_center.png`.
- Edges must line up tile to tile: two `path_edge_n` side by side form one continuous wavy border, and an edge flows
  into the outer and inner corners without a step.
- Run `godot --headless --path game --import` so the `.import` files exist, and commit them (ARCHITECTURE rule 13).
- Write `game/assets/tiles/path/README.md`: one line per file (source Kenney tile number and any rotation or flip),
  plus the neighbour rule T-071 will use:
  - A path tile looks at its 4 orthogonal neighbours. Path, DIRT or out of bounds count as "dirt"; GRASS counts as
    "grass".
  - 0 grass sides → `center`, unless exactly one diagonal neighbour is grass → `inner_<that diagonal>`.
  - 1 grass side → `edge_<side>`. 2 adjacent grass sides → `outer_<corner>`.
  - Anything else can't happen with 2-wide paths; fall back to `center`.
- Contact sheet `project/runs/T-070/path_contact.png`: lay out, on a grass_1/2/3 background, a 2-wide path that runs
  in from the left edge, bends down, bends right again (an S-bend), and has a T-junction where a second 2-wide path
  joins from below. Build it only from these 13 tiles, using the neighbour rule above. Put the 13 tiles labelled in a
  row underneath. Read the PNG and confirm by eye that there are no seams. If it clashes, pick different source
  tiles (up to 3 tries) before settling.

## Acceptance criteria

- The 13 PNGs exist at 64×64 with the exact names above, plus their `.import` files. Import is clean.
- `README.md` lists each file's source and the neighbour rule.
- `project/runs/T-070/path_contact.png` shows a seamless S-bend and T-junction built from the tiles.
- No game code or existing asset changes. All tests pass and every screenshot is unchanged.

## Pitfalls

- Don't use the sand or grey-stone sets (tiles 5–14, 28–37 and so on). Only grass↔brown dirt.
- Don't stretch or rescale. These are already 64 px.
- Don't touch `road_*.png`. T-071 decides whether to delete them.
