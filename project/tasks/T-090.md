# T-090: Polish: Block build-menu (B) and roster (R) hotkeys while the pause menu is open

Milestone: M6 | Type: code | Owner: gemini | Scenario: `pause_menu`

## Goal

With the pause menu open, pressing B or R still toggles the build bar panel and the roster behind the dimmed
overlay. Nothing breaks, but it looks sloppy. Make the pause menu swallow those keys while it is visible.

## Context

- `game/scripts/ui/pause_menu.gd` `_input` already consumes `pause` and `speed_1..3` while `visible`.
- `build_menu` is handled in `game/scripts/ui/build_bar.gd` (~line 118, `_unhandled_input`), and `roster` in
  `game/scripts/ui/roster_panel.gd` (~line 42). Both check `is_action_pressed` in unhandled input, so marking
  the event handled in `_input` stops them.

## Do

1. In `PauseMenu._input`, add `event.is_action("build_menu")` and `event.is_action("roster")` to the
   consumed set while `visible`.
2. Add a test to `game/tests/test_pause_menu.gd` that follows its existing pattern. Prefer a small pure static
   helper (for example `static func blocks_action(event: InputEvent) -> bool`) that `_input` uses and the test
   calls with `InputEventAction` instances, so no scene tree is needed.

## Acceptance criteria

- With the pause menu open, pressing B or R changes no panel visibility.
- With the pause menu closed, B and R behave exactly as before.
- All tests pass with no SCRIPT ERROR. The pause_menu and default screenshots are unchanged.

## Pitfalls

- Do not touch `dev_tools.gd`, `run_tests.gd` or `test_case.gd`.
- Don't consume `cancel` in `_input`. Esc must still reach `_unhandled_input` to close the menu.
