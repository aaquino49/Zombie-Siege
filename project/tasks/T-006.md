# T-006: Resources store + top bar HUD

Milestone: M1 | Type: code | Owner: gemini | Scenario: `hud`
Depends on: T-002 (GameData), T-004 (`GameState`, `Game`/`Events` autoloads, main scene). Uses T-001 icons and UI art.

## Goal

The colony's four resources live in a tested sim class, and a top bar shows them with icons. Building placement (T-008) and the clock (T-009) plug into this.

## Files to create / change

1. `game/scripts/sim/resource_store.gd`: `class_name ResourceStore extends RefCounted`.
   - `const KINDS: Array[String] = ["food", "wood", "scrap", "ammo"]`.
   - `signal changed(kind: String, amount: int)`.
   - `func _init(data: GameData)`: starting values from balance.json `start_food/start_wood/start_scrap/start_ammo`.
   - `get_amount(kind) -> int`, `add(kind, n)` (n ≥ 0), `take(kind, n) -> int` (removes up to n, returns the amount actually taken; used for eating food/firing ammo later).
   - `can_afford(cost: Dictionary) -> bool` and `spend(cost: Dictionary) -> bool`. `cost` uses the buildings.json shape `{"wood": 5, "scrap": 0}`; missing keys mean 0. `spend` is **all-or-nothing**: if any kind is short, nothing changes and it returns false.
   - `refund(cost: Dictionary, fraction: float)`: adds `floori(amount * fraction)` per kind.
   - Unknown kinds: `push_error` and no change. Amounts never go negative. Emit `changed` only for kinds whose value actually changed.
2. `game/scripts/sim/game_state.gd`: add `var resources: ResourceStore`, created in `_init`.
3. `game/scenes/ui/hud.tscn` + `game/scripts/ui/hud.gd` (`extends CanvasLayer`):
   - A full-width top bar (~48 px high) using the T-001 UI panel texture (`NinePatchRect` or `StyleBoxTexture`; check `game/assets/ASSET_INDEX.md` for the files).
   - Left: four `TextureRect` icon + `Label` pairs (food, wood, scrap, ammo) from `game/assets/icons/icon_*.png`.
   - Centre: `DayLabel` showing "Day 1". Right: an empty `HBoxContainer` named `ClockArea` for T-009 (time-left and speed buttons).
   - `func bind(state: GameState) -> void`: sets all labels, then connects `state.resources.changed` to update one label. No per-frame polling.
   - Readable: light text with a dark outline or shadow, at least 18 px font.
4. `game/scenes/main.tscn` / `main.gd`: instance `hud.tscn` as `HUD`; after `Game.new_game()`, call `$HUD.bind(Game.state)`.
5. `game/dev/scenarios/hud.gd`: changes the store after binding (e.g. `add("food", 93)` → 123, `take("scrap", 15)` → 0) so the screenshot proves the labels follow the store.
6. `game/tests/test_resource_store.gd`: start values match balance.json; `can_afford` true/false and the missing-key case; `spend` success deducts; `spend` failure changes nothing (multi-kind cost where only one kind is short); `take` caps at the current amount; `refund` with 0.5 floors; `changed` emitted with the right args and not emitted on a no-op.

## Acceptance criteria

- `ResourceStore` tests pass (afford/spend/add/take/refund, never negative, atomic spend, signal behaviour).
- `hud` screenshot: top bar across the top with 4 icons + amounts (food 123, wood 60, scrap 0, ammo 40) and "Day 1"; the map is still visible below.
- Labels update through the `changed` signal (no polling in `_process`).
- All tests and smoke pass.

## Pitfalls

- HUD is a `CanvasLayer`, so it doesn't move with the camera. Make it fill the width via anchors (`PRESET_TOP_WIDE`), not fixed pixel widths. The viewport uses `canvas_items` stretch, 1280×720 base.
- Mouse filter: the bar's background should `MOUSE_FILTER_STOP` so clicks on it don't reach the world later, but child labels `IGNORE`.
- Don't hard-code starting values; read balance.json via GameData.
- Missing icon file: check `ResourceLoader.exists` and leave the icon blank rather than calling `load()` on a missing path.
