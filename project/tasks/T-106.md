Milestone: M6 | Type: code | Owner: gemini | Scenario: `night`

## Goal

Owner request R-5 (graphics overhaul), fourth swap. Zombies are still the old Kenney top-down `zombie_stand.png`,
rotated to their heading, with the brute shown as a 1.5× dark-red tinted copy. Replace them with the Ittai Manero
pixel zombies at 4×: three distinct sprites, 4-direction walk/attack/hurt/death, never rotated, y-sorted with
buildings and survivors. **View only. The sim doesn't change.**

This is the same job T-105 did for survivors. **Copy its approach**: read `game/scripts/units/survivor_layer.gd`,
`game/dev/tools/make_survivor_frames.gd` and `game/tests/test_survivor_layer.gd` first and mirror them.

   `idle_<dir>` (cell 0, 4 fps, loop), `walk_<dir>` (0,1,0,2, 8 fps, loop; runner 12 fps so it reads faster),
   `attack_<dir>` (0,1,0,2 at 10 fps, loop), `hurt_<dir>` (hurt 0,1,2, 12 fps, no loop), and `death` (down hurt cell 0,
   1 frame). Remove the `default` animation. Commit the generator and the three `.tres` files.
2. **ZombieLayer pools `AnimatedSprite2D`s** (`scale = Vector2(4, 4)`, `centered = true`, `rotation` never set).
   Feet about 12 screen px below `z.pos` (same `offset` as survivors). **Ignore `zombies.json` `scale` and `tint`**
   (pixel art uses one scale and the sprites are already distinct); leave the data fields alone and note it in
   `project/assumptions.md`. Set `sprite_frames` per type every time a pooled node is reused (a recycled walker node
   may become a brute).
3. **Direction and state** in `sync()`, reusing `SurvivorLayer.dir_name()` (call the static, don't copy it):

     `attack_timer` reset (or skip the lunge if it complicates things; the animation alone is acceptable);
   - moving (`z.pos` changed) → `walk_<dir>` from the movement delta;
   - otherwise `idle_<dir>` from `z.facing`.
   Only `play()` when the animation name changes.
4. **Hurt:** on `GameState.zombie_hit`, play `hurt_<dir>` once, then back to walk/attack (`animation_finished`).

   sprites synchronously (T-105 a1 failed review on exactly this). The pooled node returns to the pool as before.
6. **Pool reset:** a reused node starts with `walk_down` (or the right walk direction) at frame 0, `modulate = WHITE`,
   `visible = true`, HP bar full and hidden. Never in `death` or `hurt`.
7. **Y-sort:** move `Zombies` under `YSort` in `world.tscn` with `y_sort_enabled = true`. A zombie north of a wall is

   and update those paths.
8. **Tests:** rewrite `game/tests/test_zombie_layer.gd` and update `test_zombie_view_qa.gd` / `test_night_end.gd`
   where they use the old `Sprite2D` API, keeping their intent:

   - each type gets its own frames (`sprite_frames.resource_path` contains the type); each `.tres` has all 21

   - moving → `walk_<dir>`, attacking a building → `attack_<dir>` facing it, `zombie_hit` → `hurt_<dir>`;
   - **pool reuse:** remove a zombie mid-hurt, add a zombie of another type, and the recycled node plays a walk

9. **Captures** (before = first, after = when done) into `project/runs/T-106/a#/`: `night`, `defense`,

## Acceptance criteria

- `night`, `defense` and `zombie_types` captures show three clearly distinct pixel zombie types at 4×, animated,
  facing the walls/survivors they attack, never rotated, crisp pixels.
- Pool reuse test: a recycled zombie view starts in walk with the right type's frames, not in death or hurt.
- Death fades in about 0.5 s with no leaked nodes or tweens; HP bars stay aligned above the head.
- Zombies y-sort with buildings and survivors.
- Sim unchanged; all sim tests pass untouched. All tests pass; import, smoke and screenshot clean.

## Pitfalls

- `zombies_perf` scenario: there can be 150+ zombies on the Final Horde. Don't create Tweens per frame or call
  `play()` every sync. Keep per-zombie state in plain Dictionaries keyed by uid.
- `AnimatedSprite2D.offset` is in unscaled texture pixels; negative y moves the sprite up.
- No `static var` resource caches (T-119 shutdown leaks). `load()` the `.tres` each bind; Godot caches it.
- Tests run outside the tree (no `_process`, tweens don't advance). Call `sync()` directly.
- The brute used to be 1.5× bigger. The pack's "big" zombie is already larger in its 16×16 cell; don't scale it.
