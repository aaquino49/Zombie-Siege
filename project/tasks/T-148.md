# T-148: Difficulty 2: pick Easy / Normal / Hard on New Game; show it in the pause menu and end screens

Milestone: M7 | Type: code | Owner: gemini | Scenario: `difficulty_picker`

Starts after T-158 (game.gd/main_menu.gd) and T-159 (pause menu), which edit the same files. The sim side is done:
T-147 added `GameState.new(data, seed, difficulty)`, `state.difficulty`, the multipliers and the save field. The night
forecast (T-162) already reflects the difficulty, so nothing to do there.

## Goal

Let players choose the difficulty from T-147 (GDD §17.3).

## Do

1. New Game opens a small themed panel (MenuStyle, `UiFont` sizes) with three buttons, each with a one-line
   description built from the `balance.json` `difficulty` block, so it stays true after tuning: Easy "Hordes 15%
   smaller", Normal "The intended siege", Hard "Hordes 20% bigger" (T-147 tuned difficulty to wave size only: Easy
   ×0.85, Hard ×1.2; HP, supplies and food are 1.0, so don't promise more supplies or tougher zombies). Mention
   another multiplier only if it isn't 1.0. Back/Esc returns to the main menu. The last choice is remembered (`GameSettings` `[gameplay] difficulty`,
   default normal) and focused.
2. `Game.start_new_game(difficulty)` → `new_game(seed, ..., difficulty)` → `GameState.new(..., difficulty)`.
   Continue uses the saved difficulty.
3. Show the difficulty: in the pause menu header and in the Victory/Game Over stats ("Difficulty: Hard").
   Normal shows too (consistent).
4. Scenario `difficulty_picker.gd`; extend the menu-flow QA script with New Game → Hard → in-game check that
   `Game.state.difficulty == "hard"`.

## Acceptance criteria

- `difficulty_picker` capture: three readable options at 1280x720, last choice focused.
- Picking Hard starts a hard game; Continue resumes with the saved difficulty; the end screens show it.
- Menu-flow scripts pass; all tests, import, smoke and screenshot clean.
