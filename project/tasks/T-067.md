# T-067: Polish: the info panel covers the expanded build bar at 1280x720

Milestone: M2 | Type: code | Owner: gemini | Scenario: `qa_m2_colony_day3`
Depends on: T-016. Absorbs QA duplicate T-065.

## Goal

A minor bug from M2 QA. From day 2–3, more buildings unlock, so the bottom-centre build bar (`game/scripts/ui/build_bar.gd`, buttons 96×84) grows to 7–9 buttons and starts at about x = 223. The bottom-left info panel (`game/scripts/ui/info_panel.gd` and its scene) reaches about x = 288, so it hides the Wooden Wall button (see `project/runs/T-016/a1/qa_m2_colony_day3.png`). By day 8 the bar holds 10 buttons (wall, gate, shelter, farm, storage, watchtower, workshop, lumber yard, turret, radio tower). That's about 1,000+ px, which still fits in 1280 on its own but can't sit beside a 288 px panel.

## Decision (don't pick another)

**Move the info panel up so its bottom edge sits 8 px above the build bar's top edge.** It stays on the left, and its width and content don't change. The build bar stays centred and unchanged. With every building unlocked, the bar must still fit within 1280 px with at least 8 px margin on each side. If it doesn't, reduce the button `custom_minimum_size` width (not below 88) and keep the labels readable (font 12).

Do this through anchors and offsets in the info panel's scene (or in `info_panel.gd`), not with per-frame position code. The info panel must not overlap the "Survivors (R)" button at the top left, the top bar or the roster panel at the top right.

## Files

- The info panel's scene in `game/scenes/ui/` (find which `.tscn` holds `InfoPanel`) and/or `game/scripts/ui/info_panel.gd`: anchors and offsets.
- `game/scripts/ui/build_bar.gd`: only if the width check needs smaller buttons.
- `game/tests/test_info_panel.gd` or a new `game/tests/test_ui_layout.gd`: the layout test.

## Tests

The test must be off-tree, following "Testing scenes and Node scripts" in `game/tests/README.md`. Without a viewport, compute rects from the anchors and offsets against a 1280×720 rect, or set the root Control's size by hand. Read the README to pick the right approach.

- With every placeable building type unlocked (`clock.day = 8` or higher) and an entity selected, the InfoPanel's rect and the BuildBar's rect don't intersect.
- Every build button lies fully inside 1280×720.
- The info panel's rect doesn't intersect the top bar or the "Survivors (R)" button.

## Acceptance criteria

- The tests above pass.
- The `qa_m2_colony_day3` screenshot shows the Wooden Wall button fully visible, with the farm info panel above the bar.
- The `default`, `construction`, `production` and `ui_roster` screenshots are unchanged, except that the info panel sits higher where it's visible.
- All tests pass with no SCRIPT ERROR. Smoke passes. Import is clean.

## Pitfalls

- Don't change the roster panel.
- The build bar rebuilds its buttons at dawn (`_rebuild_buttons`). The layout must hold after a rebuild, not just at startup.
- Static typing. Use only the Godot commands in `project/ARCHITECTURE.md`, always with `--path game`.
