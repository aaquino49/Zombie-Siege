## Do

1. `DawnReport.lines()` (`game/scripts/sim/dawn_report.gd`, around line 68): scavenging rows read
   `"Mara: +32 scrap, +12 food"`, which looks odd next to "Zombies killed: 12". Make them
   `"Scavenging (Mara): +32 scrap, +12 food"`. Keep the single `"label: value"` shape so
   `DawnReportPanel.report_rows` still splits it into a label and a value (the name has no colon, so this is safe).
2. `TutorialHints.check()` (`game/scripts/sim/tutorial_hints.gd` line 42): the `scavenge` hint only checks
   `state.clock.day == 2`, so an earlier hint can delay it into the night or past the morning cutoff, when sending is
   impossible. Show it only while sending is possible: `state.clock.phase == GameClock.Phase.DAY` and
   `state.clock.elapsed` below the morning cutoff (`day_length * expeditions().morning_fraction`, the same rule as
   `Expeditions.can_send`; read it, don't change it). Use `day >= 2` so a hint that missed day 2's window shows on
   the next morning instead of never.

## Acceptance criteria

- Unit test: a report with one scavenging entry yields a `"Scavenging (Name): ..."` line, and
  `DawnReportPanel.report_rows` splits it into label `"Scavenging (Name)"` and the value.
- Unit test: on day 2 at night, and on day 2 after the morning cutoff, `check()` never returns `"scavenge"`; on
  day 3 in the morning it does (once).
- All tests, import, smoke and the `scavenging` capture clean.

## Pitfalls

- Hints are one-shot (`shown`); only mark `scavenge` as shown when it is actually returned.
- Keep LF line endings.
