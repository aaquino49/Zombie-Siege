# T-123: ART: lighter ground, dark dirt paths, so terrain and props read clearly (palette-exact recolour)

Milestone: M6 | Type: asset | Owner: codex | Scenario: `map_overview`

## Goal

Owner request **R-6**. Since T-103 the whole map is one dark mud-brown (see
`project/runs/T-104/a2/screenshot_qa.png`, `project/runs/T-109/a2/screenshot_qa.png`). Near-black bushes, dead trees
and flowers barely stand out, and the scene reads murky, worse under the night tint. Make the open ground clearly
lighter, keep paths and dirt patches dark, and make sure props contrast with the ground. Stay in the pack's palette
and style.

## What the quarterback found in the pack (so you don't have to rediscover it)

- The pack has **no green**. Its "grass" tiles (`Terrain Variations`, `Grass with Flowers`) are all base `#47352c`
  (71,53,44) with `#77664e` specks and black blades/flowers. Our `grass_1..4.png` and `flowers_1..2.png` are exactly
  those tiles, so "use the lighter variations" isn't possible as-is.
- The lighter colour is the dirt: `dirt.png` is solid `#77664e` (119,102,78), and the path atlas uses it. So today
  the ground is dark and the paths are light. That's the inverse of what reads well.
- `bush_*` is black + `#47352c` + `#504433`. `tree_*` is mostly black. Both vanish on a `#47352c` ground.
- The palette (`asset_library/ittaimanero/palette.json`, 41 colours) has lighter earth/olive tones to choose from:
  `#77664e`, `#7f765d`, `#83775b`, `#8e886a`, `#928969`, `#949974` (greyish olive), `#d4ccab`.

## Do

1. **Pick the ground colours** with a small comparison sheet (`project/runs/T-123/a#/candidates.png`). Show 3
   candidates for the dominant ground base: (a) `#77664e` (simply swap ground and dirt), (b) `#7f765d` or `#83775b`,
   (c) `#8e886a` or `#949974` for an olive look. Each one is a 12×8-tile patch at 4× with a dark path through it,
   bushes, trees, rocks, scrap, a fence piece and a survivor and zombie sprite on top. Show each at 1× day and under
   the night tint (multiply by `NIGHT_COLOR` from `game/scripts/world/day_night_tint.gd`). Pick the one where props
   and units read best without the ground getting busy or washed out. Record the choice and why in `work.json`.
   Rules: one or two palette colours for speckle detail; black stays the blade/flower colour; paths and dirt patches use
   `#47352c` as their base, with the current `#77664e` specks inverted to the darker tone where needed.
2. **Recolour in place**, palette-exact, with a PIL script committed at
   `asset_library/ittaimanero/gapfill/terrain_light.py`: overwrite `game/assets/pixel/terrain/grass_1..4.png`,
   `flowers_1..2.png`, `dirt.png`, `dirt_2.png`, `path_boundary.png` and the 13 `path_<suffix>.png` cells (keep them
   identical to the atlas cells). **Same file names, sizes and atlas layout**, so no game code changes. In the path
   atlas, the inside of the path becomes the dark dirt and the outside becomes the new ground. Check edges and corners
   still blend (no 1-px seams of the old colour). `tuft_1/2` stay black blades; just check they read on the new ground.
   If the T-102 processing script would regenerate these files, update it (or its manifest) too, so a re-run doesn't
   undo this. Update `ASSET_INDEX.md` / the manifest hashes.
3. **Props contrast:** with the new ground, black-outlined bushes, trees, rocks and scrap should already stand out. If a
   prop family still blends in (e.g. bush interiors of `#47352c` now match the dark paths, or rocks match a lighter
   ground), make a palette-exact tweak to that prop's PNGs in the same script (e.g. bush foliage one step lighter or
   darker). Don't touch building, character or zombie art.
4. **Re-import and capture** (commands in ARCHITECTURE.md): run `godot --headless --path game --import`. Capture
   `map_overview`, `default`, `night` and `final_night` before (do it first) and after into
   `project/runs/T-123/a#/before_<name>.png` / `after_<name>.png`. Add a side-by-side `before_after.png` (left
   before, right after, 1×, no resampling).
5. Run the full test suite and the 300-frame smoke. They should pass untouched. If `test_world_view_qa.gd` pins a
   colour or file hash, update it and say so.

## Acceptance criteria

- `after_map_overview.png` and `after_default.png`: open ground is clearly lighter than paths and dirt patches. Bushes,
  trees, rocks and scrap stand out at a glance. The map no longer reads as one dark brown.
- `after_night.png` (and `final_night`): survivors, zombies, walls and props are still distinguishable from the ground
  under the night tint.
- Every changed pixel is a palette colour, with binary alpha. Same file names, sizes and atlas order (the path atlas is
  still 208×16 in `PathTiles.SUFFIXES` order). The script reproduces the files exactly.
- `candidates.png` and `before_after.png` are in the run folder. The chosen colour and the reason are in `work.json`.
- No game code changes needed. Import clean, all tests pass, smoke clean.

## Pitfalls

- Don't tint in code (no `modulate` on the TileMapLayer). The art itself must change, so the palette stays exact.
- Don't make the ground so light that the night tint turns it grey-white, or that the earth walls (`#77664e`-ish)
  vanish into it. Check the fence/earth-wall pieces in `buildings_pixel` too, and mention it in `notes_for_qa`.
- The dirt clearing around the Command Center becomes dark. Check that the Command Center and early buildings still
  read on it (capture `default`).
- Keep the files at 16×16 native size. Never pre-upscale.
