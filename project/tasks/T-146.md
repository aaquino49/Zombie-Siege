# T-146: Save/Continue 2: autosave every dawn and a Continue button on the main menu

Milestone: M7 | Type: code | Owner: gemini | Scenario: `main_menu_continue`

## Goal

Use T-144's `SaveGame` to make runs resumable (GDD §17.1). The game writes `user://savegame.json` at every dawn; the
main menu shows **Continue (Day N)** when a valid save exists; Game Over and Victory delete the save.

## Do

1. `Game` autoload (`game/scripts/autoload/game.gd`): `const SAVE_PATH := "user://savegame.json"`,
   `save_now(extra)`, `has_save() -> bool`, `save_day() -> int` (for the button label), `delete_save()`, and
   `continue_game()` which transitions like `start_new_game()` but builds `state` via `SaveGame.restore(...)` instead of
   `GameState.new` (then sets speed and `waves.enabled = true` exactly like `new_game`, and emits `game_started`). A
   corrupt or wrong-version save is deleted with a warning and the menu hides Continue. Write via a temp file then
   rename, so a crash mid-write never leaves a half file. All paths injectable for tests (like `GameSettings.PATH`).
2. Autosave: when the dawn report is processed (`state.dawn_processed`) and the game isn't over/won, save. Put the
   tutorial hint flags (`TutorialHints.shown` from the HUD's `HintPanel`) in `extra["hints"]` and restore them on
   continue so seen hints don't reappear.
3. `state.game_lost` / `state.game_won` → `delete_save()`. New Game keeps the old save until the new run's first dawn
   overwrites it (accepted; logged in assumptions).
4. Main menu (`main_menu.tscn/.gd`): a **Continue** button above New Game, label `Continue (Day N)`, visible only when
   `Game.has_save()`. Keyboard focus starts on Continue when visible. Keep every existing button node path.
5. Pause menu: one line of small text "Progress is saved every dawn" under the buttons, so players know Quit is safe.
6. Scenario `main_menu_continue.gd` (writes a temp save, shows the menu). Tests: save/continue/delete with temp paths,
   corrupt file handling, hints carried in `extra`, menu shows/hides Continue. Extend `qa_m4_menu_flow.gd` with a
   Continue path (play to dawn 2, quit to menu, Continue, check day 2 and resources match).

## Acceptance criteria

- `main_menu_continue` capture shows "Continue (Day N)"; `main_menu` (no save) shows no Continue button.
- Live flow: play to dawn, Quit to Menu, Continue → same day, resources, buildings and survivors.
- Game Over and Victory delete the save; a corrupt save never crashes and is removed.
- Menu flow scripts pass; all tests, import, smoke and screenshot clean. Tests never touch the real `user://savegame.json`.

## Pitfalls

- `Game._transition` reloads the scene; restore the state before `game_started` fires so the world view binds to it.
- The smoke and screenshot runs must not leave or read a real save: guard autosave behind the same "scenario/headless
  smoke" checks other features use, or point the path at a temp file in those runs.
- Don't touch the title scene from T-112 beyond adding the button.
