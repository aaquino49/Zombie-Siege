# T-095: Balance bot v3: second farm, builders that scale with blueprints, guards that scale with population

Milestone: M6 | Type: code | Owner: gemini | Scenario: `default`

## Goal

Make the headless balance bot play more like a sensible human, so balance pass 2 (T-115) tunes the game and not
the bot's blind spots. T-027 found the bot loses with resources banked because it never builds a second farm,
never has a second builder, and keeps a flat guard count.

## Context

- The bot is `game/scripts/sim/balance_bot.gd` (class `BalanceBot`), **not** `game/dev/`. The runner is
  `game/dev/balance_run.gd`. Tests: `game/tests/test_balance_bot.gd`.
- `job_plan(day, survivors, ammo, food, complete_farms, workshop_complete, open_blueprints)` is a pure static
  function. `_decide(state, memo)` places blueprints, capped at 2 open (`while blueprints().size() < 2`).
- Current results after T-098 pacing: sensible won 5/5 (and 10/10 on seeds 1337, 1–9), none loses on night 4.

## Do (only `balance_bot.gd` and its tests)

(a) **Food:** in `_decide`, before ring-wall rebuilds and before the radio-tower early return, if projected food per
    day (`complete_farms * 2 * food_per_farmer - survivors`) is below 0 and every complete farm is staffed, then
    place another farm (one at a time, no farm blueprint already open).
(b) **Builders:** `job_plan` adds a second builder only at 3+ open blueprints, but `_decide` caps open blueprints
    at 2, so this never fires. Use a second builder at `open_blueprints >= 2` (with survivors >= 7), or add a
    `damaged_buildings` argument and count those too.
(c) **Guards:** scale with population instead of day only, roughly `clamp(ceil(survivors / 4), 1, posts + 1)`
    where posts is watchtowers × their guard slots, still ramping by day early. Fill at least one gatherer first
    when dusk wood is below 20.
(d) **Crafter:** the stop rule `ammo < 40 + 20 * day` caps final-night stock around 440. Raise the target from
    day 17 (for example `+ 60 * (day - 16)`), or add a second crafter when a second workshop exists.

Keep `job_plan` pure and the bot deterministic (no wall-clock, no global RNG).

## Acceptance criteria

- Only `game/scripts/sim/balance_bot.gd` and `game/tests/test_balance_bot*.gd` change.
- New unit tests cover each rule: a second farm is placed when the food balance is below 0 with full farms; a
  second builder at the blueprint cap; the guard count scales with survivors; the day-19 crafter target is above
  the old `40 + 20*day`.
- `godot --headless --path game --script res://dev/balance_run.gd -- --seeds=1337,1,2,3,4 --strategy=both` still
  reports sensible won ≥ 4 of 5, and none still loses on nights 3–6 on every seed. Paste the BALANCE /
  BALANCE_SUMMARY lines into work.json, plus seeds 5–9 for sensible.
- Full test suite, import and 300-frame smoke are clean.

## Pitfalls

- Tests must not assert balance outcomes (wins/losses). Test the rules (pure `job_plan` and small set-ups).
- Don't change `game/data/*.json`. Balance numbers are T-115's job.
- The bot must only use public GameState commands (`try_place`, `try_upgrade`, `set_job`).
