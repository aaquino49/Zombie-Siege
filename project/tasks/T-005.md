# T-005: Camera controls

Milestone: M1 | Type: code | Owner: gemini | Scenario: `camera_zoomed`
Depends on: T-004 (world scene with a plain `Camera2D` child of `World`).

## Goal

GDD §11 camera: WASD/arrow pan, screen-edge pan, mouse-wheel zoom 0.5×–2× toward the cursor, always clamped to the 48×48 map (3072×3072 px).

## Files to create / change

1. `game/scripts/world/camera_math.gd`: `class_name CameraMath extends RefCounted`, static pure functions (unit-tested):
   - `clamp_position(pos: Vector2, zoom: float, viewport: Vector2, map_px: Vector2) -> Vector2`: keeps the visible rect (`viewport / zoom`) inside `[0, map_px]`. If the visible rect is wider/taller than the map, centre on that axis.
   - `clamp_zoom(z: float) -> float`: clamps to `[ZOOM_MIN, ZOOM_MAX]` = 0.5, 2.0.
   - `zoom_toward(pos: Vector2, old_zoom: float, new_zoom: float, cursor_offset: Vector2) -> Vector2`: new camera position so the world point under the cursor stays under the cursor. `cursor_offset` = mouse position minus viewport centre, in screen px.
2. `game/scripts/world/camera_controller.gd` (`extends Camera2D`): attach to the `Camera2D` node in `world.tscn`.
   - Pan speed `PAN_SPEED := 900.0` screen px/s, divided by zoom so it feels the same at every zoom.
   - Edge pan: `const EDGE_PAN_ENABLED := true`, 12 px margin. Skip edge pan when the window isn't focused, and when the mouse is outside the viewport.
   - Mouse wheel: zoom step ×1.1 per notch, via `_unhandled_input` (so UI panels added later can eat wheel events).
   - Use `Input.get_vector("cam_left", "cam_right", "cam_up", "cam_down")`.
   - Uses real (unscaled) delta. **Decision:** game speed/pause (T-009) is a multiplier inside `GameState`, not `Engine.time_scale` or `get_tree().paused`, so the camera keeps working while paused.
   - `map_px` comes from `Game.state.data.balance("map_size") * Grid.TILE`. No hard-coded 3072.
   - Starts centred on the Command Center (keep T-004's behaviour).
3. `game/project.godot` `[input]`: define `cam_left` (A, Left), `cam_right` (D, Right), `cam_up` (W, Up), `cam_down` (S, Down), `zoom_in` (wheel up, `=`), `zoom_out` (wheel down, `-`). Also define now, with no handlers yet, so later tasks share one input map: `pause` (Space), `speed_1` (1), `speed_2` (2), `speed_3` (3), `build_menu` (B), `cancel` (Escape), `roster` (R). Use physical keycodes.
4. `game/dev/scenarios/camera_zoomed.gd`: sets camera zoom to 2.0 near a map corner, e.g. aim at tile (2, 2). The screenshot must show the clamp (the map edge lines up with the screen edge, no grey void beyond the map).
5. `game/tests/test_camera_math.gd`: clamp at each edge at zoom 0.5/1/2; centring when the view is bigger than the map; `clamp_zoom` bounds; `zoom_toward` keeps the cursor's world point fixed (within 0.01 px); zooming with cursor at centre doesn't move the camera.

## Acceptance criteria

- Pan with WASD/arrows and screen edge; wheel zoom 0.5×–2× toward the cursor; the view never shows outside the map.
- All input actions above exist in `project.godot`.
- `test_camera_math.gd` passes; all tests and smoke pass.
- `camera_zoomed` screenshot shows the 2× view clamped at the map corner.

## Pitfalls

- In Godot 4 `Camera2D.zoom` > 1 means zoomed **in** (things bigger). Visible world size = viewport size / zoom.
- Don't use `limit_left/right/...` alone; they don't handle "view bigger than map" centring, and the math must be testable. Setting them as a backup is fine.
- Don't read input in `_process` for wheel events (wheel only arrives as events).
- Don't edit `dev_tools.gd`.
