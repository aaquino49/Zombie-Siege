## Goal

T-219's `researchers` column is always 0: `BalanceBotM12.measurements` runs
at the dawn/loss row, when everyone is sheltered and the phase is not DAY.
T-220 needs a real signal for how many Researchers actually worked. Add one
appended CSV column, `day_researchers`: the **peak** number of survivors
counted as working researchers during the day that led into that night.

## Context

- Counting rule already exists inside `BalanceBotM12.measurements`
  (`game/scripts/sim/balance_bot_m12.gd` ~line 159): useful, job RESEARCHER,
  activity RESEARCHING, DAY phase, not sheltered, not moving, standing in the
  ring of a complete `field_lab`. Extract it into a static helper
  (e.g. `BalanceBotM12.working_researchers(state) -> int`) and reuse it, so
  the old column and the new one share one definition.
- Note the existing dusk sample happens on the tick that switches DAY->NIGHT,
  when the phase is already NIGHT, so the count would also be 0 there. That
  is why this column is a running max over DAY, not a single dusk sample.
- Two loops need it: `BalanceBot.run` in `game/scripts/sim/balance_bot.gd`
  (`night` dictionary, ~line 24/62) and `_run_jittered` in
  `game/dev/balance_run.gd` (~line 109/150). Track the max while
  `state.clock.phase == DAY` (each bot decision or each tick, your choice,
  but the same in both loops), reset it with the other per-night fields.
- Append `"day_researchers"` at the end of the column list
  (`balance_bot.gd` line ~10, after `cc_damage`) and in every row writer.
