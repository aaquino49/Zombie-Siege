# T-203: Balance harness: --repeat=K with jittered bot cadence and per-seed win rate

Milestone: M11 | Type: code | Owner: gemini | Scenario: `default`

Follow-up from the T-197 review. Harness-only; no sim, data, bot or UI changes.

## Problem

T-197 found the bot's win counts flip on tiny perturbations (rain-only at 5%
moves Normal 7/3/0 to 6/3/1), so one deterministic run per seed measures
final-night coin flips, not design. Balance passes need a win-rate signal per
seed instead of a single W/S/L.

## Scope fence

Touch: `game/dev/balance_run.gd` (CLI parsing, repeat loop, per-seed and
matrix reporting) and harness tests (short runs only). Optionally
`project/assumptions.md`.
Do NOT touch: `game/scripts/sim/balance_bot.gd` (T-204 owns it),
`GameState.rng` or any game sim file, `game/data/*.json`, UI or scenarios.
`project/decisions.md` only if a pin moves (it should not).

## Do

1. Add a `--repeat=K` option (default K=1) to the balance-run harness: rerun
   each seed K times with a small jitter on the bot's decision cadence (e.g.
   +- a few seconds on its build/job check timer).
2. Jitter uses its own `RandomNumberGenerator` seeded from
   `hash([map_seed, repeat_index, "jitter"])`; `GameState.rng` streams stay
   untouched so default runs are identical.
3. With K>1 print per-seed win/survived/lost rates plus matrix totals for
   each difficulty and strategy. Keep the existing CSV columns; add the rate
   summary as extra stdout lines (or extra columns documented in the brief).
4. Unit test: a short run (e.g. 3 nights, 1-2 seeds) covers the repeat/jitter
   option: K=1 equals today's output, K=2 runs twice with the jitter RNG
   consumed and different cadence offsets. Full 20-night matrices stay in the
   worker's manual runs, not in the test.
5. Run the full suite, import and 300-frame smoke.

## Acceptance criteria

- Running the harness with no `--repeat` gives byte-identical results to
  before (seed-1337 sensible Normal still a 2709.50 s win).
- `--repeat=5` prints per-seed win/survived/lost rates and matrix totals for
  each difficulty and strategy.
- Jitter uses its own RNG seeded from seed + repeat index; `GameState.rng`
  streams are untouched.
- A unit test covers the repeat/jitter option on a short run (e.g. 3
  nights); all tests pass, import/smoke clean.

## Pitfalls

- Default K=1 must reproduce today's output exactly; no existing test pin
  moves.
- Never seed or draw the jitter RNG from `GameState.rng`.
- Keep LF line endings and explicit static types.
