# T-056: Night shelter: non-guards go inside at nightfall and come out at dawn

Milestone: M2 | Type: code | Owner: gemini | Scenario: `night_shelter`
Depends on: T-013, T-015, T-014, T-061. Uses `Jobs.tick`, `Survivor.Activity`, `BuildingStore.total_beds()` / the `beds` data (T-061), `GameState.cc_ring_tiles()` (T-061), `SurvivorLayer`, `SelectionController` and `RosterPanel`.

## Goal

GDD §6: "At night, non-guards go to Shelter or the Command Center and are safe inside." At nightfall, every survivor whose job isn't GUARD stops working and walks to the nearest building with free beds, then disappears inside. At dawn they come back out next to it and carry on with the same job. Guards stay outside (their night behaviour comes in M3).

## Rules

- **Shelters** are complete buildings with `beds > 0` in `buildings.json` (CC 4, Shelter 4). A survivor **holds a bed** at building B when `s.shelter_uid == B.uid` (walking there or inside).
- **At night** (`clock.phase == NIGHT`), `Jobs.tick` calls `ShelterRules.tick(state, s, dt)` instead of the job tick for every non-guard survivor:
  1. If `shelter_uid == 0` or that building is gone or incomplete: pick the nearest (squared distance from `s.pos` to `center_world()`, then uid) complete shelter building with `beds_held < beds`. If every one is full, **overflow goes to the Command Center**. Clear the job's work state: `path`, `work_uid = 0`, `work_acc = 0`, activity WALKING. Keep `job`, `gather_kind`, `work_tile` and the carried load. Path with `find_path_adjacent(s.tile(), b.origin, b.size)`. If there's no path, retry after `job_retry_interval` (stays outside, activity IDLE).
  2. When standing in the building's ring and not moving: `sheltered = true`, activity SHELTERED, path cleared. Bank any carried load into resources (`resources.add` + `resource_delivered` at the building centre) and clear the carry.
  3. While sheltered: do nothing.
- **At dawn** (`clock.phase == DAY` and `s.sheltered`, checked at the start of that survivor's `Jobs.tick`): `sheltered = false`, `shelter_uid = 0`, place the survivor on the first passable ring tile of its shelter building (sorted y then x; for the CC use `cc_ring_tiles()`), activity IDLE, `job_timer = 0`. The normal job tick resumes the same job on the same frame or the next.
- A survivor not yet inside when dawn arrives just clears `shelter_uid` and goes back to work.
- If a shelter building is removed while survivors are inside it (M3 damage, or a test calling `buildings.remove`), they reappear on its former ring and re-pick a shelter if it's still night.
- Guards ignore all of this.

## Files

### Sim
1. `game/scripts/sim/survivor.gd`: `var sheltered: bool = false`, `var shelter_uid: int = 0`, `Activity.SHELTERED` added at the **end** of the enum (don't renumber existing values), and `activity_label` returns "Sheltered".
2. `game/scripts/sim/shelter_rules.gd` (new): `class_name ShelterRules extends RefCounted`.
   - `static func beds_held(state: GameState, b: Building) -> int`
   - `static func pick_shelter(state: GameState, s: Survivor) -> Building`
   - `static func tick(state: GameState, s: Survivor, sim_dt: float) -> void`
   - `static func release(state: GameState, s: Survivor) -> void` (the dawn step)
3. `game/scripts/sim/jobs.gd`: per survivor: if `s.sheltered or s.shelter_uid != 0` and phase is DAY → `ShelterRules.release`. Then, if phase is NIGHT and `s.job != GUARD` → `ShelterRules.tick` and skip the job. Otherwise, the existing job dispatch. Keep T-061's hunger `dt`.
4. `game/scripts/sim/survivor_store.gd`: sheltered survivors never move (their path is empty; assert it in a test).
5. `game/scripts/sim/game_state.gd` `set_job`: changing the job of a sheltered survivor at night keeps it sheltered (the new job starts at dawn). Changing a survivor to GUARD at night releases it on the next tick (it stays outside).

### Tests

   - Nightfall: every non-guard paths to a shelter and is `sheltered` within N ticks. Activity SHELTERED; nobody stands on an impassable tile on the way.
   - Bed capacity: 6 survivors (add 2 with `survivors.add`), CC only → 6 go to the CC (overflow rule). With one complete shelter: no building has more than its beds while there's free capacity elsewhere, and the nearest-with-free-beds rule holds.
   - A blueprint shelter is never used.
   - Carried load is banked on arrival (wood rises by the carried amount, carry is 0).
   - Dawn: sheltered survivors reappear on passable ring tiles, `sheltered == false`, and their job and gather_kind are unchanged. A gatherer goes back to harvesting and a builder resumes a blueprint within a few seconds.
   - Guards stay outside and keep their position and activity.
   - A shelter removed while occupied → its survivors reappear on passable tiles and re-shelter in the CC.
   - `SurvivorLayer.sync` hides a sheltered survivor's sprite. `select_at_world` on its position doesn't select it.
   - The farm/craft/gather production of a full day is unchanged: production happens only by day, so these tests still pass.

- `night_shelter` screenshot shows a night with only the guard outside and the roster listing the others as Sheltered.
- default, survivors, gathering, construction, production, dawn_hunger and ui_roster screenshots unchanged.
- All tests pass with no SCRIPT ERROR; smoke passes; import clean.

## Pitfalls

- **Existing tests that tick past nightfall** (gathering, builder, production and dawn tests with long loops) will now see workers stop at night. Grep `game/tests/` for `day_length` and long `state.tick` loops. Fix the tests by keeping them inside the day (or by asserting the new behaviour), with a comment. Don't change job logic to make them pass.
- Builders currently build blueprints at night. After this task they shelter instead, which is intended (GDD §6).
- Adding SHELTERED at the end of the enum keeps every existing `Activity` value and test intact.
- Static typing everywhere. Files under ~400 lines. Nodes in unit tests are never in the tree (see `game/tests/README.md`).
- Godot commands: only the ones in `project/ARCHITECTURE.md`. Always pass `--path game`. Scratch output goes under `project/runs/` or `game/*_out.txt`.
