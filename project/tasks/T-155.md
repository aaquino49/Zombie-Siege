# T-155: Chore: SaveGame keeps the 64-bit rng_state exact through JSON

Milestone: M7 | Type: code | Owner: gemini (Codex stands in while Gemini's quota is out) | Scenario: `default` | skip QA

**Runs in lane B alongside the v1.1.0 export (T-114).** Touch only the files named below; never the project settings, the export preset, `builds/` or `README.md` (T-114 edits those). This change is small and fully tested, so it is fine whether or not it lands before the export snapshot.


## Goal

Godot's JSON parser returns every number as a float, so `SaveGame`'s `rng_state` (64-bit int) loses its low bits on
load (verified on 4.7.2: 2343518260280137770 → 2343518260280137728). A continued game then plays a different random
sequence, and values near INT64_MAX can overflow on `int()`. `test_save_game.gd` hides it by comparing against the
JSON-parsed capture (`norm1`) rather than the original capture. Fix it before T-146 ships Continue and T-147 adds
difficulty to the same file.

## Do

In `game/scripts/sim/save_game.gd`:
1. `capture`: write `"rng_state": str(state.rng.state)`.
2. `restore`: `state.rng.state = String(save["rng_state"]).to_int()`.
3. `_validate`: accept `rng_state` only as a String with `is_valid_int()`. Keep `VERSION := 1` (no saves have shipped).
4. Tidy `restore`'s resources: loop over `ResourceStore.KINDS` instead of the special-cased `food` branch.

In `game/tests/test_save_game.gd`: add a test that captures → `to_json` → `from_json` → `restore`, then asserts
`restored.rng.state == original.rng.state` and that the next 5 `randi()` values match a `RandomNumberGenerator` copied
from the original state. Keep the existing tests.

## Acceptance criteria

- `rng_state` is saved as a decimal string and restored exactly after a JSON round trip.
- New test checks exact rng state and identical next `randi()` values.
- `restore` sets resources by looping over `ResourceStore.KINDS` (no `food` special case).
- Existing `test_save_game` tests still pass; full suite 0 failed; import, smoke and screenshot clean.

## Pitfalls

- Don't touch `game_state.gd`, the balance bot or data JSON.
- Copy the RNG for the comparison by setting `seed`/`state` on a new `RandomNumberGenerator` *before* calling `randi()`
  on either one.
