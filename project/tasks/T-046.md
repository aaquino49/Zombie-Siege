# T-046: Build bar: buildings with icon, name and cost; wired to BuildMode

Milestone: M1 | Type: code | Owner: gemini | Scenario: `build_mode`
Depends on: T-045 (BuildMode with `select`, `cancel`, `mode_changed`). Part 3 of 3 of the old T-040. Closes the M1 goal "place buildings that cost resources".

## Goal

A bar at the bottom-centre of the screen lists every building the player can place today. Each button shows the icon, the name and the cost. Clicking a button selects that building in BuildMode, and clicking it again (or right-click/Esc) cancels. The bar gains new buildings at dawn, dims ones you can't afford, and B toggles it.


## Files

1. `game/scenes/ui/build_bar.tscn` (CanvasLayer `BuildBarLayer` > PanelContainer `Panel` with `assets/ui/panel.png` > HBoxContainer `HBox`):
   - Let the panel size to its contents. Keep the bottom-centre anchors (0.5, 1.0), set `grow_horizontal = BOTH` and `grow_vertical = BEGIN`, and set `offset_left = offset_right = 0`, `offset_bottom = -8`. Remove the fixed ±200 offsets. Seven 96-px buttons on day 2 must fit and stay centred.
   - Panel `mouse_filter = STOP` (clicks on the bar never reach the world). HBox `IGNORE`.
2. `game/scripts/ui/build_bar.gd`: `class_name BuildBar extends CanvasLayer`, fully typed (`var _state: GameState`, `var btn: Button`, the sort lambda params, ...).
   - **No `@onready`.** Use `func _panel() -> PanelContainer: return $Panel` and `func _hbox() -> HBoxContainer: return $Panel/HBox`, so tests can `bind()` an instance that isn't in the tree.
   - `bind(state)`: store the state, connect `clock.dawn` → `_rebuild_buttons` and `resources.changed` → `_update_affordability`, then build.
   - `static func cost_text(cost: Dictionary) -> String`: skip zero amounts and join with `" · "`, e.g. `"5 wood"`, `"25 wood · 5 scrap"`, or `"Free"` if nothing is left. Order the keys wood, scrap, food, ammo.
   - Buttons: one per `data.buildings_unlocked_on(clock.day)` that passes `Placement.is_placeable_type`, sorted by `unlock_day` and then total cost. Each button: `custom_minimum_size = Vector2(96, 84)`, `text = name + "\n" + cost_text(cost)`, `icon = BuildingSprites.texture_for(...)`, `expand_icon = true`, `icon_alignment = HORIZONTAL_ALIGNMENT_CENTER`, `vertical_icon_alignment = VERTICAL_ALIGNMENT_TOP`, `toggle_mode = true`, `focus_mode = FOCUS_NONE` (Space is pause), `tooltip_text = name + "\n" + cost text`, `set_meta("type_id", id)`. A small font size override (e.g. 12) is fine if the text doesn't fit.
   - When rebuilding, `hbox.remove_child(btn)` and then `btn.queue_free()`, so the count is right immediately.
   - Button `toggled(on)`: `building_selected.emit(type_id if on else "")`.
   - `func set_active_type(type_id: String) -> void`: for each button, `set_pressed_no_signal(meta == type_id)`. It must **not** re-emit `building_selected` (no feedback loop with BuildMode).
   - `_update_affordability`: `modulate.a = 1.0` when `resources.can_afford(cost)`, otherwise `0.5`. Still clickable, so the red ghost explains "Not enough resources".
   - `_unhandled_input`: the `build_menu` action (B) toggles `_panel().visible`. Return early if `_state == null`.

- Clicking a bar button selects it in BuildMode, and clicking it again cancels. Esc/right-click un-presses the button (via `mode_changed`). Clicks on the bar never place a building.
- All new code is statically typed.
- All tests pass and the test output has **no `SCRIPT ERROR` line**. Smoke passes. `default`, `hud`, `clock` and `build_mode_invalid` still look right.
- No stray files in the repo root or `game/`.

## Pitfalls

- `button_pressed = x` emits `toggled`. Use `set_pressed_no_signal` wherever code (not the player) changes the pressed state.
- `GameData.buildings_unlocked_on` returns a PackedStringArray. Copy it into an `Array[String]` before `sort_custom`.
- The HUD top bar already stops mouse clicks. Don't add any full-screen Control with `MOUSE_FILTER_STOP`, or every world click is swallowed.
