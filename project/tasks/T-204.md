# T-204: Balance bot reacts to a fog forecast

Milestone: M11 | Type: code | Owner: gemini | Scenario: `default`

Follow-up from the T-197 review. Bot-only; no game sim, data, harness or UI
changes.

## Problem

The balance bot (`game/scripts/sim/balance_bot.gd`) never reads the morning
forecast, so its fog-night losses overstate what a player sees (T-197
pitfall): a human who is told "Fog: range -1" posts another guard or builds
turrets closer, the bot does not.

## Scope fence

Touch: `game/scripts/sim/balance_bot.gd`, bot unit tests
(`game/tests/test_balance_bot.gd` or a new bot test file), and
`project/decisions.md` (version + before/after table + moved pins).
Optionally `project/assumptions.md`.
Do NOT touch: `game/dev/balance_run.gd` CLI parsing (T-203 owns it), any game
sim file, `game/data/*.json` (no data tuning here), UI, scenarios or saves.

## Do

1. On a day whose morning forecast (`WaveSpawner.forecast` /
   `state.weather_night()`) has fog, the `sensible` and `scavenger`
   strategies answer it the way GDD section 20.1 suggests: post one extra
   guard for the night if a survivor is free, and place any new
   turret/watchtower within the fog-reduced range of the Command Center
   approach (turret 5 -> 4, tower guard 7.5 -> 6.5 effective).
2. Keep the `none` strategy unchanged (it must still lose early).
3. Bump the bot version constant and record it, the before/after 10-seed
   table (Normal + Hard, sensible at minimum) and any moved test pins
   (old -> new) in `project/decisions.md`.
4. Unit tests: a forced-fog-forecast day posts at least one more guard than
   the same state on a clear day; turrets/towers built on fog days use the
   fog-reduced range for placement; `none` behaviour is unchanged.
5. Run the full suite, import and 300-frame smoke.

## Acceptance criteria

- On a forecast fog day the sensible bot posts at least one more guard than
  on a clear day with the same state (unit test with a forced fog forecast).
- Turrets/towers built on fog days use the fog-reduced range for placement
  (unit test).
- `none` strategy behaviour is unchanged and still loses early.
- Bot version bumped; before/after 10-seed table and moved pins recorded in
  `project/decisions.md`; all tests pass, import/smoke clean.

## Pitfalls

- Read the forecast only; never change the forecast, weather rolls or game
  RNG streams.
- No `balance.json` / `weather.json` / `waves.json` edits: this is a bot
  task, not a balance pass.
- Keep LF line endings and explicit static types.
