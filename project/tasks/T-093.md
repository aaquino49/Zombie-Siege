# T-093: Fix: night never ends when runners get stuck chasing a walled-off survivor (+ night time cap)

Milestone: M4 | Type: code | Owner: codex | Scenario: `default`
Depends on: nothing open. Blocks T-027 (balance pass), because the balance bot softlocks on this bug.

## Goal

A night must always end. Today it ends only when `GameState.hostiles_remaining() == 0`. Two runners that can never
reach their target keep it at 3 forever, the clock never reaches dawn, and the player is stuck in an endless night.
Fix the stuck chase, and add a hard night-length cap as a safety net for any other stuck case.

## Evidence (PLAN 2026-10-10 22:07, reproduced by the quarterback)

The T-027 balance runs hit `Simulation tick cap reached` on seeds 1337 and 3 (night 10/11) with the CC at 100%.
The probe at `project/runs/T-027/attempt1_data/probes/probe.gd`, run with the data in
`project/runs/T-027/blocked_after_a3.patch` (seed 3, watch night 11), shows this at t=120 s and still at t=125 s:

```
Z runner tile=(27, 31) next=(28, 31)    Z runner tile=(28, 31) next=(29, 31)   (3 runners, positions unchanged)
S Alex job=FARMER act=IDLE tile=(27, 27) sheltered=false   (his shelter path is empty, so he stays outside)
MAP y=30 x=21..30 is a solid row of wall tiles between the runners and Alex
```

Cause, in `game/scripts/sim/zombie_ai.gd`: a runner sees the exposed survivor within `runner_seek_tiles` (6) and
takes a greedy step toward him with `_survivor_step`. The wall blocks every greedy step from (27,31), so that tick
falls through to the flow field, which moves it east to (28,31). From (28,31) the greedy step back to (27,31) gets
closer to Alex again, so it steps back. It flip-flops between two tiles forever, never attacks the wall and never
follows the flow field to the CC.

## What to change

1. **Stuck chase** (`zombie_ai.gd`, `zombie.gd`). Give each zombie a chase-progress memory, for example
   `chase_best_dist: float`, `chase_stall: float`, `chase_cooldown: float` on `Zombie`.
   - While `chase_cooldown > 0`, count it down and skip the survivor-seek branch entirely (normal flow field and
     building attacks).
   - While a seek target exists (out of attack range), whether or not `_survivor_step` found a step: if the
     distance to the target improved on `chase_best_dist` by at least about a quarter tile, store it and reset
     `chase_stall`. Otherwise add `dt` to `chase_stall`. When `chase_stall` reaches `runner_chase_stall_time`, set
     `chase_cooldown = runner_chase_cooldown` and reset the memory.
   - Reset the memory when there is no target, or the target changes.
   - New balance keys with code defaults: `runner_chase_stall_time` 2.0, `runner_chase_cooldown` 6.0.
   Keep the rest of the AI as it is (brutes, walkers, the pocket branch and building attacks).
2. **Night cap** (`game_clock.gd`, `game_state.gd`, `balance.json`).
   - New balance key `night_max_length` = 300 (default 300.0 in `GameClock`). `_night_can_end()` returns true when
     `elapsed >= _night_max_length` even if `night_end_check` says no. Keep the 45 s minimum as it is.
   - When dawn comes with zombies still alive, they retreat: in `GameState._on_dawn`, before anything else, remove
     every remaining zombie with `zombies.remove(uid)` (the pooled zombie view already reacts to `zombie_removed`;
     check this) and clear any pending spawns in `WaveSpawner`. Do **not** emit `zombie_killed` and do not count
     them as kills. Put the number in the dawn report dictionary as `zombies_fled` (no UI change).
   - The HUD night countdown, if it shows time, must not break when the night runs long. No other UI work.
3. Data: add the three keys to `game/data/balance.json`, keeping its existing formatting and line endings. If
   `GameData` validates required balance keys, leave them optional with code defaults.

## Tests (`game/tests/test_night_end.gd`, new)

- **Stuck runner:** seeded `GameState`, waves disabled. Place a complete horizontal row of `wooden_wall` (about 8
  tiles, with no gap) between a runner and an idle survivor 4 tiles away on the other side, with nothing else
  exposed nearby. Spawn the runner with `state.zombies.add("runner", pos)`. Tick 0.25 s at a time for up to 30 s
  of sim time during NIGHT. Pass if the runner leaves the 2-tile flip-flop: it either damages a building, or
  reaches attack range of a survivor, or its `state.flow.distance(tile)` improves by at least 3 tiles. Assert it
  did not spend the whole 30 s on the same two tiles.
- **Night cap:** a zombie that can never be killed or reach anything (for example walled in by impassable tiles, or
  `night_end_check` forced false on a bare `GameClock`). Night ends at `night_max_length` (±1 tick), not before 45 s
  and not after. With `GameState`, the zombie store is empty after dawn and the kills counter is unchanged.
- The open-ground runner chase still works: a runner with a clear line to an exposed survivor still reaches attack
  range (regression for T-078's behaviour).
- Re-run the existing zombie/combat tests. Nothing that passes today may fail.
