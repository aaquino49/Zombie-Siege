# T-061: Dawn rules: eating, hunger, leaving, beds and newcomers

Milestone: M2 | Type: code | Owner: gemini | Scenario: `dawn_hunger`
Depends on: T-014 (so the hunger slowdown also covers farmers and crafters).
Split out of the original T-014. GDD §6 is the source: "at dawn each survivor eats 1 food. If food is short, the survivors who don't eat become Hungry and work at 50% speed. After 2 hungry days in a row, a survivor leaves the colony. Newcomers: at dawn, if beds > population and food ≥ 2 × population, 1–2 newcomers arrive. Beds: the Command Center has 4. Each Shelter adds 4."

## Goal

One pure sim function processes each dawn and returns a report dictionary (the M4 Dawn Report panel will display it). Hungry survivors move and work at half speed and are labelled "Hungry" in the info panel and roster.

## Rules (all numbers from `balance.json` / `buildings.json`)

`DawnRules.process(state)` runs once per dawn, in this order:
1. **Eat.** `need := food_eat_per_survivor` (1). Survivors eat in priority order: `hungry_days` descending (the hungriest eat first, so a short day doesn't make the same person leave), then `uid` ascending. Each eater takes `need` food. Once `food < need`, the rest go unfed. Eaters set `hungry_days = 0`. Unfed survivors get `hungry_days += 1`.
2. **Leave.** Every survivor with `hungry_days >= food_hungry_leave_days` (2) is removed with `state.survivors.remove(uid)`. Anything they carry is lost.
3. **Newcomers.** `pop := survivors.count()` after step 2, `beds := state.buildings.total_beds()`, `food := resources.get_amount("food")` after step 1. If `pop > 0 and beds > pop and food >= food_newcomers_threshold * pop` (threshold 2): `n := state.rng.randi_range(food_newcomers_min, food_newcomers_max)` (1–2), capped at `beds - pop`. Spawn `n` survivors.
   - **Name:** the first entry of `survivor_names` that no living survivor uses. If every name is taken, use `"Survivor %d" % uid`.
   - **Variant:** `survivor_variants[(uid - 1) % size]`.
   - **Tile:** the first free passable tile of the CC ring (same ring and sort order as the starting survivors). If all are taken, use any passable ring tile.
   - **Job:** IDLE. The player assigns it.
4. Return the report: `{"day": int, "food_eaten": int, "hungry": Array[String] (names left unfed who stay), "left": Array[String], "arrived": Array[String]}`.

## Files

### Sim
1. `game/scripts/sim/survivor.gd`: `var hungry_days: int = 0` and `func is_hungry() -> bool: return hungry_days > 0`.
2. `game/scripts/sim/building_store.gd`: `func total_beds() -> int` sums `beds` from `buildings.json` over **complete** buildings only (blueprint shelters don't count).
3. `game/scripts/sim/dawn_rules.gd` (new): `class_name DawnRules extends RefCounted` with `static func process(state: GameState) -> Dictionary` (rules above). Keep helpers static and private (`_eat`, `_leave`, `_newcomers`, `_free_name`).
4. `game/scripts/sim/game_state.gd`:
   - `var rng: RandomNumberGenerator`, seeded with `map_seed + 2` in `_init`.
   - Move the CC ring-tile code from `_init` into `func cc_ring_tiles() -> Array[Vector2i]` (same filter and sort). Use it for the starting survivors and for newcomers. The starting survivors must not change: same tiles, names and jobs.
   - `signal dawn_processed(report: Dictionary)` and `var last_dawn_report: Dictionary = {}`.
   - In `_init`, connect `clock.dawn` to `_on_dawn(day: int)`, which sets `last_dawn_report = DawnRules.process(self)` and emits `dawn_processed`. Dawn then processes no matter whether the clock is advanced through `state.tick` or `clock.advance`.
5. **Hunger slowdown** (`food_hungry_speed`, 0.5):
   - `jobs.gd`: compute `var dt := sim_dt * (hungry_speed if s.is_hungry() else 1.0)` per survivor and pass `dt` to that survivor's job tick (builder, gatherer, production). Build progress, repair, harvesting, farming and crafting all slow down.
   - `survivor_store.gd` `tick`: the hungry survivor's `move_dist` is multiplied by the same factor. Read the factor once per tick, not per survivor.

   - `last_dawn_report` is set and `dawn_processed` is emitted once per dawn, including when the clock is advanced through several phases in one call.

## Pitfalls

- **Existing tests that cross a dawn will now see food eaten (−4).** Grep for `day_length`, `night_min_length`, `clock.advance` and long `state.tick` loops in `game/tests/`, and update any food assertions with a comment. Don't weaken unrelated assertions.
- `GameClock.advance` can cross several dawns in one call. Each `dawn` emit must process exactly once.
- `SurvivorStore.remove` while iterating `survivors.all()` is safe (it returns a copy), but don't remove from `_survivors` while iterating it directly.
- Don't touch the clock or night-ending logic. The lose condition at 0 survivors is M3 (T-021). Here, just don't spawn newcomers when pop is 0.
- Static typing everywhere, including the report arrays (`Array[String]`). Files under ~400 lines.
- Godot commands: only the ones in `project/ARCHITECTURE.md`. Always pass `--path game`. Scratch output goes under `project/runs/` or `game/*_out.txt`.
