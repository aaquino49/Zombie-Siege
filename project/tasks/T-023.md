# T-023: Victory condition (Radio Tower + night 20) and Victory screen

Milestone: M4 | Type: code | Owner: gemini | Scenario: `victory`
Depends on: T-022 (done). The helicopter fly-in is a separate task (T-084), so this task shows the Victory screen
straight away.

## Goal

The player can win. GDD §10: "Rescue happens at the first dawn after the tower is done and night 20 or later has
passed." If the tower isn't finished by night 20, nights carry on (the waves keep growing) until the first dawn where
both are true.

## Context (what already exists, so don't rebuild it)

- The Radio Tower is already a building: `game/data/buildings.json` `radio_tower` (2×2, 150 wood + 120 scrap,
  hp 500, `unlock_day` 8, `build_time` 300). Its sprite `assets/buildings/radio_tower.png` is drawn by
  `BuildingSprites`, and it is in the build bar from day 8. Builders construct it like any other building.
- `game/data/balance.json` has `"nights_to_win": 20`. Use it, not a literal 20 and not `waves.final_night`.
- `GameState._on_dawn` (`game/scripts/sim/game_state.gd`) runs `DawnRules.process`, emits `dawn_processed`, then
  `_check_lose()`. Nothing else listens to `dawn_processed` yet, so reordering it is safe.
- `GameState.stats()` returns the five end-of-game stats (`nights_survived` = `clock.day - 1`).
- `GameOverScreen` (`scripts/ui/game_over_screen.gd`, `scenes/ui/game_over.tscn`) is the model to copy: CanvasLayer,
  `bind(state)`, pauses and locks the clock, static `stat_rows()`, Restart (`reload_current_scene`) and Quit.
- `GameData.wave_for_night(n)` already grows past 20 (night 21 = 67 walkers, 36 runners, 14 brutes, 4 sides,
  not final), so "nights continue, getting harder" needs no wave change.

## What to do

1. **Sim (`game_state.gd`)**
   - Add `signal game_won` and `var won: bool = false`.
   - Add `func radio_tower_complete() -> bool`: true if any `radio_tower` building exists and `complete`.
   - Add `func _check_win() -> void`: if `game_over` is already true, return. If `radio_tower_complete()` and
     `clock.day - 1 >= int(data.balance("nights_to_win"))`, set `won = true`, `game_over = true` (so later
     `_check_lose` calls return early) and emit `game_won` once.
   - Reorder `_on_dawn` to: `var report := DawnRules.process(self)`, `_check_lose()`, `_check_win()`, then
     `last_dawn_report = report` and `dawn_processed.emit(report)`. Listeners then see the final
     `game_over`/`won` flags (the Dawn Report in T-024 depends on this). A loss at the same dawn wins over victory.
   - Leave `lose_reason` as `""` on a win. Don't change `stats()`.
2. **View: `VictoryScreen`**: new `scenes/ui/victory.tscn` + `scripts/ui/victory_screen.gd`
   (`class_name VictoryScreen extends CanvasLayer`, layer 20, hidden by default). Copy the GameOverScreen layout
   and panel style. Title **"RESCUED!"** in gold/green (not red). Subtitle: `"The helicopter got you out after %d nights."`
   with `nights_survived`. The five stat rows come from `GameOverScreen.stat_rows(_state.stats())`; reuse that, don't
   copy it. Buttons: Restart and Quit, the same behaviour as GameOverScreen (T-025 will reroute both screens).
   `bind(state)` connects `game_won`, and if `state.won` is already true, shows straight away. On show:
   `clock.set_paused(true)`, then `clock.locked = true`.
3. **`main.tscn` / `main.gd`**: add a `VictoryScreen` instance next to `GameOverScreen` and bind it in `_ready`.
4. **Scenario `game/dev/scenarios/victory.gd`**: `waves.enabled = false`, `clock.day = 20`, give wood/scrap,
   clear a 2×2 spot near the CC (use the same clearing approach as `game_over.gd`), `try_place("radio_tower", ...)` +
   `buildings.finish(uid)`, set a few believable stats (e.g. `zombies_killed = 812`, `time_played = 2400.0`),
   then set `clock.phase = GameClock.Phase.NIGHT` and `clock.elapsed` to `night_min_length`, and call `state.tick(0.1)`
   so the real dawn path fires the win. Centre the camera on the tower. Expect a dimmed map with the Victory panel.

## Tests: `game/tests/test_victory.gd`

Build GameState directly (seed 1337, waves disabled). Give the resources, clear the tiles, and place and finish
the tower with the real APIs. Advance with a helper that sets night + elapsed and ticks (or ticks the real clock).
- Tower complete, night 20 ends → `won`, `game_over`, `game_won` emitted exactly once, `game_lost` never, and
  `stats().nights_survived == 20`.
- No tower, night 20 ends → not won, `clock.day == 21`, phase DAY. `wave_for_night(21)` isn't final and has more
  walkers than `wave_for_night(19)`.
- Tower finished during day 22 (after the night-20 dawn passed without a win) → no win at dawn 22 before it was
  finished, win at dawn 23.
- Tower complete but only night 19 ended (dawn of day 20) → not won.
- Tower still a blueprint (not complete) at the night-20 dawn → not won.
- Tower destroyed via `damage_building` before the night-20 dawn → not won.
- Same dawn, with the tower complete and all survivors gone (remove them) → `game_lost` fires, `won` stays false.
- Radio Tower placement is LOCKED on day 7 and OK on day 8 (`Placement.check`).
- `VictoryScreen` off-tree test (see `game/tests/README.md` "Testing scenes"): instantiate the scene, bind to a won
  state, and check the title text and the five stat rows. Skip it if it can't be done cleanly off-tree, and say so.

## Acceptance criteria

- `test_victory.gd` covers the cases above and passes. Existing lose-condition tests still pass.
- `_on_dawn` order is DawnRules → lose check → win check → `dawn_processed`. A same-dawn loss wins over victory.
- Win threshold comes from `balance.json` `nights_to_win`. No hard-coded 20.
- Scenario `victory` at 1280x720: dimmed map, readable "RESCUED!" panel, subtitle, five stats, Restart + Quit.
- All tests pass with no SCRIPT ERROR. Import, smoke and screenshot are clean. `game_state.gd` stays under 400 lines.

## Pitfalls

- Don't check the win in `tick()`. It only happens at dawn.
- `_check_lose` already returns when `game_over` is true, so setting `game_over` on a win stops a later "loss".
  Don't break that early return.
- Placement needs free tiles: on seed 1337 the clearing around the CC is 5 tiles. Pick an origin that
  `Placement.check` accepts, or clear occupants first, as `game_over.gd` does. Assert that placement returned OK so
  a silent failure can't fake a pass. (T-072 failed QA once for exactly this.)
- The clock's own `dawn` signal fires inside `advance()`. Don't call `_on_dawn` directly in tests. Drive the clock.
- Don't touch `GameOverScreen` behaviour beyond reusing `stat_rows`.
