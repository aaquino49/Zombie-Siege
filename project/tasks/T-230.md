# T-230: Fix: welcome hint card stretches to the bottom and covers the F1 Wooden Wall button

Milestone: M12 | Type: code | Owner: gemini | Scenario: `tutorial`
Depends on: none (T-221 done). T-222 (v1.7.0 export) waits for this task.
From QA T-221 (minor, `project/runs/T-221/a1/shot_tutorial.png`).

## Goal

At 1280x720, the Day-1 welcome hint shows three lines of text and a
"Got it" button. The card's panel runs from y≈108 almost to the bottom of
the screen (≈600 px tall, mostly empty). It covers the F1 Wooden Wall
build-bar button until the player dismisses it. The card must hug its
content and never overlap the build bar.

## Likely root cause (confirm before fixing)

`game/scenes/ui/hint_panel.tscn`: `PanelContainer` has a fixed width
(offset_left 8, offset_right 388). `HintLabel` uses `autowrap_mode = 3`
with no minimum width. A Godot 4 autowrap Label works out its minimum
height at its current width. On the first layout pass that width can be
about 0, so every word wraps onto its own line and the minimum height is
huge. The container then grows, and containers never shrink by
themselves. Longer queued hints can grow it the same way.

## What to change (scope fence)

- `game/scripts/ui/hint_panel.gd` and, if needed,
  `game/scenes/ui/hint_panel.tscn` only. No change to hint text, hint
  triggers, timings, `TutorialHints`, the HUD or the build bar.
- Give the label a stable wrap width: e.g. `custom_minimum_size.x` on
  `HintLabel` equal to the panel's inner width (panel width 380 minus
  margins). Keep the card's left/top position and its 380 px width.
- After every text change in `_display_card` (and in
  `_position_below_hud`), reset the panel to its minimum height:
  `_panel.reset_size()`, or set `size = Vector2(width, 0)`, deferred if
  needed so it runs after the label re-measures.
- Safety clamp: the card's bottom stays at least 8 px above the build
  bar panel's top. The build bar is the sibling CanvasLayer `BuildBar`,
  node `Panel`, anchored by `BuildBar._anchor_panel()`. If a hint is
  ever too tall for that, keep the top and let the label clip; do not
  move the card over the bar. Keep `HUD._position_toasts()` working,
  since it reads the panel's position and size.

## Acceptance criteria

1. In the `tutorial` scenario at 1280x720 (welcome hint showing), the
   hint card is no taller than its content plus margins (well under
   250 px for the welcome text). Its rect does not intersect the build
   bar panel's rect, and the F1 Wooden Wall button is fully visible and
   clickable.
2. Showing a long hint and then a short one shrinks the card back
   (no stale height).
3. New regression test (e.g. `game/tests/test_hint_panel_layout.gd`).
   It instances the main scene, or HintPanel plus BuildBar in a 1280x720
   viewport under the tree, shows `welcome`, waits for layout frames, and
   asserts both points above. It also checks every hint id that
   `TutorialHints` can show: each card's bottom stays above the build
   bar's top. Existing `test_tutorial_hints*.gd` and `test_ui_layout*.gd`
   still pass.
4. Screenshot: `tutorial` scenario capture shows a compact card and the
   full build bar, F1 Wooden Wall included.

## Pitfalls

- Off-tree Controls don't get a layout pass. Test under the tree and
  `await` a couple of process frames, or use combined minimum sizes the
  way `test_ui_layout.gd` does.
- Font sizes must stay multiples of 11 (`UiFont`); don't touch them.
- LF line endings. Never run git commit/reset/checkout/stash.
