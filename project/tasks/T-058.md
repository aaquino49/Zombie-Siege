# T-058: BuilderJob hardening: typed state params + zero build_time repair guard

Milestone: M2 | Type: code | Owner: gemini | Scenario: `construction`
Depends on: T-012. Absorbs QA bug T-057 (dropped as a duplicate).

## Goal

Two small fixes from the T-012 review and QA, with no other behaviour change.

1. **Static typing.** `game/scripts/sim/builder_job.gd` `tick(state, ...)` and `game/scripts/sim/jobs.gd` `tick(state, ...)` leave `state` untyped. Change both to `state: GameState` (ARCHITECTURE rule 3). If T-014 already typed `jobs.gd`, leave it as is.
2. **Zero-duration repair.** BuilderJob's REPAIRING branch divides by `b.build_time * repair_time_fraction`. The Command Center has `build_time` 0 (and repair cost 0), so once anything damages it (M3) a builder would divide by zero (INF → garbage HP). In `builder_job.gd`:
   - compute `var repair_duration := b.build_time * repair_time_fraction`;
   - if `repair_duration <= 0.0`: set `b.hp = b.max_hp`, `work_uid = 0`, `job_timer = 0.0`, activity IDLE (instant repair);
   - otherwise keep the current accumulation.

## Pitfalls

- Typing `state: GameState` in a static function of a class that GameState itself references can cause a cyclic-reference parse error in some Godot versions. If `--check-only` reports one, keep the type and check the import order. Godot 4.7 supports cyclic class_name references. Don't fall back to untyped without logging why in `project/assumptions.md`.
- Godot commands: only the ones in `project/ARCHITECTURE.md`. Always pass `--path game`. Scratch output goes under `project/runs/` or `game/*_out.txt`, never the repo root.
