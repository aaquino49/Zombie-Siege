# T-145: Juice: Command Center alarm (red screen-edge flash) and screen shake, with a Settings toggle

Milestone: M7 | Type: code | Owner: gemini | Scenario: `cc_alarm`

## Goal

GDD §11 promised "a screen-edge red flash when the Command Center is attacked", and it was never built (no code
listens for CC damage outside audio and the night log). Hits and building losses also have no physical feedback.
Add both (GDD §17.2): a red edge flash when the CC takes damage, and a short, small screen shake on big impacts.
Players who dislike shake can turn it off in Settings.

## Do

1. **CC alarm.** New `game/scripts/ui/cc_alarm.gd` (+ node in `game/scenes/ui/hud.tscn` or its own CanvasLayer above
   the world, below menus): a full-screen, mouse-ignoring red vignette (a gradient texture or a tiny shader that is
   transparent in the middle and ~45% red at the edges). `bind(state: GameState)` connects
   `state.building_damaged`; when `b.type_id == "command_center"` it flashes to full and fades out over 1.2 s. Repeated
   hits re-trigger at most every 0.4 s (no strobing). Hidden when the game is over or a menu is open.
2. **Screen shake.** New pure helper `game/scripts/world/screen_shake.gd` (`class_name ScreenShake extends RefCounted`):
   trauma model: `add(amount)` clamps trauma to 0..1, `tick(delta)` decays it at ~1.6/s, `offset()` returns
   `max_offset * trauma²` times a seeded noise/RNG direction (deterministic for a given seed). `CameraController`
   owns one and applies it to `Camera2D.offset` (never `position`, so clamping and panning are unaffected), rounded
   to whole screen pixels and divided by zoom. Max offset 6 px.
   Triggers (connect where `GameState` signals are already bound for the world view): building destroyed 0.5
   (CC destroyed 1.0), CC damaged 0.15 (throttled with the alarm). No shake from ordinary wall hits or shots.
3. **Setting.** `GameSettings.load_screen_shake()/save_screen_shake()` (`[gameplay] screen_shake`, default `true`,
   same load-before-save pattern), a "Screen shake" CheckButton in `settings_screen.tscn` Options after Hints, wired in
   `settings_screen.gd`. When off, `add()` is ignored. The alarm vignette stays on regardless (it is information).
4. Scenario `game/dev/scenarios/cc_alarm.gd`: night, zombies hitting the Command Center, capture taken while the
   vignette is visible (force a hit right before the capture frame if needed).
5. Tests: `test_screen_shake.gd` (trauma clamps, decays to 0, offset 0 at 0 trauma and ≤ max, deterministic with a
   seed, disabled setting ignores add), `test_cc_alarm.gd` (CC damage raises alpha, a farm hit does not, throttle),
   settings round-trip for `screen_shake` in the existing settings test.

## Acceptance criteria

- `cc_alarm` capture: red edges visible while the CC is under attack; the centre of the screen is unaffected.
- Shake moves only `Camera2D.offset`, by whole pixels, ≤ 6 px, and settles to zero within ~1 s; off when the setting
  is off.
- Settings screen shows a "Screen shake" toggle that persists in `user://settings.cfg`; `settings_screen` capture
  still fits at 1280x720.
- All tests, import, smoke and screenshot clean; no change to sim code or data.

## Pitfalls

- Headless tests: nodes are off-tree; keep the logic in `ScreenShake` / small pure functions so it's testable.
- Don't edit `main_menu.gd`, `pause_menu.gd`, the Dawn Report or the menu screens (T-135, T-112 are on them), the
  theme/font (T-141) or the build bar.
- The night `CanvasModulate` tints world nodes only; put the vignette on a CanvasLayer so it stays red at night.
