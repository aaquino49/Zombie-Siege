# T-025: Main menu + New Game / Restart / Main Menu flow

Milestone: M4 | Type: code | Owner: gemini | Scenario: `main_menu`
Depends on: T-023 (VictoryScreen exists and gets the same buttons). The pause menu and volume sliders are split
out into T-085.

## Goal

The game opens on a main menu (GDD §11: "Main Menu (New Game, Quit)"). New Game starts a fresh colony on a new map.
Game Over and Victory offer **Restart** (same map again) and **Main Menu**. Restarting any number of times leaks
nothing and prints no errors.

## Key decision: keep `main.tscn` as the main scene

The pipeline (smoke runs, `--scenario` screenshots, DevTools) relies on `get_tree().current_scene` being `main.tscn`.
So the menu is an **overlay inside `main.tscn`**, shown over a paused, dimmed live map, not a separate scene. Don't
change `run/main_scene`. Don't edit `scripts/autoload/dev_tools.gd`.

## What to do

1. **`scripts/autoload/game.gd`**
   - `var show_menu: bool = true` and `var next_seed: int = DEFAULT_SEED`.
   - `func start_new_game() -> void`: `show_menu = false`, `next_seed = _fresh_seed()` (from `randi()`, kept in a
     sensible positive range), then `get_tree().reload_current_scene()`.
   - `func restart() -> void`: `show_menu = false`, keep `next_seed` (the same map), reload.
   - `func quit_to_menu() -> void`: `show_menu = true`, reload. The map behind the menu can stay the last seed.
   - Before reloading, drop the old state: `state = null`. (`Game._process` ticks `state`. Make sure it never ticks a
     state whose view is gone; it's fine if `main._ready` creates the new one.)
2. **`main.gd`**
   - `Game.new_game(Game.next_seed)` instead of the default seed.
   - Add a static pure helper `static func scenario_arg(args: PackedStringArray) -> String` that returns the
     `--scenario=<name>` value or `""`. In `_ready`, read
     `OS.get_cmdline_args() + OS.get_cmdline_user_args()`.
   - Show the menu only when `Game.show_menu` is true **and** no scenario was requested. Scenario screenshots and
     every existing scenario must look exactly as before. (The `main_menu` scenario opens it explicitly.) The
     300-frame smoke run will show the menu, which is fine.
3. **`MainMenu`**: `scenes/ui/main_menu.tscn` + `scripts/ui/main_menu.gd`, CanvasLayer layer 30.
   - A full-screen dim (about 0.55 alpha black) over the live map. Big title **"ZOMBIE SIEGE"** (about 72 px, white with
     a dark outline; title art comes in M5 T-031, so keep the title a Label that's easy to swap for a TextureRect
     later), tagline **"Survive 20 nights. Build the Radio Tower. Get rescued."** (take 20 from `nights_to_win`), and
     two buttons: **New Game** → `Game.start_new_game()`, **Quit** → `get_tree().quit()`. Same panel/button styling as
     GameOverScreen.
   - `open(state)`: show, `clock.set_paused(true)`, `clock.locked = true` (Space/1/2/3 can't start the game behind the
     menu). Also stop map input while it's open: the dim `ColorRect` with `mouse_filter = STOP` covers clicks, and
     BuildMode/Selection/Camera keys should do nothing. The simplest way is to hide the HUD, BuildBar and RosterPanel
     layers while the menu is open.
4. **GameOverScreen and VictoryScreen**: buttons become **Restart** → `Game.restart()` and **Main Menu** →
   `Game.quit_to_menu()` (rename the Quit button label and node accordingly). Don't change anything else.
5. **Scenario `main_menu.gd`**: opens the menu over the default map (`main.get_node("MainMenu").open(Game.state)`).

## Tests: `game/tests/test_restart.gd`

- `scenario_arg`: `["--scenario=night"]` → `"night"`, args with no scenario → `""`, and it ignores other `--x=y` args.
- Create a full `GameState` with waves enabled, tick through night 1 with some zombies spawned, drop it, and assert a
  weakref to it is null. Do this **3 times in a row** with different seeds, the same way `test_no_ref_cycles.gd` does
  (T-072). No SCRIPT ERROR or leak warnings in the test output.
- MainMenu off-tree (read `game/tests/README.md` "Testing scenes and Node scripts"): `open(state)` pauses and locks
  the clock. The tagline contains `nights_to_win`.
- If `Game` (the autoload) isn't reachable from the test runner, don't test `start_new_game` / `restart` directly.
  Keep their logic trivial, and verify by hand that the scene reload works (say so in notes_for_qa).

## Acceptance criteria

- Launching the game (no scenario) shows the main menu over a dimmed, paused map. New Game starts an unpaused game on
  a new seed. Quit exits.
- Game Over and Victory show Restart (same seed, game running) and Main Menu (back to the menu).
- `test_restart.gd` passes: 3 create/teardown cycles free cleanly.
- `main_menu` screenshot at 1280x720: title, tagline and both buttons readable over the dimmed map. **All other
  scenario screenshots are unchanged** (no menu).
- All tests pass with no SCRIPT ERROR. Import, smoke and screenshots are clean.

## Pitfalls

- `reload_current_scene()` frees `main.tscn` at the end of the frame, while the `Game` autoload survives. Anything
  connected to the old `state`'s signals from autoloads must not keep the old state alive (Events.game_started
  listeners included).
- `clock.locked` also blocks `set_paused(false)`. Since New Game reloads the scene, you never need to unlock it.
- Don't route Esc to anything here. T-085 adds the pause menu on Esc.
- Keep the menu's dim and panel from blocking the DevTools screenshot: it's a CanvasLayer, so it just draws.
