# T-112: Animated title background: live scripted siege scene

Milestone: M6 | Type: code | Owner: gemini | Scenario: `main_menu`

## Goal

The main menu still shows the v1 Kenney title art (`game/assets/ui/title_art.png`, node `MainMenu/TitleArt` in
`game/scenes/ui/main_menu.tscn`), which clashes with the M6 pixel art (see `project/runs/T-111/a1/qa_main_menu.png`).
Replace it with a small live pixel-art scene behind the menu panel: a walled pixel base at dusk, a guard on a
watchtower firing, and a few zombies shambling in and dying, looping forever. GDD §16 "Menus".

## Design

- New `game/scenes/ui/title_scene.tscn` + `game/scripts/ui/title_scene.gd` (a `SubViewportContainer` or a `Node2D`
  under its own `CanvasLayer` with a lower `layer` than the menu). It replaces the `TitleArt` node inside MainMenu.
- **Never touch the real game state.** Do not read or tick `Game.state`. Build the scene from view pieces only:
  the T-103 terrain tiles, T-104 building sprites (Command Center, a short wooden wall line, a watchtower), the T-105
  survivor `SpriteFrames` for one guard and two idle survivors, the T-106 zombie `SpriteFrames` (walkers plus one
  runner), the T-140 `CombatFx`-style muzzle flash and blood (reuse its textures/strips, not its GameState hooks).
- Scripted loop (about 12–16 s): zombies walk in from the right edge on fixed paths, the guard turns and fires every
  ~0.8 s, a zombie plays hurt then death, its corpse fades, and the loop restarts. Use a fixed seed so every run and
  every screenshot looks the same. Lighting: day colours with a warm dusk `CanvasModulate` (no night tint, the
  buttons must stay readable). Pixel rules from ART_GUIDE: 4x scale, nearest filtering, integer positions.
- Keep the `Dim` overlay but lower its alpha so the scene shows through while the cream text still reads.
- Delete `TitleArt` and its ext_resource from `main_menu.tscn`. Keep `title_art.png` on disk only if
  `project/tools/compose_title.py` or the export icon still uses it (check with grep); otherwise leave it, don't delete
  assets in this task.
- Cheap: at most ~20 animated sprites, no per-frame allocations, `process_mode` so it stops when the menu hides.
- When New Game/Continue starts a game the menu scene reloads (`Game._transition`); make sure the title scene frees
  with it (no orphan tweens/timers). The `main_menu` screenshot scenario must show the scene mid-action at frame 120.

## Acceptance criteria

- `main_menu` capture at 1280x720: pixel siege scene (base, guard, zombies, a muzzle flash or blood visible) behind
  readable menu buttons; no Kenney title art left.
- Two captures 120 frames apart differ (it is animated); the same frame number on two runs is identical (seeded).
- Starting a new game frees the title scene: smoke shows no leak lines, `qa_m4_menu_flow.gd` and
  `qa_t025_menu_flow.gd` pass (use `--no-fade` as earlier tasks did).
- A test instantiates `title_scene.tscn` off-tree and checks it builds its sprites without touching `Game.state`.
- All tests, import, smoke and screenshot clean.

## Pitfalls

- `main_menu.gd` is edited by T-135 (MenuStyle.apply tidy) before this task; rebase on it, don't revert it.
- Do not change `Game`, `GameState` or any sim code. Do not change the menu buttons or their node paths (M7 adds a
  Continue button there next).
- Godot 4.7: `SubViewport` needs `canvas_item_default_texture_filter = nearest` if you use one, or the pixels blur.
