# T-104: Pixel art swap 2: buildings, walls, fences and gates

Milestone: M6 | Type: code | Owner: gemini | Scenario: `buildings_pixel`

## Goal

Owner request R-5, step 3, second swap. Every building switches from the Kenney sprites to the Ittai Manero pixel
sprites in `game/assets/pixel/buildings/`, drawn at 4× with Nearest filtering, bottom-anchored and y-sorted with the
props. Walls join up with their neighbours (corners, T-pieces, crosses). **View code and data sprite names only. The
sim, footprints and placement rules don't change.**

  pattern used on props: native PNG, `scale = Vector2(4, 4)`, bottom anchor through `offset`, `y_sort_enabled` parent.
- Renderer: `game/scripts/world/building_sprites.gd` (`make`, `texture_for`, `update_aim`, `update_hp_bar`,
  `update_progress`). Nodes are created and replaced in `game/scripts/world/world_view.gd`

  Build bar icons: `game/scripts/ui/build_bar.gd` (~line 79). Data: `game/data/buildings.json` (`sprite`, `sprite_top`).
- Upgrading a wooden wall to reinforced removes the old building and adds a new one (`GameState.try_upgrade`), so the
  added/removed signals cover it.
- New art (native px, all in `game/assets/pixel/buildings/`; rows in `game/assets/ASSET_INDEX.md`):

  | Building | File(s) | Native size | Footprint |
  |---|---|---|---|
  | command_center | `command_center.png` | 32×48 | 2×2 (bottom 32 px) |
  | shelter, farm, lumber_yard | `<id>.png` | 32×32 | 2×2 |
  | storage, workshop | `<id>.png` | 32×48 | 2×2 |
  | radio_tower | `radio_tower.png` | 32×48 | 2×2 |
  | watchtower | `watchtower.png` | 16×32 | 1×1 |
  | turret | `turret_base.png` + `turret_barrel_{up,down,left,right}.png` | 16×16 each | 1×1 |
  | gate | `gate_closed.png` (`gate_open.png` unused for now) | 16×16 | 1×1 |
  | wooden_wall | `fence_<suffix>.png` | 16×16 | 1×1 |
  | reinforced_wall | `wall_earth_<suffix>.png` | 16×16 | 1×1 |
  | blueprints | `construction_1x1.png`, `construction_2x2.png` | 16×16, 32×32 | 1×1, 2×2 |

  Wall suffixes, by which of the four neighbours connect: none → `post`; one → `end_n`/`end_e`/`end_s`/`end_w` (the
  end piece named after the side that connects); N+S → `v`; E+W → `h`; N+E → `corner_ne`, N+W → `corner_nw`,
  S+E → `corner_se`, S+W → `corner_sw`; three → `tee_nes`, `tee_esw`, `tee_nsw`, `tee_new` (letters = connected sides);
  four → `cross`. Open the PNGs on a 4× contact sheet once to confirm the naming before you rely on it.

## Acceptance criteria

- `buildings_pixel`, `buildings_placed` and `construction` screenshots show every building type in the pack style at a
  crisp 4× (no blur, no squashing), sitting on its footprint with roofs rising above it.
- Wall rings join visually: corners, straight runs and the T-junction use the matching fence/earth pieces; the gate
  and reinforced segment sit in the ring without gaps.
- Y-sort: a prop directly south of a building draws over it; nothing draws a building over a prop that is in front.
- Turret barrel faces its target through four direction sprites, never rotated. Blueprints show the scaffold + progress.
- Ghost preview and build bar icons use the new sprites with correct proportions.
- All tests pass (new tests above included); import, smoke and screenshots clean (no `ERROR:` lines).

## Pitfalls

- `Sprite2D.offset` is in unscaled texture pixels; negative y moves the texture up.
- Don't move the building node's origin away from `b.center_world()`: selection, HP bars, zombie targeting tests and
  floating text assume it. Anchor through the child sprite.
- In Godot 4, a y-sorted child of a y-sorted parent sorts its own children together with the parent's. That is what
  merges Props and Buildings into one order. A non-y-sorted building node draws all its children at its own y.
- Re-texturing neighbours on add/remove must look up by tile through the sim (`state.map.building_at` / the building
  store), not by scanning every node each frame.
- The scaffold and blueprint tint must not leak into the completed node: `_on_building_completed` already rebuilds it.
- Night tint multiplies everything. Check the `night` scenario still reads; tuning it is T-099.
