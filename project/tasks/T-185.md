# T-185: Polish: scavenging morning hint waits until a survivor can actually be sent

Milestone: M8 | Type: code | Owner: gemini | Scenario: `default` | skip QA

Found by T-170 QA (`project/runs/T-170/a1/bugs.json`,
`scavenge_hint_all_guards.png`). In `game/scripts/sim/tutorial_hints.gd`,
`check()` returns `scavenge` and sets `shown["scavenge"]` on any day ≥ 2
morning, even when every survivor is a Guard (or otherwise ineligible), so
the one-shot hint is spent while every Scavenge button is disabled. This
absorbs T-184 (same bug filed as QA BUG).

## Scope fence

Touch only `game/scripts/sim/tutorial_hints.gd`,
`game/tests/test_scavenge_hint_timing.gd` (check actual file name first;
T-176 created the timing test) and `project/assumptions.md`. No data, UI
or save-field changes.

## Do

1. In the `scavenge` branch of `TutorialHints.check()`, only fire (and only
   mark `shown["scavenge"]`) when at least one survivor in
   `state.survivors.all()` has `state.expeditions.can_send(s) == ""`.
   Leave the day ≥ 2 / DAY phase / morning-cutoff conditions and the hint
   text exactly as they are.
2. Add regression tests in the timing test file:
   - Day 2 morning with every survivor on Guard: `check()` does not return
     `scavenge` and `shown` has no `scavenge` key.
   - Same state after one survivor is set back to Idle (eligible):
     `check()` returns `scavenge` once, then never again.

## Acceptance criteria

- Day 2 morning all-Guard: no `scavenge`, `shown` unmarked.
- After one survivor becomes eligible: `scavenge` once, then never again.
- Existing hint-timing tests (`test_scavenge_hint_timing`,
  `test_tutorial_hints`) still pass; all tests pass, smoke clean.

## Pitfalls

- `can_send` needs the expeditions state; call it read-only, don't send.
- Sheltered survivors at night never reach this branch (phase gate); the
  Guard case is the regression that matters.
- Keep LF line endings.
