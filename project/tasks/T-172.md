# T-172: Chore: per-process unique user:// temp paths in tests

Milestone: M7 | Type: code | Owner: gemini (Codex stands in) | Scenario: `default` | skip_qa

## Goal

Two lanes run the full suite in parallel from separate checkouts but share one
`user://` directory, so tests that use fixed temp file names flake when they
overwrite or delete each other's files. Make every test temp path unique per
process. Test-only change.

## Context

During T-157 a1 the full suite failed once in
`test_game_save_service.gd:test_save_day_extra_and_restore_data_with_injected_path`
(expected day 3, got 5, then `FileAccess.open` returned null). It passed in
isolation and on retry. Suspects with fixed `user://` names:
`test_game_save_service.gd` (TEMP), `test_game_settings.gd` (TEMP),
`test_pause_menu.gd`, `test_tutorial_hints.gd`, `test_tutorial_hints_qa.gd`,
`test_automated_save_isolation_qa.gd`, `test_game_data.gd`
(`user://test_data`). Audit the whole `game/tests/` tree; the list above may
not be complete.

## Do

1. Add one shared helper in the test base (or a tiny `test_temp_path.gd` helper)
   returning e.g. `"user://test_<name>_%d.<ext>" % OS.get_process_id()`, and
   switch every fixed `user://` file or directory name in tests to it.
2. Every temp file or directory a test creates is removed by the end of that
   test (`after_each` or equivalent).
3. Don't edit game scripts, scenes, data or assertions. Test files only.

## Acceptance criteria

- No test under `game/tests/` uses a fixed `user://` file or directory name;
  all of them include the process id.
- Every temp file or directory a test creates is removed by the end of that test.
- Two full test suites run at the same time from separate checkouts both
  report 0 failed.
- All tests, import and smoke clean.

## Pitfalls

- Keep the helper name stable so future tests reuse it instead of inventing
  new fixed names.
- The concurrent-run check is manual (two checkouts at once); report both
  TESTS lines in work.json.
