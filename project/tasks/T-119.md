# T-119: Chore: fix the shutdown leak ('resources still in use at exit'); absorbs T-125, T-126, T-127

Milestone: M6 | Type: code | Owner: gemini | Scenario: `default`

## Goal

Smoke runs keep ending with leaked objects. Three QA/review passes filed the same bug separately (T-125 from QA T-105,
T-126 from review T-105, T-127 from QA T-116); they are merged here. Make the 300-frame smoke shut down cleanly every
time, with and without an FPS cap.

## What we know

- Reproduce: `godot_console --headless --path game --verbose -- --quit-frames=300` (see ARCHITECTURE.md for the
  exact console binary). It exits 0 but prints four leaked audio objects (`AudioStreamPlaybackOggVorbis`,
  `OggPacketSequencePlayback`, `OggPacketSequence`, `AudioStreamOggVorbis`) and **2 resources still in use** for
  `res://assets/music/day_loop.ogg`.
- With `--max-fps 60` the shutdown is clean. So it's timing: an uncapped run reaches frame 300 (and quits) very soon
  after the day music starts.
- Logs: `project/runs/T-105/a2/qa_smoke_retest.log`, `qa_smoke_repeat_1..3.log`, `qa_smoke_capped.log`;
  `project/runs/T-116/a1/qa_smoke.log`, `qa_smoke_verbose.log`. Earlier, intermittent leaks also showed up on first
  smoke runs (T-102, T-103, T-108, T-118 QA). Most recent: T-130 a1 (`project/runs/T-130/a1/smoke.log` and
  `smoke_retry.log` leak 4 objects / 2 resources; `smoke_final.log` from the same run is clean).
- Owner: `game/scripts/audio/audio_manager.gd` (`AudioManager`). Music uses two `AudioStreamPlayer`s
  (`_music_player_a/_b`), a crossfade `_music_tween`, `active_music_stream` (a member holding the stream) and a
  `_streams` dictionary cache. `_release_audio()` runs on `_exit_tree` and `NOTIFICATION_PREDELETE`. T-097 already
  added AudioServer lock/unlock there.

## Do

1. Reproduce first: run the uncapped verbose smoke 5 times, save logs to `project/runs/T-119/a#/before_#.log`.
2. Find who still holds the playback/stream at exit. Likely suspects, in order:
   - `_release_audio()` stops the players but `active_music_stream` and `_streams` still reference the streams;
     clear them (`active_music_stream = null`, `_streams.clear()`) and set every player's `stream = null`.
   - `_music_tween` still running at exit and capturing the player: `kill()` it before stopping players.
   - the AudioServer mix thread still holds the `AudioStreamPlayback` when the node frees: stop the player, then
     wait one frame is impossible at exit, so make quit go through a path that stops audio first, e.g. in the
     DevTools `--quit-frames` handler (`game/scripts/autoload/dev_tools.gd`) call a `release` on the audio manager
     before `get_tree().quit()`, and handle `NOTIFICATION_WM_CLOSE_REQUEST` the same way for real quits.
   - any `static var` holding resources: `game/scripts/world/building_sprites.gd:5` has
     `static var _barrel_textures: Dictionary` (turret barrel textures). Static caches outlive the tree; replace it
     with a per-instance cache or plain `load()` calls (Godot caches resources itself), or clear it on exit.
   Fix the cause in the owning script. **Don't silence the message**, don't disable audio in headless runs to hide it.
3. Verify: 20 consecutive uncapped verbose smoke runs **and** 5 capped (`--max-fps 60`) with no `leaked`,
   `still in use at exit` or `ObjectDB instances` lines. Commit the loop script as `project/tools/smoke_loop.sh`
   (or `.py`), save the logs in the run folder.
4. Regression test (`game/tests/test_audio_teardown.gd` or extend the existing audio tests): after `unbind()` /
   `_release_audio()`, every music and SFX player has `stream == null` and is not playing, `active_music_stream` is
   null, the stream cache is empty and the tween is invalid or killed.

## Acceptance criteria

- 20 consecutive uncapped verbose 300-frame smoke runs show no leaked-instance or "still in use at exit" lines; the
  loop script and logs are in the run folder.
- `work.json` names the leaked resources and the actual cause.
- Regression test covers the teardown state.
- Music still plays and crossfades day/night in a windowed run (say how you checked in `notes_for_qa`).
- All tests pass; import, smoke and screenshot clean.

## Pitfalls

- `AudioStreamPlayer.stop()` doesn't drop the stream; `stream = null` does.
- Clearing `_streams` while a later scene still needs it is fine: `_get_stream` reloads lazily.
- The autoload `Game` reloads the scene on New Game / Restart: teardown must also be clean on scene reload, not just
  at quit (run `qa_m4_menu_flow` once with `--verbose` and check its exit).
