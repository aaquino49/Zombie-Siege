# T-130: ART: numeral-distinct pixel font (5, 8 and S must never look alike)

Milestone: M6 | Type: asset | Owner: codex | Scenario: `font_check`

## Goal

Owner request **R-8** (high priority). After T-122 the UI font (Pixelify Sans, `game/assets/pixel/ui/font/pixelify_sans.ttf`)
renders crisply, but its digits are ambiguous. In `project/runs/T-122/a3/qa_qa_pixel_theme.png` and
`project/runs/T-120/a2/screenshot_work.png`:
- 'HP 80/80' reads 'HP S0/S0' (the 8 looks like S);
- scrap 15 reads '1S' and wood 500 reads 'S00' (the 5 looks like S).

Numbers are the most important text in this game (resources, HP, costs, timer, day). Produce a font file whose
digits are unmistakable at every UI size, **without changing the font's pixel grid**, so T-122's crisp-size rules
(`UiFont`: multiples of 11) and layouts keep working.

## Approach (decided by the quarterback; log any deviation in `project/assumptions.md`)

Redraw the digit glyphs of Pixelify Sans on its own 11-pixels-per-em grid. Pixelify Sans is OFL 1.1 with **no Reserved
Font Name** in its copyright line, so modification is allowed. Still give the modified font its own name so it isn't
confused with upstream.

1. **Make a static instance first.** The TTF is a variable font (wght axis). Editing contours in a variable font breaks
   `gvar`. Use `fontTools.varLib.instancer` to pin `wght=400` (the current default instance) and work on that static
   font.
2. **Grid:** unitsPerEm 1000, one font pixel ≈ 90.9 units. Existing outline x positions sit at about 50, 141, 232, 323,
   413, 515, 606, 706... Measure the real grid origin and baseline/cap-height from the existing digits and 'S' with
   fontTools before drawing. Every new point must be on that grid (round to the nearest grid line; at 22 px a
   grid pixel is exactly 2×2 screen pixels).
3. **Redraw 0–9** as rectangles-of-pixels contours (one closed contour per pixel run is fine; merge if you can) with
   these rules:
   - **5:** flat top bar and a hard square top-left corner, with a vertical stroke down the left to the middle bar,
     then the bowl. It must not share S's rounded top.
   - **8:** two clearly stacked closed counters with a solid middle crossbar (a visible "waist"); no open gaps.
   - **S** (and 's') stay as they are: the difference comes from the digits.
   - **0:** taller-than-wide with a closed counter; a dot or slash inside is fine if it fits at 11 px. **0 vs O**
     should differ (narrower 0, or the inner mark).
   - **1:** flag at the top and a foot bar, so it doesn't read as 'l' or 'I'.
   - **3 vs 8, 6 vs 8, 9 vs 8:** 3 is open on the left, 6 open at top-right, 9 open at bottom-left.
   - **Tabular:** all ten digits share one advance width (so HUD counts don't jitter as they change). Also set the
     same advance for ':' and '/' only if it doesn't break their look; otherwise leave them.
   - Keep the digits' height equal to the current cap height and their baseline unchanged.
4. **Rename:** family "Siege Pixel", full name "Siege Pixel Regular", PostScript name `SiegePixel-Regular`. Keep the
   original copyright line, add "Digits modified 2026 for Zombie Siege", keep the OFL licence text (name ID 13/14).
   Save as `game/assets/pixel/ui/font/siege_pixel.ttf`. Copy the OFL text to `game/assets/pixel/ui/font/OFL.txt`
   (already there, add a line naming the modified font) and add an entry to `CREDITS.md` and `game/assets/ASSET_INDEX.md`.
5. **Godot import file:** create `siege_pixel.ttf.import` with the same settings as `pixelify_sans.ttf.import`
   (antialiasing 0, hinting 0, subpixel_positioning 0, oversampling 1, no MSDF). Run the headless import from
   ARCHITECTURE.md so the `.godot` cache is valid. **Don't wire it into the theme**; T-131 does that.
6. **Generator script:** keep the whole process in one reproducible script, `project/tools/make_siege_pixel_font.py`
   (fontTools + PIL), that reads `pixelify_sans.ttf` and writes `siege_pixel.ttf` and the sheets below.
7. **Comparison sheet:** `project/runs/T-130/a#/digits_sheet.png` rendered from the TTF files with PIL at 1× (no
   resampling, antialias off, e.g. `ImageFont.truetype(..., size)` then threshold the alpha at 50%, or
   `fontmode = "1"`) at sizes **11, 22, 33 and 44**, showing for BOTH the old and the new font:
   `0123456789 S s O o l I`, `HP 80/80  15  500  58 85 S8 5S`, `Nightfall in 1:05  Day 18  -8 +5`.
   Add an enlarged (nearest ×4) crop of the 11 px row so the glyph pixels can be inspected.

## Acceptance criteria

- `siege_pixel.ttf` exists, is a static (non-variable) TTF named "Siege Pixel", with every digit's outline points on
  the 11-per-em grid (the script asserts this) and all ten digits sharing one advance width.
- In `digits_sheet.png`, at every size, 5 and 8 are clearly different from S, 0 from O, 1 from l/I; the old row next
  to it shows the improvement.
- Letters and punctuation other than the digits are unchanged (the script compares every non-digit glyph's outline
  with the source instance and reports zero differences).
- OFL text, CREDITS.md and ASSET_INDEX.md updated; the `.import` file has the crisp settings; headless import clean.
- No game code or theme change in this task. All tests pass; import and smoke clean.

## Pitfalls

- Don't edit the variable font directly (gvar point counts). Instance first.
- Don't scale or re-grid the whole font; only the digit glyphs change. The theme sizes (multiples of 11) depend on it.
- Contours: TrueType wants outer contours clockwise and counters counter-clockwise (or merge overlapping squares
  with `pathops`/`skia-pathops` if available). Overlapping same-direction squares can render holes in some
  rasterizers; check the PIL sheet *and* a Godot render if you can.
- Keep `hmtx` left side bearings consistent with the new outlines (`glyf[...].recalcBounds`, then update `hmtx`).
