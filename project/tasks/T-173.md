# T-173: Restart preserves the active run difficulty after Continue

Milestone: M7 | Type: code | Owner: gemini | Scenario: `pause_menu`

## Goal

After Continuing a save, Restart (from the pause menu, Game Over or Victory screen) must start a fresh run on the
*active run's* difficulty, not on the remembered New Game difficulty.

## Context

Review probe on T-148 (`project/runs/T-148/a2/review_restart_probe.log`): with Easy remembered and a Hard save
continued, Continue correctly restores Hard, but Restart flips the run to Easy. Root cause is in
`game/scripts/autoload/game.gd`: `restart()` calls `_transition(false)` without carrying anything, and after the
scene reload `new_game()` resolves an empty difficulty via `_pending_new_difficulty` (already consumed at game
start) and falls back to `GameSettings.load_difficulty()` (the remembered New Game choice). All three Restart
buttons (`pause_menu.gd:85`, `game_over_screen.gd:39`, `victory_screen.gd:39`) go through `Game.restart()`, so one
fix covers all entry points.

## Do

- In `game.gd`, capture `state.difficulty` before the restart scene reload (autoload members survive
  `reload_current_scene`) and prefer it in `new_game()`'s difficulty resolution when restarting. Keep the
  remembered New Game choice untouched: never call `GameSettings.save_difficulty()` on this path.
- Keep the map seed behaviour as is (Restart reuses the seed).
- Extend live-flow coverage for mismatched saved vs remembered difficulties (Easy remembered + Hard save, and the
  reverse), exercising the pause-menu and both terminal Restart buttons.

## Acceptance criteria

- With Easy remembered and a Hard save continued, Restart from pause, Game Over and Victory starts a fresh Hard run
  and preserves the map seed.
- Restart does not overwrite the remembered New Game difficulty; reopening the picker still focuses Easy.
- Pause and end screens reflect the retained run difficulty; both menu-flow scripts, unit tests, import, smoke and
  capture pass.

## Pitfalls

- `_pending_new_difficulty` is consumed (cleared) by `new_game()` and `_pending_continue` is consumed by Continue,
  so neither survives to a later Restart; use a separate field or set the pending value from `state.difficulty`
  inside `restart()`.
- Do not "fix" this by writing the active difficulty into settings: the picker must still open on the remembered
  choice afterwards.
- Small task: touch only `game.gd` and its tests. No balance, wave or save-format changes.
