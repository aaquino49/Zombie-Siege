# T-009: Game clock: day timer, pause, speed

Milestone: M1 | Type: code | Owner: gemini | Scenario: `clock`
Depends on: T-006 (ResourceStore + HUD), T-038 (typed `hud.gd`). Placement (T-008) reads `clock.day` for unlocks.

## Goal

A day/night clock in the sim drives the run. Space pauses, and 1/2/3 set the game speed. The top bar shows the day, the time until nightfall, and the current speed. For M1 the night just ends when its timer runs out (zombies come in M3).

Decided earlier (decisions.md): pause/speed is a **multiplier inside the sim**, not `Engine.time_scale` or `SceneTree.paused`, so the camera and UI keep working while paused.

## Files to create / change

1. `game/data/balance.json`: add `"speed_mult_1": 1.0, "speed_mult_2": 2.0, "speed_mult_3": 3.0`. `day_length` (150) and `night_min_length` (45) already exist. Don't add these keys to GameData's required-key validation.
2. `game/scripts/sim/game_clock.gd`: `class_name GameClock extends RefCounted`.
   - `enum Phase { DAY, NIGHT }`
   - `signal phase_changed(phase: int, day: int)`, `signal dawn(day: int)` (a new day started), `signal speed_changed(paused: bool, speed: int)`.
   - `var day: int = 1`, `var phase: int = Phase.DAY`, `var elapsed: float` (sim seconds into the current phase), `var paused: bool = false`, `var speed: int = 1` (1, 2 or 3).
   - `func _init(data: GameData)`: reads `day_length`, `night_min_length`, `speed_mult_*` (fall back to 150/45/1-2-3 if `data` is null, so tests can pass null).
   - `func scale(real_delta: float) -> float`: returns 0 when paused, otherwise `real_delta * speed multiplier`.
   - `func advance(sim_delta: float) -> void`: adds sim time and handles **multiple transitions in one call** (e.g. `advance(400)` from day 1 start goes DAY→NIGHT→DAY(2)→NIGHT; carry the leftover time). DAY ends after `day_length`, giving NIGHT on the same day number. NIGHT ends after `night_min_length`, giving DAY with `day += 1` and emitting `dawn(day)`. Emit `phase_changed` on every transition.
   - `func time_left() -> float`: seconds left in the current phase.
   - `func set_speed(n: int)`: clamps to 1..3, unpauses, emits `speed_changed`. `func toggle_pause()` / `func set_paused(p: bool)`: emit `speed_changed` only when the value changes.
   - Keep the night-end check in one function, `_night_can_end() -> bool` (for now: `elapsed >= night_min_length`). M3 will add "and the wave is cleared".
3. `game/scripts/sim/game_state.gd`: `var clock: GameClock`, created in `_init`. `tick(delta)` becomes `var sim_dt: float = clock.scale(delta)`, then `clock.advance(sim_dt)` (later systems will tick with `sim_dt`).
4. `game/scripts/ui/hud.gd` + `game/scenes/ui/hud.tscn`, in the existing `ClockArea`:
   - `TimeLabel`: during DAY "Nightfall in m:ss" (e.g. `Nightfall in 2:30`). During NIGHT "Night – m:ss" (M3 will change it to the zombie count). Same `LabelSettings` as the resource labels.
   - Four buttons: Pause (`icon_pause.png`), 1x (`icon_play.png`), 2x and 3x (`icon_fast.png` with text "2x"/"3x"). Use toggle buttons in one `ButtonGroup` so exactly one shows as pressed (Pause while paused, otherwise the active speed). Clicking calls `clock.set_paused(true)` / `clock.set_speed(n)`.
   - `DayLabel` shows `"Day %d" % clock.day` and is updated from `dawn`, not hard-coded "Day 1".
   - `TimeLabel` may update in `_process` (the clock changes continuously), but only set `.text` when the displayed whole second changes. Button state updates from `speed_changed` only.
   - Keyboard: `_unhandled_input` handles `pause` (toggle), `speed_1/2/3` (`set_speed`). The actions already exist in project.godot.
5. `game/dev/scenarios/clock.gd`: `Game.state.clock.advance(150.0 + 45.0 + 50.0)` puts it at Day 2 with 100 s to nightfall, then `set_paused(true)`. The screenshot must read **"Day 2"**, **"Nightfall in 1:40"**, Pause highlighted. Being paused keeps it deterministic across the 120 capture frames.
6. `game/tests/test_game_clock.gd`:
   - starts at Day 1, DAY, `time_left()` = day_length
   - `advance(day_length)` → NIGHT, still day 1, `phase_changed` emitted once
   - night ends after night_min_length → DAY, day 2, `dawn(2)` emitted
   - one big `advance` crosses several phases and lands on the right day/phase/elapsed
   - `scale`: paused → 0. Speed 2 → 2x, speed 3 → 3x. `set_speed(5)` clamps to 3. `set_speed` unpauses.
   - `speed_changed` not emitted on a no-op `set_paused`
   - `GameState.tick(1.0)` at speed 3 advances the clock by 3 s. While paused it doesn't move.

## Acceptance criteria

- `test_game_clock.gd` covers phase transitions, the day increment at dawn, multi-phase advance, speed scaling, clamping and pause. All tests pass.
- `clock` screenshot shows the top bar with resources, "Day 2", "Nightfall in 1:40" and four speed buttons with Pause pressed. The map is visible below.
- Space toggles pause and 1/2/3 change speed in the real game, and the camera still pans while paused.
- No timing numbers hard-coded in scripts (balance.json via GameData, with the null-data fallback only in GameClock).
- Smoke and existing tests pass (`hud` scenario still shows food 123 / wood 60 / scrap 0 / ammo 40).

## Pitfalls

- Don't use `Engine.time_scale`, `get_tree().paused` or a `Timer` node. The sim must be steppable headlessly by tests and the M4 balance bot.
- `Game._process` already calls `state.tick(delta)`. Don't add a second ticker.
- Format with `"%d:%02d" % [mins, secs]` using `ceili(time_left())` so 150 s shows 2:30, not 2:29 at start.
- The HUD buttons sit on the top bar, which already has `MOUSE_FILTER_STOP`. Buttons need `focus_mode = FOCUS_NONE`, so Space doesn't also "click" a focused button and double-toggle.
- Keep `hud.gd` under ~400 lines and statically typed (T-038 typed it, so keep it that way).
