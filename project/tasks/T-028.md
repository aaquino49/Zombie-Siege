# T-028: M4 QA: full-run playthrough

Milestone: M4 | Type: qa | Owner: codex | Scenario: `default`
Depends on: T-027 (balance pass 1), T-024 (NightLog), T-087 (Dawn Report panel), T-086 (no Game Over on a won game),
T-025 (menus), T-084 (rescue helicopter), T-085 (pause menu). T-093 (night cap), T-030 (audio) and T-092 (title art)
are also done, so this checks the build we will ship.

## Goal

Prove M4 (Full game) is done: *20 nights with wave scaling, the Radio Tower, a real win and a real loss, the main
menu → game → Game Over/Victory → menu loop, the pause menu, and a Dawn Report every dawn, balanced by the bot*
(GDD §§3, 9, 10, 11, 14). Add one headless full-run regression test file, capture the flows as screenshots, and
report bugs. **Don't fix game code.** Report bugs instead.

## What to check

1. **Balance bot on current data.** Run
   `godot --headless --path game --script res://dev/balance_run.gd -- --seeds=1337,1,2,3,4 --nights=20 --strategy=both`.
   Expected (decisions.md "Balance pass 1"): sensible won on 1337, 3 and 4, survived on 2, lost_survivors on 1;
   none lost_cc on night 4 on every seed. Paste the BALANCE/BALANCE_SUMMARY lines in `qa.json`. A different result
   on the same data is a determinism bug. Report it.
2. **Real win path.** Radio Tower complete + night 20 survived → at the next dawn the helicopter flies in, then the
   Victory screen shows the stats. The Game Over screen never appears on a won game (T-086). Victory's buttons work.
3. **Real loss paths.** CC destroyed (`reason "command_center"`) and 0 survivors (`"survivors"`). Game Over shows
   nights survived, zombies killed, survivors lost, buildings built and time played. Restart starts a fresh day 1.
   Main Menu returns to the menu. The clock stays locked while the screen is up.
4. **Menu flow.** Launch → main menu over the title art → New Game → day 1 (camera on the CC, HUD correct) → Esc
   pause menu (Resume / Restart / Quit to Menu, volume sliders persist across restarts) → Quit to Menu → New Game
   again starts clean (no leftover zombies, buildings, popups, banners or audio from the last game).
5. **Dawn Report** after every night, including night 1 and night 20. Numbers match NightLog (kills, survivors
   lost, buildings destroyed, food eaten, newcomers). It closes cleanly and the day resumes.
6. **Night cap and wave scaling.** Walkers 4+3n, runners max(0, 2(n−3)), brutes max(0, n−10), 1/2/3/4 sides by band,
   night 20 doubled with the red tint and Final Horde banner. No night runs past 300 s. Leftover zombies retreat
   and aren't counted as kills.
7. **Audio sanity (headless-safe only).** No `ERROR:` or `SCRIPT ERROR` from AudioManager during any flow above.
   T-097 already covers the known "resources still in use at exit" lines from the smoke run. Don't re-report those.

## Deliverables

### `game/tests/test_full_run_qa.gd` (new)

Use `GameState.new(GameData.load_default(), seed)` with `state.waves.enabled = true` and the `BalanceBot` the way
`dev/balance_run.gd` drives it, stepping with `state.tick(...)`. Cap every loop by tick count and fail with a clear
message rather than hanging. Keep the whole file under ~60 s of wall time. If a full 20-night run is too slow,
run it once and share the result across asserts, or test the win on a state jumped to day 19 the way
`dev/scenarios/victory_setup.gd` does.

- **`test_sensible_bot_wins_seed_1337`:** the sensible bot on seed 1337 reaches `game_won`. `game_lost` never fires.
  The Radio Tower is complete. Night count is 20.
- **`test_do_nothing_loses_early`:** the `none` strategy on seed 1337 loses with reason `"command_center"` on a night
  from 3 to 6. `game_lost` fires exactly once, and `game_won` never fires.
- **`test_dawn_report_every_night`:** count `dawn_processed` emissions over the sensible run (or a 5-night slice).
  One per night survived, each with the NightLog keys the Dawn Report panel reads.
- **`test_night_never_exceeds_cap`:** over the run, no night's length exceeds `night_max_length` (+1 tick).
- **`test_full_run_deterministic`:** two 5-night sensible runs on the same seed give identical kills, survivors,
  buildings and resources at dawn 5.

If an existing test already covers one of these with a full `state.tick` loop, skip it and name that test in
`qa.json`.

### Scenarios (`game/dev/scenarios/qa_m4_*.gd`, at least 4, with screenshots in `qa.json`)

Suggested: `qa_m4_final_horde` (night 20 with the red tint and banner, all four sides), `qa_m4_victory` (Victory
screen reached through the real rescue path, not a forced screen), `qa_m4_game_over_survivors` (loss by 0
survivors), `qa_m4_dawn_report_late` (a night 15+ Dawn Report with real losses), `qa_m4_pause_over_night` (pause
menu open during a night). Look at every PNG you produce before you list it.

### Reports

- `bugs.json` in the run folder (may be empty). Each bug has a title, the steps or test that reproduce it, and a
  severity. Only report bugs that break gameplay, crash, or make a v1 feature unusable as `major`/`blocker`.
  Cosmetic issues are `minor` (they go to post-v1 polish).
- **Balance and feel observations go in `qa.json`, not bugs.** Examples: how long a full game takes at 1x (target
  30–40 min), when the first runner and brute nights feel unfair, and whether the do-nothing loss on night 4 feels
  right.

## Acceptance criteria

- `game/tests/test_full_run_qa.gd` added with the tests above (or named existing coverage), all passing.
- At least 4 `qa_m4_*` scenarios with screenshots, including a real Victory path and a real Game Over path.
- Balance bot output for the 5 seeds in `qa.json`.
- `bugs.json` written (may be empty).
- All tests pass with no SCRIPT ERROR. Smoke passes and import is clean.

## Pitfalls

- Don't edit `game/data/*.json`, `game/dev/balance_bot.gd`, `dev_tools.gd`, `run_tests.gd` or `test_case.gd`.
- Known, already-filed issues aren't new bugs: T-089 (Dawn Report title contrast), T-090 (B/R hotkeys behind the
  pause menu), T-094 (walled-off survivor has no shelter), T-095 (bot limits), T-096 (CC never damaged late),
  T-097 (audio exit leak).
- Expected `ERROR:` lines from deliberate negative unit tests aren't bugs (ARCHITECTURE.md).
- Find build spots with `Placement.check(...)` scans, never hard-coded tiles. Map layouts depend on the seed.
- In the unit-test run, nodes aren't in the tree. Test the sim (`GameState`), not the screens. Use scenarios for
  the screens.
