# T-015: Selection, info panel, survivor roster + job assignment UI

Milestone: M2 | Type: code | Owner: gemini | Scenario: `ui_roster`
Depends on: T-012 (`set_job`, `cancel_building`, `Survivor.Activity`, `job_label`/`activity_label`) and T-013 (`gather_kind`, `set_job(uid, job, kind)`, carry fields). Read `game/tests/README.md` "Testing scenes and Node scripts" before writing any test.

## Goal

The player can see and control the colony:
- Click a survivor or building to select it. A ring or outline marks the selection.
- An info panel shows what the selection is doing. Survivors get a job dropdown. Blueprints get a Cancel button.
- **R** toggles a roster listing every survivor with a job dropdown.
- Changing a job in either place changes the sim at once.

Night behaviour (going to shelter) is **not** part of this task. It's T-056.

## Files

### Shared helper
1. `game/scripts/ui/job_options.gd`: `class_name JobOptions extends RefCounted`.
   - `const LABELS: Array[String] = ["Idle", "Gatherer: Wood", "Gatherer: Scrap", "Farmer", "Builder", "Crafter", "Guard"]`
   - `static func index_for(s: Survivor) -> int`: the GATHERER job maps to index 1 or 2 by `gather_kind`.
   - `static func apply(state: GameState, uid: int, index: int) -> bool`: calls `state.set_job(...)` with the matching job and kind. Returns false for an out-of-range index.
   - `static func fill(btn: OptionButton) -> void`: adds the labels.

### Selection (world)
2. `game/scripts/world/selection_controller.gd`: `class_name SelectionController extends Node2D`. **No `@onready`.**
   - `signal selection_changed(kind: String, uid: int)`, where kind is "survivor", "building" or "".
   - `var selected_kind: String = ""`, `var selected_uid: int = 0`.
   - `bind(state)` connects `survivor_removed` and `building_removed` to clear the selection when the selected thing disappears.
   - `select_at_world(p: Vector2) -> void`: picks the closest survivor whose `pos` is within 24 px of `p`. Otherwise it picks the building at `Grid.world_to_tile(p)`. Otherwise it clears. Survivors win over buildings.
   - `select_survivor(uid)`, `select_building(uid)` and `clear()` emit `selection_changed` only when the selection actually changes.
   - `_draw()`: for a survivor, a 2 px light-green arc (radius 22) at its `pos`. For a building, a 2 px rect outline around its footprint (yellow if complete, light blue if blueprint). `_process` calls `queue_redraw()` while something is selected.
   - `_unhandled_input`: a left-click press calls `select_at_world(get_global_mouse_position())` and marks the event handled. `cancel` (Esc) or a right-click clears a non-empty selection.
   - BuildMode is a later sibling, so it receives input first and already marks its clicks handled while a building type is active. Don't change BuildMode.
3. `game/scenes/world/world.tscn`: add `Selection` (Node2D, this script) after `FloatingText` and before `Camera2D`. Don't touch other nodes.

### Info panel (UI)
4. `game/scenes/ui/info_panel.tscn` + `game/scripts/ui/info_panel.gd`:
   - `class_name InfoPanel extends CanvasLayer`, bottom-left, about 280 px wide, 8 px margins.
   - Reuse the `panel.png` StyleBoxTexture from `build_bar.tscn`. Set `mouse_filter = STOP` on the panel so clicks on it don't select through to the world.
   - Hidden when nothing is selected.
   - `bind(state: GameState, selection: SelectionController) -> void`. Look up child nodes in a getter or in `bind()`, not with `@onready`.
   - **Survivor:** name (bold/larger), `HP 50/50`, a job `OptionButton` (`JobOptions.fill`; `item_selected` → `JobOptions.apply`), the activity (`Survivor.activity_label`), and `Carrying 6 wood` when carrying.
   - **Building:** name from data, `HP a/b`, `Under construction 40%` or `Complete`, `Workers: n/m` (only when data `workers > 0`; n = survivors whose `work_uid == b.uid`), and a **Cancel blueprint** button that's visible only for incomplete buildings and calls `state.cancel_building(uid)`.
   - `refresh()` updates the text and only sets a value when it changed. Set the OptionButton with `select()`, which doesn't emit `item_selected`, so refresh never fights the player. `_process` calls `refresh()`.

### Roster (UI)
5. `game/scenes/ui/roster_panel.tscn` + `game/scripts/ui/roster_panel.gd`:
   - `class_name RosterPanel extends CanvasLayer`.
   - A small always-visible `Survivors (R)` toggle button at the top-left just under the resource bar.
   - A panel on the right side under the top bar (about 360 px wide, max height about 420 px, ScrollContainer) with a header `Survivors (N)`.
   - One row per survivor: a name Button (press → `selection.select_survivor(uid)`), a job OptionButton, and an activity label.
   - Rows are rebuilt on `survivor_added`/`survivor_removed`. Use `remove_child` then `queue_free`, so the row count is right immediately.
   - `toggle()`, `is_open() -> bool`, and `_unhandled_input` on the `roster` action (it already exists in project.godot).
   - `refresh()` updates the activity labels and job selections, as in the info panel.

## Acceptance criteria

- `select_at_world` on a survivor's position selects it, even when it stands next to a building. On a building tile with no survivor near, it selects the building. On empty grass, it clears. `selection_changed` fires once per actual change.
- Removing the selected survivor or cancelling the selected blueprint clears the selection.
- `JobOptions`: `index_for` round-trips through `apply` for all 7 options. Index 2 sets GATHERER with `gather_kind == "scrap"`. An out-of-range index returns false.
- InfoPanel with a selected survivor: the name label shows its name. Choosing "Builder" in the OptionButton (call the `item_selected` handler with the index) changes the sim survivor's `job` to BUILDER. With a selected blueprint: the Cancel button is visible, and pressing it removes the building and refunds per GDD. With a selected complete building: the Cancel button is hidden.
- RosterPanel: one row per survivor after bind. `survivors.add(...)` adds a row and `remove(uid)` removes it (counts correct immediately). Changing a row's job changes the sim. `toggle()` flips `is_open()`.
- `ui_roster` screenshot: the roster panel lists 4 survivors with jobs (Builder, Gatherer: Wood ×2, Gatherer: Scrap). The info panel shows the selected builder. A selection ring is visible around it. Nothing overlaps the top bar or the build bar.
- `default`, `build_mode`, `construction`, `gathering` screenshots still look right (the roster is closed by default; the `Survivors (R)` button is the only new element there).
- All tests pass with no `SCRIPT ERROR` line. Smoke passes. Static typing. Every file under ~250 lines.

## Pitfalls

- Nodes in tests have no viewport. Keep the logic in `select_at_world`, `refresh` and the handlers, not in `_unhandled_input`.
- Don't rebuild the roster rows every frame. Rebuild only on add/remove, and update labels in `refresh`.
- Don't put game rules in UI scripts. Job changes go through `GameState.set_job`, and cancels through `cancel_building`.
- Don't edit `hud.tscn` or BuildMode input.
- Godot commands: only the ones in `project/ARCHITECTURE.md`. Always pass `--path game`.
