# T-020: Wave spawner

Milestone: M3 | Type: code | Owner: gemini | Scenario: `night`
Depends on: T-018 (zombie sim), T-068 (zombie view). Both done.

## Goal

Nights currently have no zombies unless a scenario spawns them by hand. Add a sim-side `WaveSpawner` that, at
nightfall, schedules the night's wave from `GameData.wave_for_night(day)` and trickles the zombies in from the
map edges over the first 60% of the night. GDD §9.

Runner/brute target priorities are NOT in this task (that's T-078). Every spawned zombie uses the existing
`ZombieAI` behaviour.

## Context (read first)

- `game/scripts/sim/game_data.gd::wave_for_night(n)` already returns
  `{"walker": int, "runner": int, "brute": int, "sides": int, "final": bool}` from `waves.json`
  (`spawn_window_fraction` 0.6 is in the same file; read it via a new `GameData.wave_value(key, default)` getter or
  similar, no hard-coded 0.6).
- `GameState` (`scripts/sim/game_state.gd`) owns `clock`, `zombies`, `flow`, `rng`, `map`, `map_seed`.
  `spawn_zombie(type_id, world_pos)` exists. `hostiles_remaining()` currently returns `zombies.count()` and feeds both
  `clock.night_end_check` (night can't end while hostiles remain) and the HUD's "NIGHT – n zombies left".
- `ZombieAI` already walks out-of-bounds zombies onto the nearest edge tile, then follows the flow field.
- Night *n* is the night that follows day *n* (`clock.day` doesn't change until dawn).

## Work

1. **New `game/scripts/sim/wave_spawner.gd`** (`class_name WaveSpawner extends RefCounted`), owned by GameState as
   `var waves: WaveSpawner` (created in `_init` after `zombies`/`flow`).
   - `var enabled: bool = false`. **Off by default** so the 300+ existing unit tests that tick through nights keep
     working unchanged. `Game.new_game()` (`scripts/autoload/game.gd`) sets `state.waves.enabled = true`.
   - Its own `RandomNumberGenerator` seeded `map_seed + 3`. Do NOT draw from `state.rng` or the map RNG (it would shift
     every existing seeded result).
   - Connect `clock.phase_changed` with a **method Callable** (no lambda capturing `self`/state: see T-072). On the
     switch to NIGHT and only when `enabled`, call `plan_night(clock.day)`.
   - `plan_night(n: int) -> void`: builds `_schedule: Array[Dictionary]` of `{"time": float, "type": String,
     "side": int}`:
     - Pick `sides` distinct edges from `[0 N, 1 E, 2 S, 3 W]` with the wave RNG (shuffle, take first k).
     - Make the type list (walkers, runners, brutes, counts from `wave_for_night`), shuffle it with the wave RNG.
     - Entry *i* of *count*: `time = window * i / count` where `window = night_min_length * spawn_window_fraction`
       (night_min_length from `balance.json`), `side = chosen_sides[i % sides]`.
   - `tick(state, dt)` (called from `GameState.tick` each step, **before** `ZombieAI.tick`): while the next entry's
     `time <= clock.elapsed` and phase is NIGHT, pop it and spawn it at `spawn_point(side)`.
   - `spawn_point(side: int) -> Vector2`: a random position one tile **outside** the map on that edge
     (e.g. N = tile row -1, x in 2..size-3). Prefer points whose adjacent in-bounds edge tile has a route to the CC
     (`state.flow.distance(edge_tile)` is finite / `next_tile` isn't `(-1,-1)`); try up to 8 rolls, then use the last.
     Add a small random sub-tile jitter (±16 px along the edge) so zombies don't stack.
   - `pending() -> int` (entries not yet spawned). Any leftover schedule is cleared at dawn.
2. `GameState.hostiles_remaining()` returns `zombies.count() + waves.pending()`, so a night can't end between spawns.
3. Scenarios: every existing scenario that reaches night via `Game.state` but isn't about waves must set
   `Game.state.waves.enabled = false` as its first line, so its screenshot is unchanged: `zombies`, `zombies_perf`,
   `night_shelter`, `dawn_hunger`, `qa_m1_night`, `qa_clock_controls`, `qa_m1_day2_unlocks`,
   `qa_t067_full_build_bar`, `wall_upgrade` (check each one: grep `Phase.NIGHT|night_min|day_length` in
   `game/dev/scenarios/`).
4. **Scenario `night`** (`dev/scenarios/night.gd`, also used by `final_night.gd`): keep waves enabled, advance about
   12 s into night 1 so 2–3 walkers have spawned and are walking in, pause, and point the camera at the first spawned
   zombie (clamped by the camera as usual). The HUD should read "NIGHT – n zombies left" with n = 7 for night 1.
   `final_night` (day 20) then shows the final horde arriving from all four sides near the camera.

## Tests: new `game/tests/test_wave_spawner.gd`

- Disabled by default: `GameState.new(...)` ticked through night 1 spawns nothing and the night ends at 45 s (existing
  behaviour).
- Enabled, night 1: exactly 7 walkers spawn in total, all from 1 side; night 4: 16 walkers + 2 runners from 2
  distinct sides; night 8: brutes = 1 and sides = 2; night 20: double counts, 4 sides (use `plan_night(n)` directly
  plus ticking, or set `clock.day` before nightfall).
- Timing: every spawn happens at `clock.elapsed <= 45 * 0.6 + one tick`; the first spawns at the start of the night;
  spawns are spread out (no more than `ceil(count / 10)` spawn in any 10% slice of the window).
- Positions: every spawn is outside `[0, size)` on exactly one axis and on one of the chosen sides.
- `hostiles_remaining()` counts pending spawns: right after nightfall it equals the full wave size.
- The night does not end at 45 s while zombies live; after killing all of them (`state.zombies.damage(uid, 9999)`)
  the next tick past 45 s reaches dawn.
- Determinism: two states with the same seed produce identical spawn lists (type, time, position) for night 4.
- Existing tests unchanged and passing.

## Acceptance criteria

- `test_wave_spawner.gd` passes; all existing tests pass with no SCRIPT ERROR; import and smoke clean.
- No balance number hard-coded in `wave_spawner.gd` (counts, window fraction, night length all come from data).
- `night` screenshot shows zombies entering from a map edge and "NIGHT – 7 zombies left"-style HUD text;
  `final_night` shows a larger crowd; every other existing scenario's screenshot is unchanged.
- In the real game (Game.new_game), night 1 spawns 7 walkers.

## Pitfalls

- Don't touch `ZombieAI` targeting (T-078) or add combat (T-019).
- Typed everything: `var entry: Dictionary = _schedule[0]`, never `var w := weakref(x)`.
- `phase_changed` fires during `clock.advance()` inside `GameState.tick`; just build the schedule there, spawn in the
  next `waves.tick`.
- `sides_by_night` keys are strings in JSON; `wave_for_night` already handles that.
