# T-021: Lose condition + Game Over screen

Milestone: M3 | Type: code | Owner: gemini | Scenario: `game_over`
Depends on: T-019 (adds `GameState.damage_zombie` and `zombies_killed`).

## Goal

GDD §10: you lose when the Command Center is destroyed or the survivor count reaches 0. A Game Over screen shows the
stats (nights survived, zombies killed, survivors lost, buildings built, time played) with Restart and Quit.
(Main Menu comes with T-025; until then the second button is Quit. Log this in assumptions.md.)

## Work

1. **Sim (`scripts/sim/game_state.gd`, or a new `scripts/sim/game_stats.gd` if game_state.gd passes ~300 lines):**
   - `var game_over: bool = false`, `var lose_reason: String = ""` (`"command_center"` or `"survivors"`),
     `signal game_lost(reason: String)`.
   - `var time_played: float` (sum of sim `step`s in `tick`), `var buildings_built: int` (count
     `buildings.building_completed`, excluding the CC; connect with a method Callable), `var survivors_left: int`
     (survivors who walked out at dawn: increment where `DawnRules` removes them). Don't change what
     `survivors_lost` already means (deaths).
   - `func stats() -> Dictionary`: `{"nights_survived": clock.day - 1, "zombies_killed": zombies_killed,
     "survivors_lost": survivors_lost + survivors_left, "buildings_built": buildings_built, "time_played":
     time_played}`.
   - `_check_lose()` at the end of `tick()` and after dawn processing: if not `game_over` and (`cc_destroyed` or
     `survivors.count() == 0`), set `game_over`, `lose_reason` (CC wins if both), emit `game_lost` once.
   - The sim does **not** stop itself (existing tests tick past CC destruction). Freezing is the view's job.
2. **GameClock:** `var locked: bool = false`. While locked, `set_speed`, `toggle_pause` and `set_paused(false)` do
   nothing, so Space/1/2/3 and the HUD buttons can't resume a lost game.
3. **View: `scenes/ui/game_over.tscn` + `scripts/ui/game_over_screen.gd`** (CanvasLayer, layer above HUD, hidden
   until `game_lost`). Instanced in `main.tscn`, bound in `main.gd` like the other panels.
   - On `game_lost`: `clock.set_paused(true)`, `clock.locked = true`, show.
   - Full-screen dim (`Color(0, 0, 0, 0.6)`, `mouse_filter = STOP` so the map and build bar can't be clicked), a
     centred panel using the same panel texture/theme as the info panel, title "THE COLONY HAS FALLEN" (large, red),
     reason line ("The Command Center was destroyed." / "No survivors remain."), then five stat rows (label left,
     value right; time as m:ss), then **Restart** and **Quit** buttons.
   - Restart: `get_tree().reload_current_scene()` (`main._ready` already calls `Game.new_game()`). Quit:
     `get_tree().quit()`.
   - Keep the formatting in a static, testable helper (e.g. `GameOverScreen.stat_rows(stats: Dictionary) ->
     Array[Array]`).
4. **Scenario `dev/scenarios/game_over.gd`:** `waves.enabled = false` if present. Stage a believable run: set
   `clock.day = 6`, place and finish a few buildings through the real API, set `zombies_killed`/time fields directly
   (dev code may), then destroy the CC with `state.damage_building(cc, cc.hp)` and tick once so the screen shows.

## Tests: `game/tests/test_lose_condition.gd` (+ `test_game_over_screen.gd` for the helper)

- CC destroyed → `game_over`, reason "command_center", `game_lost` emitted exactly once even after more ticks.
- Last survivor killed via `damage_survivor` → reason "survivors". Last survivor leaving at dawn (hunger) → same.
- No loss while ≥1 survivor and the CC stands.
- Stats: `buildings_built` counts completed blueprints only (not the CC, not cancelled blueprints);
  `time_played` grows with sim time (not while paused); `nights_survived` == day − 1; kills counted via
  `damage_zombie`.
- Clock lock: after `locked = true`, `set_speed(2)` and `toggle_pause()` leave it paused.
- `stat_rows` formats 125.4 s as "2:05" and lists the five stats in GDD order.

## Acceptance criteria

- New tests pass; all tests pass with no SCRIPT ERROR; import/smoke clean.
- `game_over` screenshot: dimmed map, readable panel with title, reason, five stats, two buttons, at 1280×720.
- Other screenshots unchanged.

## Pitfalls

- `reload_current_scene()` must not leave the old GameState alive. `Game.new_game()` replaces `Game.state`; don't keep
  extra references in static vars.
- Don't free/disable nodes in tests that aren't in the tree; see `game/tests/README.md` "Testing scenes and Node
  scripts".
