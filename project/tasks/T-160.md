## Goal

A rendered (windowed, non-headless) run of the menu-flow QA script without `--no-fade` reports 19 failures out of 47
checks. Headless runs and `--no-fade` runs pass. Make the script pass with real fades too.

## Context

- Since T-110, `Game` (`game/scripts/autoload/game.gd` line ~189) calls `screen_fade.fade_out()` (default 0.3 s, see
  `fade_out(duration: float = 0.3)` in `game/scripts/ui/screen_fade.gd`) before reloading the scene. In headless mode
  the fade is instant; in a rendered run it takes ~18+ frames.
- `_button_reload(...)` in `qa_t025_menu_flow.gd` presses the button, drops its reference, then waits a fixed
  `_frames(tree, 4)` and checks `old_ref.get_ref() == null`. With a real fade the old `GameState` is still alive, so
  'MainMenu/NewGame is visible and frees previous GameState' fails and the later Reload/seed checks cascade.

## Do

1. Add a helper such as `static func _wait_freed(tree: SceneTree, ref: WeakRef, max_frames: int) -> void` that awaits
   `tree.process_frame` until `ref.get_ref() == null` or `max_frames` frames have passed. Cap: enough for the fade plus
   reload with margin (e.g. 180 frames ≈ 3 s at 60 fps); name it as a constant at the top of the script.
2. Use it in `_button_reload` in place of `_frames(tree, 4)`, then keep a couple of extra frames (`_frames(tree, 4)`)
   so the new scene's `_ready` has run before the following checks. Keep `button = null` before waiting.
3. Check every other place in the script that waits after something that triggers a reload/fade (e.g. Restart, Main
   Menu, Continue) and use the same bounded wait there. Don't change what any check asserts or its label text.

  --flow-report=<abs path in run folder>.json` prints `47 checks, 0 failures` (keep the report JSON in the run folder).

## Pitfalls

- Don't hold a strong reference to the old `GameState` or the pressed button while waiting (the check is that it frees).
- Don't touch `screen_fade.gd`, `game.gd`, `project.godot` or `export_presets.cfg`: the export is running in the other lane.
- A bounded poll, never an unbounded `while` loop: a real failure must still fail, not hang.
