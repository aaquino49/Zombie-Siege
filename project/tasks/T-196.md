# T-196: Personal records per difficulty (records.cfg, Victory/Game Over lines, menu line)

Milestone: M10 | Type: code | Owner: gemini | Scenario: `game_over`

GDD §20.3. Endless mode (M9) has no score to beat. Keep a small local
record book.

## Scope fence

Touch: new `game/scripts/ui/records.gd` (static helpers in the style of
`game_settings.gd`, with a path parameter defaulting to
`user://records.cfg`), `game/scripts/ui/victory_screen.gd`,
`game/scripts/ui/game_over_screen.gd`, `game/scripts/ui/main_menu.gd`, the
`game_over` and `main_menu` scenarios if they need a seeded record, new
`game/tests/test_records.gd`, `project/assumptions.md`. No sim changes:
read the existing `GameState.stats()` and difficulty.

## Do

1. `class_name Records` with `load_all(path)` and
   `submit(difficulty, nights_survived, won, time_played_s, path) ->
   Dictionary` that updates and saves the file and returns what was beaten
   (`{"best_nights": bool, "fastest_win": bool, "first_win": bool}`).
   Per difficulty: `best_nights` (completed nights, endless included),
   `wins`, `fastest_win_s` (0 = none).
2. Submit once when the Victory panel shows (won = true) and once when Game
   Over shows (won = false). Victory, then Keep fighting, then a later Game
   Over submits twice; that's intended, but the second submit must not add
   another win. Track "this run already won" in the screen/game flow, not
   in the file.
3. Victory and Game Over: under the stats, one accent-coloured line per
   beaten record: "New record: 23 nights (Normal)", "Fastest win: 41:10".
   Nothing extra when nothing is beaten.
4. Main menu: one small line under the buttons, "Best: Easy 12 · Normal 23
   · Hard 9 nights", listing only difficulties that have a record; hidden
   when the file is missing or empty. No overlap with Continue or the buttons.
5. A corrupt or missing file means empty records: no crash, no error spam.
6. Tests use a temp path (never the real `user://records.cfg`): first submit
   sets records; a worse result doesn't overwrite; a win counts once per
   run; fastest win keeps the minimum; a corrupt file is tolerated; the menu
   line formats correctly.
7. Captures: `game_over` shows a "New record" line; `main_menu` shows the
   Best line (seed a temp records file in the scenario via the path
   parameter or a scenario-only override, and clean it up afterwards).

## Acceptance criteria

- Records persist per difficulty across launches in `user://records.cfg`.
- New-record lines appear only when a record is beaten; the menu line only
  when a record exists.
- Wins never double-count for one run (Keep fighting, then a later loss).
- Tests and scenarios never touch the real user records file.
- All tests pass, no SCRIPT ERROR, import/smoke clean; captures at 1280x720.

## Pitfalls

- Tests and scenarios share the user's APPDATA; always pass a temp path and
  delete it afterwards.
- `UiFont` sizes only; keep Victory's three buttons readable (T-186 layout).
