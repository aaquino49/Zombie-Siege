# T-045: BuildMode: ghost preview, click/Shift/drag placement, cancel

Milestone: M1 | Type: code | Owner: gemini | Scenario: `build_mode_invalid`
Depends on: T-044 (BuildingSprites, per-building world nodes, `buildings_placed` scenario). Part 2 of 3 of the old T-040. T-046 adds the build bar that calls `BuildMode.select`.

## Goal

A `BuildMode` node in the world shows a green or red ghost of the selected building, snapped to the grid under the mouse. A click places the building through `GameState.try_place`. Shift keeps placing, right-click or Esc cancels, and dragging with a wall places a straight line. All logic sits behind public methods, so it is unit-testable without a viewport.

### The one remaining bug (QA major, T-045 a1)

`BuildMode.end_drag` does `else: break` on the first failed `try_place`, so a wall line with an existing wall in the middle stops early. Required behaviour: **skip** failed tiles and keep going (`continue`, or just no else branch). Running out of wood still leaves the remaining tiles unplaced, because each later `try_place` fails on cost.

- Repro (already a test in `test_build_mode.gd`: `test_drag_skips_blocked_tiles_and_places_remaining_free_tiles`): seed 1337, `a = command_center_origin() + Vector2i(0, -4)`, pre-place a wall at `a + (1,0)`, `select("wooden_wall")`, `begin_drag(a)`, `end_drag(a + (3,0), true)` → returns 3; walls at offsets 0, 2, 3; the old wall at 1 is untouched.
- Make the drag **preview** agree with that: a tile that is blocked is red, and it does **not** count against the wood budget for the tiles after it (only tiles that would really be placed spend wood in the preview).
- Do not weaken or delete QA's tests. All tests in `test_build_mode.gd` must pass.
