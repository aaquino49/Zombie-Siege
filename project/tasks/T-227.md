# T-227: Fix: spitter watchtower coverage ignores the Spotters guard-range bonus

Milestone: M12 | Type: code | Owner: gemini | Scenario: `spitter` | skip_qa (unit-tested sim fix)
Depends on: T-218 (done).

## Problem

`game/scripts/sim/zombie_ai.gd` `_spitter_fallback_cache()` (around line
270) computes the watchtower ring as
`guard_range_tiles * watchtower.guard_range_mult * TILE + weather_delta`.
Every other range lookup adds the Spotters research bonus first:
`GuardJob.effective_range_px()` (guard_job.gd:89), `build_mode.gd:197`,
`selection_controller.gd:136`, `build_info_card.gd:68` all use
`(guard_range_tiles + state.tech.bonus("guard_range_tiles")) * mult`.
After Spotters, spitters judge tower coverage with a smaller ring than the
guards really have, so they keep walking in when they could already stop.

## Scope fence

Touch only `game/scripts/sim/zombie_ai.gd`, `game/scripts/sim/guard_job.gd`
(a helper), and `game/tests/test_spitter.gd` (or `test_guard_job.gd`).
**Do not touch `game/scripts/sim/balance_bot.gd`**: T-219 owns it in the
other lane. Its range estimate (line ~431) is a bot planning heuristic;
it stays as is and is listed as a known minor in PM notes. No data, UI or view changes.

## Do

1. Add a static helper in `GuardJob`, e.g.
   `static func tower_range_px(state: GameState, tower_type: String) -> float`
   = `maxf(TILE, (guard_range_tiles + tech.bonus("guard_range_tiles")) *
   guard_range_mult(tower_type) * TILE + Weather.range_delta_px(state))`.
   Make `effective_range_px()` use it for the on-tower case so the two can
   never drift (ground-guard case unchanged).
2. `_spitter_fallback_cache()` uses `GuardJob.tower_range_px(state,
   "watchtower")` instead of its inline formula.
3. Unit tests: (a) with Spotters done, the cache's watchtower radius equals
   `GuardJob.effective_range_px` for an on-tower guard, under clear and fog
   weather; (b) a tile just outside the old ring but inside the new one is
   now `covered_tiles` with Spotters, and is not without it; (c) without
   Spotters every existing spitter test is unchanged.

## Acceptance criteria

- With Spotters done, zombie_ai's watchtower coverage radius equals
  `GuardJob.effective_range_px` for an on-tower guard, clear and fog (test).
- Without Spotters, behaviour and all existing spitter/guard tests unchanged.
- Determinism: no new RNG draws; the cache is still built once per tick.
- Import, full suite and 300-frame smoke are clean.

## Pitfalls

- `effective_range_px` already calls `state.tech.bonus` directly; use the
  same access so fixtures that build a GameState keep working.
- Keep LF line endings. No balance retuning here; T-220 measures it.
