# T-156: Chore: qa_t025_menu_flow presses buttons reliably in headless mode

Milestone: M6 | Type: code | Owner: gemini | Scenario: `victory` | skip QA

## Goal

The live menu-flow QA script must pass headless on any seed, so the M6 QA pass (T-113) and later regressions can run it
without a window. Today the headless run reports **47 checks, 25 failures**
(`project/runs/T-153/a1/flow1.json` .. `flow3.json`), while the rendered run passes 47/0
(`project/runs/T-112/a1/qa_t025_flow_rendered.json`). This is a test-harness bug, not a game bug.

## Context

- Run it: `godot --headless --path game --script res://dev/scenarios/qa_t025_menu_flow.gd -- --quit-frames=1200 --flow-report=<abs path>.json`
- The first failure is `MainMenu/NewGame frees previous GameState`; every later "Reload ...", seed and Restart/Main
  Menu check cascades from it.
- `_button_reload` (around line 108 of `qa_t025_menu_flow.gd`) clicks with `_click(tree, point)`, which sends
  `InputEventMouseButton` press/release through `tree.root.push_input` at `button.get_global_rect().get_center()`.
  Headless, that click never reaches the button, so no reload happens. The tab checks earlier in the same file press
  with `button.pressed.emit()` and pass.
- `qa_m4_menu_flow.gd` already uses `pressed.emit()` for buttons (its `push_input` calls are Esc key events, which
  work), so it needs no change.

## Do

Only edit `game/dev/scenarios/qa_t025_menu_flow.gd`:
1. In `_button_reload`, press the button with `button.pressed.emit()` when `DisplayServer.get_name() == "headless"`;
   keep the synthetic click in rendered runs so they still exercise real mouse input. (Using `pressed.emit()` always is
   fine too if the rendered run still passes; say which you chose in work.json.)
2. Keep the WeakRef "frees previous GameState" check and the 4-frame wait. If headless needs more frames before the old
   `GameState` is freed, raise the wait to the smallest count that passes 3 runs in a row and add a one-line comment
   saying why.
3. Drop `_click` if nothing uses it any more.

## Acceptance criteria

- Three headless `qa_t025_menu_flow` runs (each New Game rolls a random seed) each print `47 checks, 0 failures`;
  quote the three lines and keep the three report JSONs in the run folder.
- One rendered (non-headless) run with `--quit-frames=1200` still reports 0 failures.
- No game code changes (Game autoload, `main.gd`, menus). If a real game bug turns up, log it in
  `project/assumptions.md` and report it as out of scope instead of fixing it.
- All tests, import, smoke and screenshot clean.

## Pitfalls

- Don't hold a strong reference to the old `GameState` (or to the pressed button's scene) across the wait, or the
  WeakRef check fails for the wrong reason. The existing `button = null` before waiting is there for that.
- `pressed.emit()` on a hidden or disabled button still fires the signal: check the button is visible first (as the
  click path implicitly did) and add that as a check so a hidden button still shows up as a failure.
