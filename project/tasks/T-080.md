# T-080: Zombies face their attack target (survivor or building)

Milestone: M3 | Type: code | Owner: gemini | Scenario: `zombies`
Depends on: T-078 (done). Review follow-up from T-078. Facing is presentation-only: no gameplay change.

## Problem

`Zombie.facing` only changes when a zombie moves (`zombie_ai.gd::_move_toward` and the carry-over step). A zombie
that starts attacking without moving keeps its spawn facing (`Vector2.DOWN`), so walkers and brutes hit walls
sideways. T-078 hid this with manual `facing = Vector2.LEFT` overrides in two scenarios.

## Work

1. `game/scripts/sim/zombie_ai.gd`: add `static func _face(z: Zombie, target_pos: Vector2) -> void`. It sets
   `z.facing = (target_pos - z.pos).normalized()` only when the length is > 0.001.
2. Call it in every attack branch, on every tick the zombie is attacking (not only when the hit lands):
   - survivor in range: `_face(z, target_s.pos)`
   - building on the zombie's own tile (`b_here`): `_face(z, b_here.center_world())`. If the vector is ~zero, it's skipped.
   - unreachable-pocket building (`b_target` in the `next == Vector2i(-1, -1)` branch)
   - building on the flow path (`b_target = state.buildings.get_at(next)`)
   - `_attack_building(state, z, b, dt)` (brute structure priority): `_face(z, b.center_world())`
   Use `Building.center_world()` so 2x2 targets like the CC are faced at their centre.
3. Delete the overrides: in `game/dev/scenarios/zombies.gd`, the `if type_id == "brute": z.facing = Vector2.LEFT`
   block and its comment; in `game/dev/scenarios/zombie_types.gd`, the `brute.facing = Vector2.LEFT` line.

## Acceptance criteria

- New tests (in `game/tests/test_zombie_priorities.gd` or `test_zombies.gd`):
  - A walker spawned one tile east of a complete wooden wall that blocks its flow path, with facing DOWN, has
    `facing.distance_to(Vector2.LEFT) < 0.1` after one `state.tick(0.1)`.
  - A walker with an exposed survivor directly north within 1 tile faces approximately `Vector2.UP` after one tick.
- Positions, targets, attack timers and damage are unchanged. The existing zombie, flow-field, priority and 250-walker
  perf tests pass with no edits.
- `zombies` screenshot: zombies at the wall face the wall. The `zombie_types` screenshot still shows the runner chase,
  the brute hitting the wall and the walker heading for the gap.
- `grep -n "facing" game/dev/scenarios/zombies.gd game/dev/scenarios/zombie_types.gd` finds nothing.
- All tests pass with no SCRIPT ERROR; import and smoke are clean.

## Pitfalls

- Only add `_face` calls inside the attack branches. Movement already sets facing; don't add writes after `_move_toward`.
- T-073 removes a stale comment in this file just before this task. Keep the current file content and only add.
- `zombie_ai.gd` is about 210 lines. Keep the change small: one helper and five one-line calls.
