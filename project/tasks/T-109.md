# T-109: Themed pixel UI: one Godot Theme for HUD, build bar, info panel, roster, hints

Milestone: M6 | Type: code | Owner: gemini | Scenario: `hud`

## Goal

Owner request R-5, UI must-have: replace the grey/Kenney panels and the default font with one pixel Theme built from
the T-108 kit (`game/assets/pixel/ui/`): 9-slice panels and buttons with hover/pressed/disabled, the OFL pixel font,
and pixel HUD icons. In-game UI only. The menus get the theme for free but are restyled properly in T-110.

## Decisions already made (don't re-open)

- **UI pixel scale is 2×** (1 source px = 2 screen px) for every UI texture: 9-slices, icons, glyphs. The world stays
  4×. At 4× the 6 px slice corners become 24 px and the 16 px resource icons 64 px, which doesn't fit a 48 px top bar at
  1280×720. One UI scale everywhere; no 4× UI pieces.
- **StyleBoxTexture can't scale a texture**, so 2× copies are generated, not hand-made: a script writes nearest-neighbour
  2× copies of the kit PNGs to `game/assets/pixel/ui/x2/` (same file names). Native files stay the source of truth;
  the copies are rebuilt by the script. This is the one allowed exception to ART_GUIDE §2's "never pre-upscale" (the
  quarterback adds that line to the guide).
- **Text sizes are real UI px** (README): body 16, HUD numbers and panel titles 20, Dawn Report title 32. Don't scale
  text by 2.

## Context

- Kit: `game/assets/pixel/ui/README.md` (read it). Panel, panel_inset, tooltip and the five button states are 32×22 with
  6 px margins on all sides; slider track/bar background 32×6 (2 px margins); fills 8×4 (1 px); grabber 8×12;
  checkbox 12×12; resource/day/night icons 16×16; pause/play/fast/faster glyphs 8×8.
  Font: `font/pixelify_sans.ttf` (OFL, import already set to no antialiasing/hinting).
  Palette (text colours must come from it): `asset_library/ittaimanero/palette.json`.
- Current UI: `game/scenes/ui/hud.tscn` (a `NinePatchRect` TopBar, `StyleBoxFlat` pressed styles and colour overrides
  on the speed buttons), `build_bar.tscn`, `info_panel.tscn`, `roster_panel.tscn`, `hint_panel.tscn`,
  `dawn_report.tscn` (each has a `StyleBoxTexture` override using the old `res://assets/ui/panel.png`), scripts in
  `game/scripts/ui/` (`build_bar.gd`, `dawn_report_panel.gd`, `phase_banner.gd` add overrides in code).
- These UI nodes live under `CanvasLayer`s, so a theme set on a parent Control or on the root Window does **not** reach
  them. Use the **project theme** (`gui/theme/custom` in `game/project.godot`), which applies everywhere.

## Pitfalls

- A theme on the root Window or on a Control parent doesn't reach Controls under a CanvasLayer. Use `gui/theme/custom`.
- `theme_override_*` beats the theme. Any leftover override in a scene or script silently keeps the old look; grep for
  `theme_override_styles`, `add_theme_stylebox_override`, `StyleBoxFlat` in `scenes/ui/` and `scripts/ui/`.
- With 12 px corners, a button smaller than 24 px in either direction has no centre region and looks broken. Keep
  buttons at least 32 px tall.
- `expand_icon` on Buttons scales icons to fit (fractional). For the speed buttons use the 2× glyphs at native size
  (`expand_icon = false`). Build bar building icons are world art (T-104) and may scale to fit; that's fine.
- Pixelify Sans is a variable font; keep the default (Regular 400). Don't enable MSDF or antialiasing in the import.
- The floating text, HP bars and phase banner are drawn in the world/canvas, not themed here, except the banner's font
  may switch to Pixelify Sans if it reads better (optional).
