# T-030: Audio integration

Milestone: M5 | Type: code | Owner: gemini | Scenario: `default`
Depends on: T-029 (done: the sound files), T-085 (done: `SFX`/`Music` buses + volume sliders in `AudioSettings`).

## Goal

The game makes sound: gunfire, hits, groans, building and UI cues, a nightfall horn and dawn chime, end-screen
stingers, and day/night music that crossfades. Everything plays on the buses the pause-menu sliders already
control. The sim stays deterministic and silent.

## Files (exact names from T-029, all present)

`game/assets/sfx/`: `gunshot.wav`, `turret_shot.wav`, `zombie_hit.ogg`, `zombie_die.ogg`,
`zombie_groan_1.wav`, `zombie_groan_2.wav`, `zombie_groan_3.wav`, `building_hit.ogg`, `building_destroyed.ogg`,
`building_placed.ogg`, `build_complete.ogg`, `survivor_hurt.ogg`, `ui_click.ogg`, `ui_error.ogg`,
`night_horn.wav`, `dawn_chime.wav`, `cc_alarm.wav`, `victory.wav`, `game_over.wav`.
`game/assets/music/`: `day_loop.ogg`, `night_loop.ogg` (looping is already on in their `.import` files).
Preload them with `const` paths in one table. Don't scan the folder at runtime.

## What to build

1. **Sim signals (`game/scripts/sim/game_state.gd`), additive only:**
   - `signal zombie_hit(z: Zombie)`: in `damage_zombie`, emit when the zombie took damage but didn't die (deaths
     keep `zombie_killed`).
   - `signal building_damaged(b: Building, amount: int)`: in `damage_building` when `lost > 0`, next to the
     existing `night_log.on_building_damaged` call.
   - `signal survivor_damaged(s: Survivor, amount: int)`: in `damage_survivor`, before the death check.
   Don't change any existing logic or emission order.
2. **BuildMode (`game/scripts/world/build_mode.gd`):** add `signal placement_attempted(ok: bool)`. Emit it from
   `place_at` (ok = result is OK) and once from `end_drag` (ok = `placed_count > 0`).
3. **`AudioManager` (`game/scripts/audio/audio_manager.gd`, `class_name AudioManager extends Node`)**, added to
   `game/scenes/main.tscn` as a node named `Audio`, bound in `main.gd` with `$Audio.bind(Game.state, $World/BuildMode)`,
   following the other `bind` calls.
   - `bind()` connects to: `state.shot_fired` (turret → `turret_shot`, guard → `gunshot`), `zombie_hit`,
     `zombie_killed` → `zombie_die`, `building_damaged` → `building_hit` (and `cc_alarm` when the type is
     `command_center`, at most once per 5 s), `building_destroyed`, `survivor_damaged` → `survivor_hurt`,
     `state.buildings.building_completed` → `build_complete` (skip the starting CC: only after the first tick, or
     only for buildings that were added as blueprints), `placement_attempted` → `building_placed` / `ui_error`,
     `state.clock.phase_changed` (NIGHT → `night_horn` + night music, DAY → `dawn_chime` + day music),
     `game_won` → `victory`, `game_lost` → `game_over` (both stop the music).
   - **UI clicks:** play `ui_click` for every `BaseButton.pressed` in the scene. Connect existing buttons in
     `bind()` (walk the tree from `get_tree().current_scene`), and catch later ones through `get_tree().node_added`.
   - **Night groans:** while it's night and `state.zombies.count() > 0`, play a random `zombie_groan_1..3` every 4–9 s.
     Use the manager's **own** `RandomNumberGenerator` and real `delta` in `_process`. Never touch the sim RNGs.
   - **Voice caps:** a small pool of `AudioStreamPlayer`s per sound (bus `SFX`). Limits: `gunshot` 4,
     `turret_shot` 4, `zombie_hit` 3, `zombie_die` 3, `building_hit` 2, everything else 1–2. When every player for
     that sound is busy, skip the new play (don't cut off a playing one).
   - **Music:** two `AudioStreamPlayer`s on bus `Music`. On a phase change, tween the old one down to -40 dB and
     the new one up to 0 dB over 2 s, then stop the old one. Start with the music for the current phase in `bind()`
     (the main menu runs over a paused DAY state, so day music plays there). Volumes rely on the buses. Don't
     apply per-player dB except for the crossfade.
   - **Testability:** keep `var played: Dictionary` (sound name → count of accepted plays) and a single `_play(name)`
     entry point that increments it before starting a player. Start the player only when `is_inside_tree()`, so
     off-tree tests produce no errors.
   - The sim ticks while the Game Over/Victory screens are up, so don't loop stingers. Guard re-entry with a flag.
4. No changes to `AudioSettings`, the pause menu, `dev_tools.gd`, `run_tests.gd` or `test_case.gd`.

## Tests (`game/tests/test_audio_manager.gd`, new)

Off-tree, with a seeded `GameState` and a `BuildMode` instance (or a stub with the signal), `bind`, then emit or
cause the events and assert `played` counts:
- `shot_fired(..., false)` → `gunshot` +1, `shot_fired(..., true)` → `turret_shot` +1.
- `damage_zombie` that doesn't kill → `zombie_hit`. One that kills → `zombie_die`.
- `damage_building` on the CC twice within 5 s of manager time → `cc_alarm` exactly once.
- `placement_attempted(true/false)` → `building_placed` / `ui_error`.
- Phase change to NIGHT → `night_horn`, and the active music stream is `night_loop`. Back to DAY → `dawn_chime`
  and `day_loop`.
- Voice cap: the pure helper that decides whether a sound may start (for example `_can_start(name, busy_count)`)
  refuses a 5th `gunshot`. Test the helper directly, because the headless audio driver may not report `playing`.
- The new GameState signals fire with the right arguments (`zombie_hit` not on the killing blow).
- Determinism: two seeded GameStates ticked for the same nights, one with an AudioManager bound and one without,
  end with identical zombie/kill counts.

## Acceptance criteria

- The volume sliders affect the sounds, because every SFX player uses bus `SFX` and both music players use `Music`.
- All new tests pass. The whole suite passes with no `SCRIPT ERROR`/`ERROR` lines. Import, the 300-frame smoke run
  and the default screenshot are clean (the screenshot is unchanged, since audio has no visuals).
- `notes_for_qa` lists every event → sound mapping and the cap values.

## Pitfalls

- Load audio only through `preload`/`load` of the files above. Missing files must not crash: they're all present,
  and a test should assert every path loads.
- Don't connect to signals with lambdas that capture `self` from sim objects back into the view. Bind methods on
  the manager instead, so no reference cycle forms (see T-072's GameState-frees-cleanly test).
- No `@onready` on nodes that scenarios or tests may not create. Build the players in code in `bind()`.
- No scratch files in the repo root.
