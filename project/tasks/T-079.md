# T-079: Guard posting: don't abandon a reachable ground post for an unreachable free watchtower

Milestone: M3 | Type: code | Owner: gemini | Scenario: `defense`
Depends on: T-019 (done). Review follow-up from T-019. Small sim fix: one file plus a test.

## Problem

`game/scripts/sim/guard_job.gd::tick()` re-checks a ground-posted guard every `guard_post_check_interval`. If
`free_tower(state, s)` returns any complete, unheld watchtower, it calls `leave_post`, then `pick_post` assigns that
tower. If the tower's whole 1-tile ring is walled in, `find_path_adjacent` returns `[]`, so the guard sits IDLE and
retries every `job_retry_interval` **forever** instead of guarding at its CC ring post. On a real night, that guard
never fires a shot.

## Work

1. In `guard_job.gd`, only take a tower when it can be reached:
   - Add `static func _reachable_tower(state: GameState, s: Survivor) -> Building`. It walks the candidates in the same
     order as `free_tower` (nearest by squared distance, then lowest uid) and returns the first one where the
     survivor is already `on_tower` for it, **or** `state.pathfinder.find_path_adjacent(s.tile(), b.origin, b.size)`
     is non-empty, **or** the survivor already stands on a passable ring tile of it (`Grid.in_ring`). Otherwise it
     returns `null`.
   - Use `_reachable_tower` in `pick_post` and in the periodic ground-post re-check, instead of `free_tower`.
     Keep `free_tower` unchanged (tests and other code may call it).
   - When a guard is assigned to a tower and the path to it comes back empty (the existing `s.path.is_empty()`
     branch when `b != null`), call `leave_post(state, s)` so the next tick picks again. With the change above, that
     falls back to a ground post. Don't leave the guard IDLE while it still holds a tower `post_uid`.
2. Pathfinding cost: `find_path_adjacent` runs at most once per candidate tower per guard per
   `guard_post_check_interval`. Never call it every tick.
3. Keep it deterministic: no `state.rng`, and don't iterate dictionaries for ordering.

## Acceptance criteria

- New test in `game/tests/test_guard_job.gd`: a complete watchtower away from the CC whose whole ring is complete
  wooden walls, plus one guard. After 10 s of ticks (dt 0.1), the guard has `post_uid == 0`, holds a CC ring
  `post_tile`, stands on it, and has `activity == GUARDING`.
- Same test continued: remove one ring wall (use the building-removal API the existing tests use). Within another 10 s,
  the guard is `on_tower` on that watchtower.
- Existing `test_guard_job.gd`, `test_combat.gd` and `test_combat_qa.gd` pass. That includes
  `test_nearest_tower_tie_reservation_and_unreachable_retry`. If that test asserts the old IDLE-retry behaviour for an
  unreachable tower, change only the assertion that contradicts this brief, and explain it in `notes_for_qa`.
- All tests pass with no SCRIPT ERROR; import and smoke are clean; the `defense` screenshot is unchanged.

## Pitfalls

- A guard on a tower stands at the tower's centre, not on a ring tile. Don't path-check a guard's own current tower,
  because from the centre it would come back unreachable.
- Blueprints also block tiles. Use complete walls in the test so it doesn't depend on builders.
- Never declare inferred-Variant locals (`var x := dict[k]`); warnings are errors.
