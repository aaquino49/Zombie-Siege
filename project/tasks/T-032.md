# T-032: Tutorial hints

Milestone: M5 | Type: code | Owner: gemini | Scenario: `tutorial`
Depends on: nothing open (re-planned 2026-10-10: the hints don't need the M4 QA result, so they can run right after it).

## Goal

A first-time player should learn the core loop without a manual. Show short, contextual hint cards at the right
moments (GDD §11 "Tutorial hints"). Each hint shows at most once per game. The player can dismiss a card, and can
turn hints off in the pause menu. The game never pauses for a hint.

## Design

### Sim side: `game/scripts/sim/tutorial_hints.gd` (new, `class_name TutorialHints extends RefCounted`)

Pure logic, no nodes, fully unit-testable. It doesn't touch `GameState.tick` or the balance bot.

- `var enabled: bool = true`, `var shown: Dictionary = {}` (hint id → true), `var day_time: float` (seconds of daytime
  seen this day, reset at each new day).
- `func check(state: GameState, delta: float) -> String` returns the id of the next hint to show, or `""`. It marks
  that id as shown. It returns `""` when disabled, during the night (except `night_soon`, which fires in the day),
  or when `state.game_over` is true. At most one id per call, in the priority order below.
- `static func text(id: String) -> String` returns the card text. Keep each to 1–2 short lines.

Hints, in priority order (use `GameData` for unlock days and costs, never hard-coded numbers):

| id | Trigger | Text (suggested) |
|---|---|---|
| `welcome` | day 1, first check | "Day 1. Gather, build and farm by day. Zombies attack at night. Press B to build." |
| `farm` | day 1, ≥ 20 s of daytime, no Farm (blueprint or complete) | "Every survivor eats 1 food each dawn. Build a Farm and give it Farmers (R opens the roster)." |
| `night_soon` | day phase, `clock.time_left()` ≤ 30 s, before the first night (T-098: the day is 70 s, so 45 s would land right after `farm`) | "Night is coming. Zombies walk in from the map edge. Wall in the Command Center and keep a Guard posted." |
| `ammo` | day ≥ Workshop unlock day, no Workshop (blueprint or complete), ammo < 30 | "Guards and turrets spend 1 ammo per shot. Build a Workshop and assign a Crafter to turn scrap into ammo." |
| `hungry` | any survivor `is_hungry()` | "Hungry survivors work at half speed and leave after 2 hungry days. Build more Farms." |
| `radio` | day ≥ Radio Tower unlock day, no Radio Tower | "The Radio Tower is unlocked. Build it and survive night 20 to call the rescue helicopter." |

### Settings: `game/scripts/ui/hint_settings.gd` (new, `class_name HintSettings extends RefCounted`)

`static func load_enabled(path: String = AudioSettings.PATH) -> bool` (default true) and
`static func save_enabled(on: bool, path: String = AudioSettings.PATH) -> void`. Use section `"gameplay"`, key
`"hints"` in the same `user://settings.cfg`. Load the file first and keep the existing `audio` keys (copy
`AudioSettings.save_volumes`' load-then-set pattern).

### View: `game/scenes/ui/hint_panel.tscn` + `game/scripts/ui/hint_panel.gd` (new, `class_name HintPanel extends CanvasLayer`)

- `layer` 12: above the HUD, below Dawn Report (15), Game Over/Victory (20), pause (25) and main menu (30), so
  every modal covers it.
- A small panel at the top left under the "Survivors (R)" button: about x 8–388, y 96–190 at 1280x720. Reuse the
  panel texture and font styling of the info panel. A Label with autowrap, plus a small "Got it" button.
- `bind(state: GameState)` creates a `TutorialHints`, sets `enabled = HintSettings.load_enabled()`, and checks once
  per `_process` with the clock-scaled delta. Skip checks while the clock is paused. When `check` returns an id,
  show its text. If a card is already showing, queue the id and show it after the current one closes.
- A card closes on "Got it" or after 12 s of real time. Closing doesn't pause or unpause anything.
- `set_enabled(on: bool)`: hides the current card when turned off.
- **Screenshots:** in `main.gd`, call `$Hints.set_enabled(false)` when a `--scenario=` argument is present, so every
  existing scenario screenshot stays unchanged. The `tutorial` scenario turns them back on.

### Pause menu toggle

Add a "Hints" `CheckButton` row under the volume sliders in `pause_menu.tscn`. In `pause_menu.gd`, load it from
`HintSettings`, save it on toggle, and call a hints callback so the panel updates live. Wire it the same way the
other `bind` arguments are wired: add an optional `hints: HintPanel = null` parameter at the end of
`PauseMenu.bind`, so existing tests keep compiling. Keep the panel inside 1280x720.

### Wiring

Add `Hints` (hint_panel.tscn) to `main.tscn`, call `$Hints.bind(Game.state)` in `main.gd` `_ready`, and pass it to
`$PauseMenu.bind(...)`. New Game / Restart already rebuild state. Make sure a new game gets a fresh `TutorialHints`.

### Scenario `game/dev/scenarios/tutorial.gd` (new)

Day 1 a few seconds in, hints enabled, the `welcome` card visible (call the panel's show method directly if needed
so it's on screen at frame 120).

## Acceptance criteria

- `game/tests/test_tutorial_hints.gd` (new) covers, on a real `GameState.new(GameData.load_default(), 1337)`:
  `welcome` fires first, and only once. `farm` fires after 20 s of day 1 with no farm, and doesn't fire if a Farm
  blueprint exists. `night_soon` fires at ≤ 30 s to nightfall on day 1. `ammo` and `radio` respect the unlock days
  from data. `hungry` fires when a survivor is hungry. Nothing fires while `enabled == false` or once `game_over`
  is set. At most one id per `check` call. No id ever repeats.
- `HintSettings` round-trip test using a temp path under `user://` (never the real settings file). Saving hints
  keeps existing `audio` volume keys.
- `tutorial` scenario screenshot at 1280x720 shows the hint card, readable, and not overlapping the top bar, the
  Survivors button or the build bar.
- `default` and every other existing scenario screenshot is unchanged (no hint card).
- All tests pass with no SCRIPT ERROR. Import, smoke and screenshots are clean.
- GDD §11 already describes this feature. Don't edit the GDD.

## Pitfalls

- `TutorialHints` must never be ticked by `GameState` or used by the balance bot or `dev/balance_run.gd`.
- Nodes in tests aren't in the tree (`game/tests/README.md`). Test `TutorialHints` and `HintSettings`, not the
  CanvasLayer. If you test `HintPanel` at all, use the existing off-tree pattern.
- Don't edit `dev_tools.gd`, `run_tests.gd`, `test_case.gd`, `game/data/*.json` or `balance_bot.gd`.
- Building ids must come from data (check `game/data/buildings.json` for `farm`, `workshop`, `radio_tower`).
  Unlock days are `unlock_day` there.
- Keep every text inside the card at 1280x720. No clipped words.
