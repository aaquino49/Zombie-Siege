# T-152: QoL: build-bar info card (what each building does, its stats, what you still need)

Milestone: M7 | Type: code | Owner: gemini | Scenario: `build_info`

## Goal

The build bar only shows icon, name and cost; its tooltip repeats the same ("Workshop: 30 wood, 10 scrap") in 11 px
text. A new player has no way to learn in-game what a Lumber Yard or Watchtower does, or that a Shelter adds beds,
without reading How to Play. Add a small themed **info card** above the build bar that explains the building under
the mouse (or the one selected for placement). GDD §17.4.

## Do

1. **Data (text only).** Add a short `"blurb"` string to each placeable building in `game/data/buildings.json`, taken
   from GDD §7's Effect column, no numbers in it (numbers come from data, below). Suggested wording:
   wall "Blocks zombies.", gate "A wall your survivors can walk through.", shelter "Beds and a safe place at night.",
   farm "Farmers grow food.", storage "Extra drop-off point for gatherers.", watchtower "A guard here shoots further
   and is protected.", workshop "A crafter turns scrap into ammo by day.", lumber_yard "Speeds up wood chopping
   nearby.", turret "Shoots zombies on its own. Uses ammo.", reinforced_wall "Upgrade a Wooden Wall: much tougher.",
   radio_tower "Build it and survive night 20 to win." If `GameData` validates building keys, accept `blurb` as an
   optional string; a missing blurb shows nothing (no crash). No balance value changes.
2. **Card.** New `game/scripts/ui/build_info_card.gd` (`class_name BuildInfoCard extends PanelContainer`), a child
   of `game/scenes/ui/build_bar.tscn` (same CanvasLayer), mouse-ignoring, theme `Panel` style. Static, testable
   `static func lines_for(data: GameData, resources: ResourceStore, type_id: String) -> Array[String]` returning:
   - name (`UiFont.LARGE`, 33 px; crisp `UiFont` sizes only),
   - the blurb,
   - a stats line from data: `HP 150 · 2×2` plus `1 worker` / `up to 2 workers` (`workers`), `+4 beds` (`beds` > 0),
     `range 5 tiles` for the turret and `ammo every 4 s` for the workshop (read `craft_time`, so T-136's 5 s shows),
   - when unaffordable, `Need 5 more scrap` (summing every short resource), else nothing.
   Body text at `UiFont.BODY` (22). Width at most 420 px; wrap at whole words.
3. **Show/hide** in `build_bar.gd`: on a button's `mouse_entered` show the card for that type, positioned just above
   the bar and horizontally aligned with the button (clamped inside 8..1272 px); on `mouse_exited` fall back to the
   active placement type if there is one, else hide. Refresh when resources change (the "Need" line) and on dawn
   rebuild. Hidden whenever the bar panel is hidden (B) and when the game is paused by the pause menu. Shorten the
   button `tooltip_text` to empty so Godot's tiny tooltip does not double up.
4. **Scenario** `game/dev/scenarios/build_info.gd`: day 4 colony (reuse `build_bar_day2.gd`'s setup style), scrap
   short of a Turret, Turret set as active type through the build bar so the card shows "Need N more scrap"; capture at
   1280x720.

## Acceptance criteria

- `build_info` capture: the card sits above the build bar, readable at 1x, showing Turret name, blurb, stats and a
  "Need … more scrap" line; nothing else on screen is covered except the map.
- `test_build_info_card.gd`: every placeable building yields a non-empty name, blurb and stats line; workshop's
  stats contain the live `craft_time` from data; shelter shows `+4 beds`; an unaffordable type gets the exact short
  amount; an affordable one gets no Need line; an unknown/missing blurb doesn't crash.
- Hovering a button shows its card; leaving it falls back to the selected type or hides (test with the bar's methods,
  no real mouse needed); B hides bar and card together.
- No change to costs, balance, placement or existing test expectations; all tests, import, smoke and screenshot clean.

## Pitfalls

- `build_bar.gd` rebuilds its buttons every dawn and frees the old ones: connect hover signals per new button, and
  don't keep references to freed buttons.
- The bar's width maths (`available_width`, `widths`) must not change; the card is a sibling of `Panel`, not inside
  the HBox.
- Don't touch the icon PNGs or the cream cost backing (T-143 owns the icons), `game_theme.tres` (T-141), the settings
  screen or `hud.tscn` (T-145), or main menu files (T-112).
- Use only `UiFont` sizes (a test rejects others); the card must not use the 11 px tooltip size for body text.
