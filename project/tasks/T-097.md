# T-097: Chore: stop audio playback on AudioManager teardown (headless exit leak)

Milestone: M5 (moved from M6 on 2026-10-10: the smoke run must print no `ERROR:` lines before the Windows export
and final QA) | Type: code | Owner: gemini | Scenario: `default` | skip_qa

## Goal

Since T-030 the 300-frame smoke run (`godot --headless --path game -- --quit-frames=300`) exits 0 but prints
`WARNING: 4 ObjectDB instances were leaked at exit` and `ERROR: 2 resources still in use at exit`. With `--verbose`
these are `AudioStreamPlaybackOggVorbis` / `OggPacketSequencePlayback` and `res://assets/music/day_loop.ogg`, held by
the music player that `AudioManager.bind()` starts. ARCHITECTURE.md says smoke output must be free of `ERROR:`
lines, and the exported exe (T-033) and final QA (T-034) will run the same check. Clear it.

## What to change

Only `game/scripts/audio/audio_manager.gd` (plus a test).

- Add `func _release_audio() -> void` that: kills `_music_tween` if valid (and sets it to null), calls `stop()` and
  sets `stream = null` on `_music_player_a`, `_music_player_b` and every player in `_sfx_pools`, and clears
  `active_music_stream` / `active_music_name`.
- Call it from `_exit_tree()` (after the existing `node_added` disconnect) and from `unbind()`. Also handle
  `NOTIFICATION_PREDELETE` in `_notification` if the players can outlive the tree exit.
- If `_streams` caches loaded `AudioStream`s, clear it in `_release_audio()` too. The players are rebuilt or
  re-streamed on the next `bind`, so `bind()` after `unbind()` must still play music. Check that.
- Don't change any event mapping, voice cap, bus, volume or crossfade timing.

## Acceptance criteria

- The 300-frame headless smoke run prints no `resources still in use at exit` or `ObjectDB instances were leaked`
  lines that trace to audio. Paste the last 10 lines of the smoke output in `work.json`.
- New test in `game/tests/test_audio_manager.gd`: after `bind` + `_release_audio()` (or `unbind()`), both music
  players have `stream == null` and are not playing. Then `bind` again restores a music stream on the active player.
- Every existing `test_audio_manager.gd` test and the full suite pass with no SCRIPT ERROR.
- Import and the default screenshot stay clean.

## Pitfalls

- If stopping alone doesn't clear the warning, find what else holds the stream (run the smoke with `--verbose`),
  for example a preload constant or a stream cached on the node. Note what you tried in `project/assumptions.md`
  and leave the cleanup in place.
- Nodes in tests aren't in the tree, so `_exit_tree` won't run there. Test `_release_audio()` / `unbind()` directly.
- Don't touch `dev_tools.gd`, `run_tests.gd`, `test_case.gd` or `main.gd`.
