# T-200: Cleanup: make Weather night rolls O(1) per sim tick

Milestone: M10 | Type: code | Owner: gemini | Scenario: `default` | skip QA (covered by T-198)

Follow-up from the T-193 review. Pure sim performance; no visible change.

## Problem

`Weather.night_weather()` (`game/scripts/sim/weather.gd`) enforces
`no_repeat` by recursing to `night - 1` all the way down to
`fog.first_night`, allocating a fresh `RandomNumberGenerator` per level.
`Weather.range_delta_px()` calls it through `GameState.weather_night()` on
every guard tick (`guard_job.gd`) and every turret range check
(`combat.gd`), and T-194 will call it for range rings every frame. On endless
night 40 at 4x speed that is tens of thousands of RNG allocations per second.

## Scope fence

Touch only `game/scripts/sim/weather.gd`, `game/scripts/sim/game_state.gd`
and `game/tests/test_weather.gd` (new tests). No data, UI, world or save
changes. `project/assumptions.md` if needed.

## Do

1. `Weather.night_weather()`: replace the recursion with a forward loop
   from `fog.first_night` to `night`, reusing **one** `RandomNumberGenerator`
   and re-seeding it per night with exactly the same
   `hash([map_seed, n, "fog"])`, so results are bit-for-bit identical.
   Keep `day_weather()` / `night_weather()` static, pure and uncached.
2. `GameState`: add a small memo used by `weather_day()` and
   `weather_night()`, keyed by `[map_seed, clock.day, <config fingerprint>]`,
   where the fingerprint is `data.weather_config().hash()` (or the rain/fog
   sub-dictionaries' hashes). Tests in `test_weather_qa.gd` mutate
   `data.weather_config()` mid-test, so a config change must invalidate the
   memo automatically. A single cached entry per kind (last key + result)
   is enough; no unbounded dictionary.
3. `Weather.range_delta_px()` keeps calling `state.weather_night()`, so it
   now hits the memo.
4. New tests in `test_weather.gd`:
   - for seeds 1337 and 1-9, nights 1-60, the loop version equals a local
     copy of the old recursive algorithm (kept in the test only);
   - `state.weather_night()` changes immediately after mutating
     `data.weather_config()["fog"]["chance"]` (memo invalidation), and
     after `clock.day` changes.

## Acceptance criteria

- No behaviour change: every existing test, including `test_weather.gd`,
  `test_weather_qa.gd`, the seed-1337 pacing pins and the M9 release tests,
  passes unchanged.
- `night_weather()` allocates at most one RNG per call; `GameState`
  weather queries are memoized and invalidate on seed, day or config change.
- All tests pass, no SCRIPT ERROR, import/smoke clean.

## Pitfalls

- `hash()` of an Array is stable within a run; don't switch to a different
  seeding scheme or the forecast changes for every existing save/seed.
- The `never_final` and `first_night` rules must still apply inside the loop
  exactly as before (a night forced clear breaks the fog chain).
- Don't touch `GameState.rng`.
