# T-026: Headless balance bot

Milestone: M4 | Type: code | Owner: gemini | Scenario: `default` (no visible change)
Depends on: T-023 (win condition, done).

## Goal

A headless bot that plays the real simulation through 20 nights with a scripted strategy, so I (Claude, T-027) can
tune `game/data/*.json` from numbers instead of guesses. Two strategies: **`sensible`** (a reasonable player) and
**`none`** (does nothing). The bot only **reads** state and **commands** it through the same public calls the UI
uses. It never changes rules, data or other sim code.

## What to build

### 1. `game/scripts/sim/balance_bot.gd`: `class_name BalanceBot extends RefCounted`

Pure sim: no Node, no autoloads, no file access in this class.

- `static func run(map_seed: int, strategy: String, nights: int, step: float = 0.25) -> Dictionary`
  - `var state := GameState.new(GameData.load_default(), map_seed)` and then `state.waves.enabled = true`. Waves are
    **off** by default in GameState; `Game.new_game()` is what normally switches them on.
  - Connect `state.dawn_processed` to record one **row per dawn** (see the columns below).
  - Loop `state.tick(step)` until `state.game_over`, or until `state.clock.day > nights` (the dawn after night
    `nights`), with a hard cap of `(nights + 1) * (day_length + 400) / step` ticks so it can never hang.
  - During the day, call the strategy's `_decide(state, memo)` every 5 simulated seconds. Track this with an
    accumulator, not with wall-clock time.
  - Returns `{"seed", "strategy", "outcome", "nights_survived", "cc_hp_pct", "rows": Array[Dictionary], "ms"}`.
    - `outcome` is `"won"` (`state.won`), `"lost_cc"` (`lose_reason == "command_center"`), `"lost_survivors"`
      (any other loss), or `"survived"` (horizon reached and still alive).
    - `ms` is `Time.get_ticks_msec()` elapsed (allowed: it's a measurement, not a rule).
- Row columns (in this order): `seed, strategy, night, cc_hp_pct, survivors, beds, food, wood, scrap, ammo,
  kills, lost, buildings_destroyed, buildings, radio_tower`. `kills`, `lost` and `buildings_destroyed` are that
  night's counts from the dawn report (`zombies_killed`, `survivors_killed.size()`, `buildings_destroyed.size()`).
  `radio_tower` is 1 when `state.radio_tower_complete()`, otherwise 0.
- `static func to_csv(rows: Array) -> String`: a header line plus one line per row, comma separated.

### 2. Strategy `none`

Keep the starting jobs and place nothing. GDD target (tuned later): it loses around nights 4–6.

### 3. Strategy `sensible`: sensible, not optimal

Keep the plan in a `memo: Dictionary` that is created once per run. Use only `state.try_place(type, origin)`,
`state.try_upgrade(uid)` and `state.set_job(uid, Survivor.Job.X, kind)`. Use `Placement.check()` to test tiles.
- **Ring:** once, at the start, choose the smallest radius r in 6..9 around the CC (same shape as
  `tests/night_sim_fixture.gd` `defended()`). Pick the first r where every ring tile is OK, UNAFFORDABLE or BLOCKED
  for `wooden_wall` (BLOCKED tiles are trees/rocks, which zombies can't pass anyway, so skip them). Put one `gate`
  on the ring tile in line with the CC's top edge. Store the ring tiles in `memo`.
- **Build queue** (each item waits until it's unlocked (`unlock_day`) and affordable; keep at most 2 open
  blueprints at a time):
  day 1: `farm`, then the ring walls + gate in ring order;
  day 2: `watchtower`, `workshop`;
  day 3: `lumber_yard`, and a `shelter` whenever survivors ≥ beds;
  day 4+: `turret` until there are 4;
  day 8+: `radio_tower` first. While it's unplaced, save resources for it (place nothing else except replacing
  destroyed ring walls);
  after the radio tower: a 2nd `farm` if food < 3 × survivors, more turrets up to 8, and upgrade ring walls to
  `reinforced_wall` with `try_upgrade` when wood > 80.
  Re-place destroyed ring walls (any day) before anything else.
  Interior buildings go on the first OK tile found by a deterministic scan from the CC outward, inside the ring.
  Never place on the ring or on the CC ring tiles (`state.cc_ring_tiles()`), so the paths stay open.
- **Jobs** (re-checked every decide call; only call `set_job` when a survivor's job actually needs to change):
  guards first: 2 from day 1, 3 from day 5, 4 from day 10 (never more than survivors − 2).
  Then 1 builder (2 while 3 or more blueprints are open). Then 1 farmer per complete farm. Then 1 crafter once a
  workshop is complete and ammo < 150. The rest gather: scrap for every third gatherer (every second from day 6),
  otherwise wood.

Determinism: no `randi()`/`randf()` anywhere. The same seed must give identical rows.

### 4. Runner `game/dev/balance_run.gd`: `extends SceneTree`

Command: `godot --headless --path game --script res://dev/balance_run.gd -- --seeds=1337,1,2,3,4 --nights=20 --strategy=both`
- Parse `--seeds=`, `--nights=` (default 20), `--strategy=` (`sensible`|`none`|`both`, default `both`), and `--out=`
  (default: `ProjectSettings.globalize_path("res://").path_join("../project/runs/balance")`, made with
  `DirAccess.make_dir_recursive_absolute`).
- For each seed and strategy: write `<out>/<strategy>_<seed>.csv` and print one summary line
  `BALANCE seed=… strategy=… outcome=… nights=… cc=…% ms=…`. Finally write `<out>/summary.csv` and call `quit()`.
- File writing lives here, not in BalanceBot.

### 5. Tests: `game/tests/test_balance_bot.gd`

Keep the whole file under about 10 seconds. **Never run 20 nights in the unit suite**, because every pipeline check
runs it.
- `run(1337, "none", 2)` returns 2 rows (or fewer only if it lost), places no buildings beyond the CC, and has the
  right columns.
- `run(1337, "sensible", 2)`: by the first row there's a farm (any state) and at least half the ring placed, and at
  least 2 survivors with `Job.GUARD`. Use a small inspection hook, for example an optional
  `on_dawn: Callable` parameter or `run_state()` returning the state as well. Your choice.
- Determinism: two `run(1337, "sensible", 2)` give identical `rows`.
- `to_csv` has the header plus one line per row.

## Acceptance criteria

- `balance_run.gd` with `--seeds=1337 --nights=20 --strategy=both` finishes, exits by itself, and each 20-night
  run takes < 60 s. Put the printed BALANCE lines for seed 1337 (both strategies) in `work.json` `summary` or
  `notes_for_qa`.
- CSVs are written to `project/runs/balance/` (that folder isn't in git, so don't commit outputs).
- Same seed → identical results. Unit tests pass in < 10 s for this file, with no SCRIPT ERROR. Import/smoke clean.
- No changes to `game/data/*.json` or to any existing sim/view file. New files only (plus their `.uid`).

## Pitfalls

- GameState/GameData are RefCounted: never `.free()` them. Disconnect nothing; just drop the reference.
- `clock.scale()` returns 0 while paused. The sim never pauses itself, but don't call `set_paused`.
- If you find a real sim bug (a crash, a survivor stuck forever), don't fix it here. Describe it in `notes_for_qa`.
- `--script` runs need a SceneTree script that calls `quit()`, and always `--path game`. Run it with `--headless`.
- No scratch files in the repo root or `game/` when you finish.
