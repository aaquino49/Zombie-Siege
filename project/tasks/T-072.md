# T-072: GameState frees cleanly: reference-cycle regression test (+ fix any exit leak)

Milestone: M3 | Type: code | Owner: gemini | Scenario: `default`
Depends on: T-018. Low priority. Owner request R-2: the exit-leak lines are now warnings, not failures, so this
task must not block anything.

## Goal

T-018 attempts 1–2 printed "5 resources still in use at exit" and "12 ObjectDB instances were leaked" in smoke, and
about 1560 leaked objects after the test run. The likely cause was a lambda that touched `self` and was connected
to `map.changed` (a map → lambda → FlowField → map cycle). T-018 attempt 4 switches it to a method Callable.
This task makes sure no sim object outlives its GameState, and adds a test so a cycle can't come back unnoticed.

## Work

1. Run smoke (`godot --headless --path game -- --quit-frames=300`) and the unit tests with `--verbose` once each, and
   note whether any "still in use" / "leaked" lines remain (put it in `notes_for_qa`).
2. New `game/tests/test_no_ref_cycles.gd`:
   - In a helper function, build `GameState.new(GameData.load_default(), 1337)`, spawn 5 walkers, place and complete
     a wall, tick 120 steps, kill one zombie and one survivor through the damage API, then return
     `[weakref(state), weakref(state.flow), weakref(state.zombies), weakref(state.buildings), weakref(state.map),
     weakref(state.pathfinder), weakref(state.survivors)]` (adjust to the real field names). The state goes out of
     scope when the helper returns.
   - Assert every `get_ref()` is `null`. RefCounted objects are freed as soon as their last reference goes, so this
     catches cycles synchronously.
3. If the test fails, find the cycle (a lambda that captures `self`/`state` and is stored on a child's signal, a
   child holding its parent, or a `static var` cache) and break it with a method Callable, a WeakRef (typed:
   `var w: WeakRef = weakref(x)`) or a uid.

## Acceptance criteria

- `test_no_ref_cycles.gd` passes. All tests pass with no SCRIPT ERROR. Import is clean.
- Smoke prints no "resources still in use" or "ObjectDB instances were leaked" line, or `notes_for_qa` explains
  exactly which engine-side objects remain and why they aren't the game's.
- No behaviour change. Every screenshot is unchanged.

## Pitfalls

- Never write `var w := weakref(x)` (an inferred Variant is a parse error under this project's warnings-as-errors).
- Don't convert method connections (`sig.connect(_on_x)`) into lambdas. Method Callables don't hold strong references.
