# T-194: Weather view: rain streaks, fog patches, top-bar tag, fogged range rings

Milestone: M10 | Type: code | Owner: gemini | Scenario: `weather_fog`

GDD §20.1. T-193 added the rules (`Weather`, `GameState.weather_day()`,
`weather_night()`, the public fog range helper). This task makes weather
visible and keeps the range preview honest.

## Scope fence

Touch: new `game/scripts/world/weather_layer.gd` (added in the world scene
or `world_view.gd`), `game/scripts/ui/hud.gd` (rain tag),
`game/scripts/world/build_mode.gd`, `game/scripts/world/selection_controller.gd`
and `game/scripts/ui/info_panel.gd` (effective range), new scenarios
`game/dev/scenarios/weather_rain.gd` and `weather_fog.gd`, new
`game/tests/test_weather_view.gd`, `project/assumptions.md`. No sim or data
changes. Small pixel textures for rain/fog may be drawn in code or added as
PNGs under `game/assets/` in the pack palette (`project/ART_GUIDE.md`); no
new third-party assets.

## Do

1. `WeatherLayer` (above terrain and buildings, below the HUD):
   - **Rain** (day phase of a rain day): thin pale-blue pixel streaks
     (whole pixels at the x4 scale, nearest filtering) falling diagonally,
     about 120-200 on screen, alpha <= 0.35. Fades in over ~1 s at dawn and
     out at nightfall.
   - **Fog** (night phase of a fog night): a handful of large, pixel-stepped
     pale patches drifting slowly (<= 10 px/s), combined alpha <= 0.25, so
     zombie rim, eyes and HP bars (T-138/T-139) stay readable. Fades in with
     the dusk fade and out at dawn.
   - Never drawn over the UI and never takes mouse input. No per-frame
     allocations.
2. Top bar: on a rain day show a small tag "Rain: farms +50%" (number from
   data) near the day label, `UiFont` sizes only, hidden otherwise. Leave
   room for T-195's "Idle: N" button (check `hud.gd` on main first; if
   T-195 has landed, place the tag so neither overlaps).
3. Range rings and the info-panel range line use the **effective** range:
   at night on a fog night, data range + the fog delta. By day, when
   tonight is fog, the info line reads "Range: 5 tiles · 4 in fog tonight".
   The ghost ring by day stays the clear-weather radius.
4. Scenarios: `weather_rain` (a rain day around day 3, a farm with farmers
   in view, tag visible) and `weather_fog` (a fog night with zombies near
   a turret, turret selected so its 4-tile ring shows). Stub the roll in
   the scenario if no convenient seed exists.
5. Tests: layer visible only in the right phase and weather; rain tag text
   from data; ring radius and info line use the effective range (fog night
   = data - 1 tile; day with fog forecast adds "in fog tonight").

## Acceptance criteria

- Rain streaks only by day on rain days; fog patches only on fog nights.
- Zombies stay clearly readable in the `weather_fog` capture (compare with
  `project/runs/T-190/a1/qa_m9_turret_night.png`).
- Rain tag in the top bar on rain days only, no overlap at 1280x720.
- Rings and the range line show the fogged range at night on fog nights.
- `weather_rain` and `weather_fog` captures at 1280x720; all tests pass,
  no SCRIPT ERROR, import/smoke clean.

## Pitfalls

- The night tint is a CanvasModulate. Decide whether fog sits under or over
  it and make sure it doesn't wash zombies out (the zombie rim is a shader
  on the zombie layer; keep fog below the zombie layer if needed).
- Integer pixels only; no blur shaders.
- BuildMode clicks and selection must keep working through the layer.
