# T-055: Survivors: unstick survivors standing on built-over tiles + scenario typing

Milestone: M2 | Type: code | Owner: gemini | Scenario: `survivors`
Depends on: T-011 (done). Runs before T-012 (construction), which makes builders and blueprints common, so this case will happen often.

## Goal

Survivors don't occupy tiles, so the player can place a building on the tile a survivor is standing on. You can see this in the `buildings_placed` screenshot: the farm and shelter sit on top of two starting survivors. `Pathfinder.find_path` then returns `[]` because `from` is solid, so that survivor can never move again (`order_move` fails, and so does the re-path in `SurvivorStore.tick`). Fix the pathfinder so a survivor standing on a solid tile can still walk off it.

## Files

1. `game/scripts/sim/pathfinder.gd`, `find_path(from, to)`:
   - Keep returning `[]` when either end is out of bounds, or when `to` is solid.
   - If `from` is solid (and in bounds): call `_astar.set_point_solid(from, false)`, run `get_id_path(from, to)`, then **always** restore `_astar.set_point_solid(from, true)` before returning, including on the empty-path branch.
   - `find_path_adjacent` goes through `find_path`, so it gets the fix for free. Make sure its ring check and loop don't skip a solid `from`.
   - Keep the result format: the path excludes `from`, and each step is an 8-neighbour of the previous one.
2. `game/scripts/sim/survivor_store.gd`: nothing should need to change. Re-path already calls `find_path(s.tile(), s.target)`. Verify it with a test.
3. `game/dev/scenarios/survivors.gd`, line ~20: `var success: bool = state.order_move(...)`. Type every other local too (`var cc_origin: Vector2i`, `var s: Survivor`, ...).
4. Tests: add to `game/tests/test_pathfinder.gd` and `game/tests/test_survivors.gd`.

## Acceptance criteria

- Seed 1337: place a farm (`try_place` returns OK) whose footprint covers a starting survivor's tile. `order_move` of that survivor to a free tile 5+ tiles away returns true, and after enough `tick(0.1)` calls it arrives exactly on the target tile centre.
- `find_path` from a solid tile to a free tile returns a non-empty path, and every step after the first is passable. The start tile is still solid afterwards: a later `find_path` *to* that tile returns `[]`.
- `find_path` to a solid target still returns `[]`. Out-of-bounds `from` or `to` still returns `[]`.
- `game/dev/scenarios/survivors.gd` has no untyped vars.
- All tests pass with no `SCRIPT ERROR` line. Smoke passes. The `survivors` and `buildings_placed` screenshots are unchanged.

## Pitfalls

- Don't change `Placement`, and don't make survivors occupy tiles (decision in T-011).
- Call `_update_solids()` first. It may rebuild every point, so restore `from` *after* the query, not before.
- Godot commands: only the ones in `project/ARCHITECTURE.md`. Always pass `--path game`.
