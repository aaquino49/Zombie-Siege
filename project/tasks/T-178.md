## Do

1. **F10 caption.** From day 8 the Radio Tower is the 10th build-bar button (12 buttons by day 9). `_rebuild_buttons`
   in `game/scripts/ui/build_bar.gd` (around line 135) captions every button `"F%d" % button_index`, and
   `_hotkey_for_type` (line 287) returns `"F%d" % (index + 1)` for any index, so the card says "[F10] Radio Tower".
   Only `build_1`..`build_9` (F1–F9) are bound. Add the `Hotkey` label only when `button_index <= 9`, and make
   `_hotkey_for_type` return `""` when `index >= 9`.
2. **Stale bar in scenario captures.** `BuildBar.bind()` builds the buttons for the day at bind time. Scenarios that
   then set `state.clock.day` directly (e.g. `spitter` sets day 9, `scavenging` day 3) leave the bar showing day 1's
   four buttons, so QA captures show a bar the player never sees. Fix it once, not per scenario:
   - In `build_bar.gd`, remember the day the buttons were built for (`_built_day`, set in `_rebuild_buttons`) and add
     `func refresh_if_stale() -> void` that rebuilds only when `_state != null and _built_day != _state.clock.day`
     (and does nothing otherwise, so scenarios that already called `refresh()` or opened the info card keep it).
   - In `game/scripts/autoload/dev_tools.gd` `_run_scenario`, right after `script.setup(main)`, call it if the scene
     has one: `var bar := main.get_node_or_null("BuildBarLayer") as BuildBar` then `if bar != null: bar.refresh_if_stale()`.
