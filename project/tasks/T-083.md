# T-083: ART: Rescue helicopter sprites (body + rotor)

Milestone: M4 | Type: asset | Owner: codex | Scenario: `qa_helicopter_asset`
Depends on: none.

## Goal

At the end of a winning game a rescue helicopter flies in over the Command Center (GDD §10). Make the art for it.
The animation itself is T-084 (Gemini). This task only delivers the sprites, a contact sheet and an asset-preview
scenario.

## Deliverables

1. `game/assets/fx/helicopter_body.png`: a top-down (90° overhead) military/rescue helicopter **without rotor
   blades**. Nose points **right** (+X), the same facing convention as the Kenney survivor sprites. The fuselage plus
   tail boom fits in about **176×96 px** on a transparent canvas, with the main-rotor hub on the canvas centre.
   Olive/khaki or muted rescue-orange with grey metal, Kenney flat style (see `project/ART_GUIDE.md`).
   A small tail rotor drawn on the boom is fine.
2. `game/assets/fx/helicopter_rotor.png`: the main rotor only, **square, about 192×192 px**, hub at the exact centre.
   2–4 blades with a soft semi-transparent motion blur look (alpha around 0.5–0.7) so it reads as spinning while the
   view rotates it. It must look fine at any rotation (no baked shadow direction).
3. Sources: Kenney packs first (`asset_library/kenney/`). If nothing fits (likely), generate with the ART_GUIDE prompt
   template, keep originals in `asset_library/generated/originals/`, then trim and Lanczos-downscale.
4. A contact sheet `asset_library/generated/helicopter_contact.png`: body, rotor, body+rotor composited, and the
   composite next to `game/assets/buildings/command_center.png` and `radio_tower.png` on a grass tile, at game
   scale. Regenerate (up to 3 tries) if it clashes with the Kenney style or is clearly out of scale (the helicopter
   should be a bit bigger than the 2×2 CC, roughly 1.3×).
5. Rows in `game/assets/ASSET_INDEX.md` (file, purpose, source) and credit in `/CREDITS.md`.
6. Scenario `game/dev/scenarios/qa_helicopter_asset.gd`: shows the composited helicopter (a `Sprite2D` body + a child
   `Sprite2D` rotor rotated about 20°) hovering beside the CC in the normal game view, camera centred on it, waves
   disabled. This is a preview only: no game logic.
7. Run `godot --headless --path game --import` so the `.import` files exist, and commit-ready files only (no scratch
   files in the repo root).

## Acceptance criteria

- Both PNGs exist with transparent backgrounds at the sizes above. The rotor hub is centred within ±2 px, and the
  body's rotor hub is at the canvas centre.
- Style matches the Kenney top-down set on the contact sheet: flat colours, clean outlines, true top-down, no text.
- `qa_helicopter_asset` screenshot at 1280x720 shows a readable helicopter next to the CC, in scale.
- ASSET_INDEX.md and CREDITS.md updated. Import and smoke clean. All tests still pass.

## Pitfalls

- No perspective or 3/4 view. Don't bake a drop shadow into the body: T-084 draws a separate offset shadow by
  tinting the body black.
- Keep the rotor separate from the body so it can spin.
- Don't change any game scripts other than adding the scenario file.
