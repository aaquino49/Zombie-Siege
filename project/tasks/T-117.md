# T-117: Cleanup: restore immediate nightfall interruption for survivors with a leftover daytime job_timer

Milestone: M6 | Type: code | Owner: gemini | Scenario: `night_shelter`

## Goal

After T-094, a survivor whose daytime job left a retry timer keeps working for up to `job_retry_interval` (1 s) after
nightfall before heading to shelter. Restore the old behaviour: at nightfall, interruption and shelter picking happen on
the first night tick.

## Context

- `game/scripts/sim/game_state.gd` `_on_phase_changed` (NIGHT branch) now sets `s.shelter_night = clock.day` for every
  survivor (added by T-094 to reset the unreachable-shelter exclusions).
- `game/scripts/sim/shelter_rules.gd` `tick`: its "new night" branch (`shelter_night != clock.day`) zeroes `job_timer`.
  Because `_on_phase_changed` already set `shelter_night`, that branch never runs in real play. Also, the `job_timer`
  early return now sits above the `b == null` interrupt block.
- The old comment "A daytime job retry must not delay the nightfall interruption" describes the intended behaviour.
- Existing test `test_clock_dawn_releases_in_dispatch_and_old_job_retry_does_not_delay_night` misses the bug: `_night()`
  sets the phase directly, so `phase_changed` never fires.
- `game/scripts/sim/jobs.gd` has a per-tick DAY reset of the exclusions that is redundant (they are cleared in `_on_dawn`
  and `_on_phase_changed`).

## Do

1. In `game_state.gd` `_on_phase_changed` (NIGHT), stop setting `shelter_night` and only reset the exclusions. (Or, if
   that breaks the once-per-night warning, also zero `job_timer` there. Pick one and say which in work.json.)
2. Make sure the interrupt for survivors with no shelter assigned runs before the `job_timer` early return in
   `ShelterRules.tick`.
3. Remove the redundant per-tick DAY exclusion reset in `jobs.gd` if the tests confirm it is redundant.
4. Add a sim test in the shelter test file that goes through the **real clock boundary**: a gatherer with
   `job_timer = 100`, `state.clock.elapsed = day_length - 0.1`, `state.tick(0.2)`. After that one tick the survivor has
   `shelter_uid != 0` (and its job state is interrupted).

## Acceptance criteria

- The new test passes, and fails on the current code (say so in work.json).
- Existing shelter tests, including T-094's unreachable-shelter and once-per-night warning tests, still pass.
- All tests pass; import and smoke clean. `night_shelter` screenshot unchanged in substance.

## Pitfalls

- Don't change the T-094 behaviour: the "can't reach shelter" warning still fires once per survivor per night, and
  exclusions still reset each night.
- Static types on every new variable (ARCHITECTURE.md).
