# T-167: Scavenging 2: Send scavenging button, away status, return toast and Dawn Report lines

Milestone: M8 | Type: code | Owner: gemini (Codex stands in) | Scenario: `scavenging` | QA: yes

Ready since T-166 and the v1.2.0 export (T-150) merged. Runs in parallel with T-164 (spitter sim), T-168 (build
hotkeys) and T-175 (bot). Stay out of `zombie_ai.gd`, `wave_spawner.gd`, `game_data.gd`, `hud_text.gd`,
`build_bar.gd` and `balance_bot.gd`. Don't change `expeditions.gd` behaviour (T-166 is tested and approved); a
read-only helper there is fine.

## Goal

Make T-166's runs playable (GDD §18.2).

## What T-166 already gives you (`game/scripts/sim/expeditions.gd`, `state.expeditions`)

- `can_send(s) -> String`: `""` when allowed, else one of `"dead"`, `"not morning"`, `"guard"`, `"already away"`,
  `"run limit"`, `"sheltered"`. `send(uid) -> bool`. `is_running(s)`, `active()`.
- Signals `run_started(s)` and `run_returned(s, result)`; `result` has `loot` (kind → amount), `hurt`, `lost`,
  `newcomer`. Runs return when night falls (`GameClock` has only DAY and NIGHT), so the toast fires at nightfall.
- `Survivor.away` is true while the survivor is off the map.
- The dawn report dict already carries `report["scavenging"]`: an array of
  `{"name", "loot", "hurt", "lost"}` for runs that returned during the night before.

## Do

1. **Button.** Info panel (`game/scripts/ui/info_panel.gd`, selected survivor) and each roster row
   (`roster_panel.gd`): a **Send scavenging** button, enabled only when `can_send(s) == ""`. When disabled, its
   tooltip gives the reason in plain words: "Only in the morning", "Guards stay on watch", "Already out",
   "No more runs today", "Can't leave the shelter". Hide the button for `"dead"`. Pressing it calls
   `state.expeditions.send(uid)`. Refresh enabled state when the clock crosses the morning cutoff.
2. **Away.** The survivor walks visibly to the edge (T-166 pathing). While `away`, the roster row shows
   "Away (back at nightfall)" with the button hidden, the survivor sprite isn't drawn, and they can't be selected.
3. **Toast.** There is no toast system yet: add a small reusable one to the HUD (a themed Label/Panel under the
   night-forecast line, on the same pattern as `hud.gd`'s ShelterWarning timer; 4 s, fades out; several queue).
   Texts: "Mara is back: +32 scrap, +12 food" (only non-zero loot, in the order wood, scrap, food, ammo),
   "Mara came back hurt: +10 wood" and "Mara didn't come back". Add ", and found a newcomer" when one joined.
   Reuse an existing SFX (no new audio).
4. **Dawn Report.** `dawn_report_panel.gd` shows a "Scavenging" section from `report["scavenging"]`, one line per
   run in the same "label: value" style, only when the array is non-empty.
5. **Hint.** A one-time tutorial hint (`game/scripts/sim/tutorial_hints.gd`) on the day-2 morning: "Send a survivor
   scavenging for supplies. They're back at nightfall, but it's risky." `how_to_play.gd` gets one line in its tips
   (T-168 edits the controls part of that file; keep your edit to the tips list).
6. **Tests** `game/tests/test_scavenging_ui.gd`: button disabled with the right reason outside the morning, for a
   guard and at the run limit; enabled and calling `send` in the morning; toast text for loot / hurt / lost /
   newcomer (pure function, e.g. `HudText.scavenge_toast(name, result)` lives in a new file or in `hud.gd`, not in
   `hud_text.gd`, which T-164 edits); Dawn Report rows include the Scavenging lines.
7. **Scenario** `game/dev/scenarios/scavenging.gd`: day 3 morning, one survivor selected with the button visible and
   enabled, a second survivor walking to the edge, and a return toast on screen (trigger it via the toast API with a
   fixed result; don't fast-forward the clock).

## Acceptance criteria

- The `scavenging` capture at 1280x720 shows the button, an away row in the open roster and the toast, without
  covering the build bar, the info card or the night-forecast line.
- The button is disabled with a readable reason outside the morning, for guards and at the run limit (unit test).
- A full day through the real UI path (test): send in the morning → away → back at nightfall with loot added and a
  toast → the next Dawn Report lists the run.
- Menu-flow scripts (`qa_t025_menu_flow.gd`, `qa_m4_menu_flow.gd`) pass; all tests, import, smoke and screenshot
  clean.

## Pitfalls

- Text uses the `UiFont` sizes (multiples of 11) and the shared Theme; no ad-hoc font sizes (a test enforces it).
- Don't keep strong references from UI nodes to `Survivor` objects after they're removed (a lost survivor is
  removed from the store at nightfall): look survivors up by uid.
- The toast must not show under the pause menu or block clicks on the map (mouse_filter IGNORE).
