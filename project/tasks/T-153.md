# T-153: Chore: VictorySetup places the radio tower on any seed (qa_t025 menu flow fails on random seeds)

Milestone: M6 | Type: code | Owner: gemini | Scenario: `victory` | skip QA

## Goal

`qa_t025_menu_flow.gd` failed 25 of 47 checks in T-112's QA (`project/runs/T-112/a1/qa_t025.log`): every check after
the first Victory cascades from `victory_setup.gd:19` `assert(p_res == Placement.Result.OK, "Radio tower placement failed")`.
QA blamed headless rendering, but the real difference is the **seed**: the flow presses New Game, which picks a fresh
random seed, and `VictorySetup.trigger_win()` hard-codes the tower at `command_center_origin() + (-4, 0)` after vacating
only occupant codes 1, 2, 3. On some maps that 3x3 (or whatever the data size is) spot is still not free or is out of
bounds, so placement fails. The rendered run passed only because it rolled a friendlier seed. The M6 QA (T-113) runs this
flow, so it must be reliable.

## Do

1. In `game/dev/scenarios/victory_setup.gd`, split out a testable static helper:
   `static func place_finished_tower(state: GameState) -> Building`. It clears the area around the CC as today, then tries
   the current spot first (so seed 1337's `victory` capture stays identical) and, if `Placement.check` is not OK, scans
   outward rings around the CC (deterministic order) for the first origin where `Placement.check(state, "radio_tower", o)`
   returns OK. Finish the building and return it. If nothing is found, `push_error` with the last `Placement.Result`
   name and return null (no bare assert without the result code).
2. `trigger_win()` reads `Game.state` and calls the helper; everything else in it stays the same.
3. Test `game/tests/test_victory_setup.gd`: for seeds 1337 and 1..20 (`GameState.new(data, seed)`), the helper returns a
   finished `radio_tower` and `state.buildings.all_of_type("radio_tower").size() == 1`. Also assert seed 1337 puts it at
   `origin + (-4, 0)`.
4. Run `godot --headless --path game --script res://dev/scenarios/qa_t025_menu_flow.gd -- --quit-frames=1200
   --flow-report=<abs path in your run dir>` at least 3 times (random seeds each time) and quote the "N checks, 0 failures"
   lines in work.json.
