# T-071: Natural roads: winding 2-wide dirt tracks with autotiled edges

Milestone: M3 | Type: code | Owner: gemini | Scenario: `map_overview` (also check `default`)
Depends on: T-070 (path tiles), T-018 (zombie sim; its seed-1337 tests must keep passing after the map changes).
Owner request R-1.

## Goal

Today `WorldMap._generate_road()` paints 1–2 full-length straight rows or columns of `Terrain.ROAD`, and the world view
draws each one with `road_plain.png`. They read like UI dividers (owner request R-1). After this task each map has
1–2 **dirt tracks** that come in from a map edge, bend a few times, and end at the centre clearing. A second track
joins the first at a junction or ends at the clearing too. Edges are drawn with T-070's grass-edged path tiles.
The map stays seeded and deterministic, and the centre clearing stays clear.

## Rules

### Generation (`game/scripts/sim/world_map.gd`)
- Keep `Terrain.ROAD` as the terrain id (the meaning is now "dirt track"). Survivors and zombies treat it like grass
  (passable, normal cost). Nothing about movement changes.
- Replace `_generate_road()` with a walk that stamps **2×2 blocks**, which guarantees every road tile is part of a
  2×2 road block (T-070's tiles need that):
  1. Pick a random edge (N/E/S/W) and a start position along it at least 8 tiles from either corner.
  2. The main direction points inward. Each step moves 1 tile in the main direction. With chance
     `map_road_turn_chance` (balance, default 0.2), start a sideways run of 2–5 steps instead (direction ±1 chosen
     by the rng). After a sideways run, return to the main direction for at least 3 steps before another turn.
     **Moves are orthogonal only.** Never step backwards. Clamp sideways runs to at least 4 tiles from the map edges.
  3. Stamp `Terrain.ROAD` on the 2×2 block at each position, including the starting one, so a road reaches the map
     edge.
  4. Stop when the block reaches the clearing (any tile within `map_clear_radius` + 1 of the map centre), or when the
     block touches a road tile laid by an earlier road (that makes the junction). Never stamp road on the Command
     Center's tiles.
- Use the existing `map_roads_min`/`map_roads_max` (1–2). Retire `map_road_center_offset`: remove its read. Leaving
  the key in balance.json is fine.
- **Trees, rocks and scrap are never placed on road tiles:** skip `Terrain.ROAD` tiles when building
  `potential_tiles`. A track stays walkable and readable.
- Keep the order dirt patches → roads → resources → CC, and keep using `_rng`, so the same seed gives the same map.

### Drawing (`game/scripts/world/world_view.gd`)
- Load the 13 `res://assets/tiles/path/path_*.png` as atlas sources (the same way grass and dirt are loaded now).
- For each ROAD tile, pick the tile with the neighbour rule in `game/assets/tiles/path/README.md`: orthogonal
  neighbours that are ROAD, DIRT or out of bounds count as dirt, GRASS counts as grass. 0 grass sides plus exactly
  one grass diagonal → `inner_<diag>`. 1 grass side → `edge_<side>`. 2 adjacent → `outer_<corner>`. Otherwise
  `center`.
- Put the rule in a small static, headless-testable helper, e.g. `static func path_tile_for(map: WorldMap, t: Vector2i)
  -> String` returning the suffix (`"center"`, `"edge_n"`, `"outer_se"`, `"inner_nw"`, ...), in a new
  `game/scripts/world/path_tiles.gd` (`class_name PathTiles`).
- Delete `road_*.png` (and their `.import` files) from `game/assets/tiles/` if nothing else uses them (grep first).
  Otherwise leave them.

## Tests (`game/tests/test_roads.gd`, new; update `test_world_view_qa.gd`)

- For seeds 1, 1337, 4242 and 9001: there are between `map_roads_min` and `map_roads_max` road starts touching the map
  border. Every road tile belongs to at least one 2×2 all-road block. No road tile is on the CC footprint. No road tile
  has a tree, rock or scrap. No road tile has grass on two opposite orthogonal sides.
- **Connectivity:** a flood fill over road tiles from each border road tile reaches a tile within
  `map_clear_radius + 1` of the centre.
- **Not straight:** on at least 3 of the 4 seeds, some road's tiles span ≥ 3 different columns (N/S roads) or rows
  (E/W roads). A bend exists.
- **Determinism:** two maps with the same seed have identical terrain everywhere.
- `PathTiles.path_tile_for` unit cases on a hand-built tiny map: a straight 2-wide horizontal track gives `edge_n` on
  the top row and `edge_s` on the bottom row. The convex corner of an L gives `outer_*`, and its concave corner gives
  `inner_*`. A tile surrounded by road gives `center`.
- `test_world_view_qa.gd`: ROAD cells must now use a texture under `res://assets/tiles/path/` (instead of
  `road_plain.png`), and the chosen file must match `PathTiles.path_tile_for`.

## Acceptance criteria

- The tests above pass. All existing tests pass (fix any test that depended on a specific seed's tree or road
  layout **without weakening what it checks**), with no SCRIPT ERROR. Smoke and import are clean.
- The `map_overview` screenshot shows 1–2 brown dirt tracks with soft grass edges that bend and reach the centre
  clearing. No full-height grey stripes. The `default` screenshot shows grass and the CC with any track entering the
  clearing looking natural (no hard grey squares).
- Same seed → same map.

## Pitfalls

- The map layout changes for every seed because the rng is consumed differently. That's expected. Scenarios that
  place buildings at fixed offsets from the CC stay valid because the clearing is unchanged. Check `qa_m1_map_edges`,
  `test_m1_qa.gd::_free_grass` and the T-018 flow-field tests (corner paths, wall ring at Chebyshev distance 3) still
  pass.
- Don't make the track walk diagonally: a diagonal 2×2 stamp leaves tiles with grass on opposite corners that the
  13-tile set can't draw.
- Static typing everywhere. Draw the ground once at map load (as now), not per frame. Use only the commands in
  ARCHITECTURE.md, always with `--path game`.
